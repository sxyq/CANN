## 实现要点

1. Host 端把最后一维以外的形状展平为 `rowCount`，每一行由一个 vector core 顺序处理。
2. 第一遍按不超过 4096 个元素的 tile 搬入 `x` 和 `residual`，转换到 FP32，完成加法、平方和 `ReduceSum`。
3. 第二遍重新搬入 `x` 和 `residual`，在 FP32 中完成加法、RMS 除法、gamma 缩放和 bias 加法；FP16/BF16 仅在最终写回前使用 `CAST_RINT`。910B 不支持 `Divs` 灵活标量接口，因此先读取 FP32 `rms`，复制为当前 tile 的除数向量，再使用普通向量 `Div`。
4. 每次 GM 到 UB 搬运都显式设置 `isPad`、`leftPadding`、`rightPadding` 和 `paddingValue`。GM 到 UB 只处理有效元素，UB 到 GM 只写有效字节。
5. 行偏移、tile 偏移和分组边界使用 `uint64_t`。Host 端用 `rowBytes` 与 32B 的最大公约数计算最小 `rowGroup`，block 只分配完整行组，末尾行组允许短尾。
6. 只保留 dtype 分支、FP32 no-op 转换和低精度最终转换三类必要分支，没有复制宽行缓存或流水线变体。

## 变更假设

- 输入、残差、gamma、bias 和输出 dtype 相同，支持 FP32、FP16、BF16。
- gamma 和 bias 是一维最后维参数，长度等于输入的 `D`。
- 题面提供的 `TensorGroupInfo`、`TensorInfo`、`GM_ADDR` 和 `aclrtStream` 定义由直调环境提供。
- `epsilon` 作为 Host 参数传入，归一化、开方和除法仍在 Kernel 内完成。
- 服务器 CANN 9.0 平台模板编译与链接已完成；FP16、BF16、FP32 的已选矩阵和 D 边界矩阵均已完成真实 NPU 运行与精度验证；性能已采集一个单点样本，重复对照仍待完成。

## API 依据

- `DataCopyExtParams`、`DataCopyPadExtParams<T>` 和 `DataCopyPad` 形式来自 `asc-devkit/include/basic_api/kernel_struct_data_copy.h` 及其搬运接口声明。
- `ReduceSum` 使用 Level 2 形式，独立 FP32 `reduceTmp` 作为工作区。
- 归一化使用 FP32 向量 `Div`；`rms` 通过 `V_S/S_V` 同步读为标量，再用 `Duplicate` 生成当前 tile 的除数向量，适配 910B 支持范围。
- `tpipe` 保留 V002 已采用的成员名称，避免使用 V001 的 `pipe_` 名称。
