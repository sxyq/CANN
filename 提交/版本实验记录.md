# AddRmsNormBias 版本实验与提交记录

## 文档用途

本文件位于唯一工程的 `提交/` 目录下，是所有方案与版本的统一迭代索引。它记录每个版本的源码变化、所属方案、实验方向、服务器验证证据和 CANNJudge 返回结果。后续只在本文件追加记录，不创建日期副本或第二份总记录。

29 条路线的最高有效平台分集中记录在 `调研/路线最高分.md`；本文件保留版本级证据。

版本号统一使用三位数字：`V001`、`V002`、`V003`、`V005`。

本仓库有两种代码形态，记录时必须分别标明：

- `源码/`：完整 Ascend C 工程，包含 Host 原型注册、Tiling、Kernel、CMake 和构建脚本。
- `提交/混合方案/H00N-名称/V00N/`：多个路线组合后的 CANNJudge 直调候选，目前每次上传的核心文件是 `kernel.asc`。
- `提交/单方案/R00N-名称/V00N/`：单条路线独立实验或提交时使用的版本目录。

两者服务于同一个题目，不代表两套独立工程。若两种形态出现实现差异，必须在本文件中注明迁移关系和未验证部分。

## 单点修改与回退记录规则

每个版本只记录一个技术变更点。变更前记录可用版本、修改假设和最小测试；变更后按“编译 → 最小运行 → 精度 → 性能”的顺序验证。编译失败、运行报错、精度下降、性能下降或资源异常时，立即停止扩展测试，保留失败版本和日志，回到最近可用版本，再决定下一条变更。禁止把多个未验证改动合并进一个版本。

每个版本的 `变更说明.md` 和 `结果.md` 至少记录：修改点、预期影响、编译返回码、最小用例结果、完整测试结果、性能变化、回退原因和后续决定。技术路线编译测试结束后，确认不再使用的构建缓存、对象文件和临时数据及时清理；记录清理前后剩余空间，不以使用率代替剩余空间判断。

## B. 归约与数值链

当前候选采用两遍扫描：

1. 第一遍按 tile 搬入 `x` 和 `residual`，转换到 FP32，完成加法、平方和 `ReduceSum`。
2. 第二遍重新搬入数据，在 FP32 中完成归一化、`gamma` 缩放和 `bias` 加法，最后转换回输入 dtype。

**关键发现与版本改动**：
- **V002 归约读取**：已改为标准 `ReduceSum` + `V_S/S_V` 同步 + `GetValue(0)`；
- **V002 尾块参数**：已明确 `leftPadding=0` 和 `rightPadding=right_padding`；
- **V002 大张量寻址**：行基址和搬运偏移已使用 `uint64_t`。
- **V003 归约路径**：每个 tile 用独立 FP32 临时区完成 `ReduceSum`，在行内累加到 FP32 标量槽；第二遍使用 `Sqrt` 后以 FP32 向量 `Div(y, rmsTile)` 完成先除。
- **V003 参考结果**：CPU 矩阵报告已落盘；该结果只说明参考链行为，不能替代目标设备输出。

目前没有真实 NPU 证据证明以下项目已经通过：
- FP32 归约误差小于题面要求。
- FP16/BF16 最终转换和舍入误差小于题面要求。
- `sqrtf` 在目标 Ascend C 编译链上的可用性和精度。

## C. 尾块与形状边界

候选按最后一维 `D` 展平为 `outer` 行，使用 `DataCopyPad` 处理不完整 tile。

**并发和边界风险记录**：
1. **尾块写回语义**：
   - V002 已修复搬入参数顺序；UB 到 GM 的真实写回语义仍需真机用非对齐多行用例确认。
2. **多核 32B Cache Line 边界**：
   - 当 $D \times \text{sizeof}(T)$ 非 32 字节整数倍时，相邻行共享同一 32 字节缓存行；多核按行均分并发 DMA 写回时将触发总线踩踏；
   - V003 引入对齐行块调度，使得每个 Core 分配的行块满足 $k \times D \times \text{sizeof}(T) \equiv 0 \pmod{32}$。

需要在真实环境覆盖：

| 类别 | 用例 |
| --- | --- |
| 维度 | 2D、3D、4D |
| D 边界 | 1、31、32、33、67(非对齐)、127、128、129、1000、32768 |
| 数据类型 | FP16、BF16、FP32 |
| 广播 | `gamma` 和 `bias` 按最后一维广播 |
| 多核 | `outer` 小于、等于、大于可用 AI Core 数 |

## D. UB 分块与流水线

当前基准参数：

| 参数 | FP16/BF16 | FP32 |
| --- | ---: | ---: |
| tile 元素数 | 4096 | 4096 |
| `BUFFER_NUM` | 1 | 1 |
| 中间计算 | FP32 | FP32 |
| 扫描次数 | 2 | 2 |

**【重大纠偏】单遍暂存可行域推翻 2048 限制，拓展至 $D \le 4096$**：
- 深入的 UB 内存精细规划表明，在 $D \le 4096$ 时，FP16/BF16 输入各 8KB，FP32 暂存 $y$ 16KB，$\gamma/\text{bias}$ 各 8KB，规约临时工作区 16KB，输出 8KB，分时复用峰值仅 80~112KB，完全处于 192KB 物理限制安全线以内；
- 因此，对于常见大模型维度（1024、2048、4096），单遍暂存可作为后续性能候选，预计减少 28.6% 的 GM 访存流量；仅在 $D > 4096$ 时回退两遍扫描。
- V003 当前只采用两遍扫描，未引入单遍驻留、双缓冲或多行合并，性能收益仍需目标设备测量。

## E. 数据类型与精度

候选的计算原则是：

- FP16/BF16 输入先转换为 FP32。
- `x + residual`、平方、归约、均值、epsilon、开方、归一化、`gamma` 和 `bias` 在 FP32 中处理。
- V003 仅在输出阶段转换回输入 dtype（使用 `RoundMode::CAST_RINT`）。
- 禁止通过写死测试输入、输出或 Host 代算获得结果。

待记录的精度表至少包含：输入 dtype、shape、D、epsilon、最大绝对误差、最大相对误差、是否通过和运行环境。
