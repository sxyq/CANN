# 提交工作区

本目录只保存经过源码审阅、真机编译和精度验证后准备上传的唯一候选文件，以及逐次结果记录。

当前工作版本为混合方案 `H001-正确性优先/V002`。调研2（**2026-09-12 重做**）交叉核对：V002 使用**逐字段赋值**配置 DataCopyPad（对字段声明顺序不敏感）；官方字段序本身仍有旧笔记 vs CANN 9.0.0 文档的**证据冲突**，列为真机第一验证项。`GetReduceRepeatSumSpr` 在 9.0.0 有官方专页，主线仍建议 `GetValue(0)+V_S`。本机无 CANN/NPU，服务器已完成模板级 CANN 编译与单案例运行。

**调研2 对 V002 的三条新增裁决**（详见 `../调研/归档/调研2/Agent10_方案审阅评估与技术报告.md`）：
1. **归一化必须改 `Divs`**：V002 用 `Muls(valueTile, valueTile, invRms)`，主代理 36 组 CPU 复核显示 `Divs` 与 golden 逐位一致（最大绝对差恒为 0），`Muls` 在「大 outer 小 D」下 bf16 最大绝对差达 1.562e-02 并出现真实失配元素。
2. **体量是编译风险**：2955 行 / ~20 个 `Process*` 变体命中官方记载的 `out of jump/jumpc imm range`；首版应收敛为参数化通用路径。
3. **两次 CE 均非算法问题**：V001 为 `pipe_` 符号冲突，V002 为上传内容截断（平台收到首行 `return false;`）。根因是**从未在本地编译成功过一次**。

后续 `V003` 仍归入 `H001-正确性优先`，用于修复精度风险并完成完整矩阵；性能实验再进入 `H002-性能组合`。V001 的平台失败结果记录在 `混合方案/H001-正确性优先/V001/结果.md`。方案矩阵见 `../调研/归档/调研2/research-report.md` 第 10 章、`../调研/归档/调研2/方案矩阵.md` 与 `../调研/归档/调研2/Agent10_方案审阅评估与技术报告.md`（2026-09-12 版）。

后续版本使用 `V001`、`V002`、`V003` 等三位数字编号，并放入所属方案目录：混合方案使用 `提交/混合方案/H00N-名称/V00N/`，单方案使用 `提交/单方案/R00N-名称/V00N/`。

```bash
cp /Users/sunyiyang/Desktop/Project/cann/提交/混合方案/H001-正确性优先/V002/kernel.asc \
```
