# 5. New Research Route 去重核对（SHAPE-TILING-CHAMPION-X）

对照要求：WIDE-X-FRESH4、R31B 现有宽 D 路径、R31A、FULL/R029 五模式。禁止创建 V001。

## 5.1 四者实际做了什么

| 对象 | 机制 | 基线 | 结果 |
|---|---|---|---|
| **WIDE-X-FRESH4 V001** | 仅宽路径 tile 常量 2048→4096，并放大该实例化 `tmp_`；fallback 8192 字节分配保留 | 弱父 BUILD-FIX-001（无 Official） | 正确性 18/18；D32768 mean -17.1%（4/4）、D16384 -16.8%（4/4），`LOCAL_ACCEPTED`；Official 19.72（绝对分低） |
| **R31B 宽 D 路径** | `ProcessWideFp32FullCacheRows` + full-y 缓存 + LP 管线；V016 将 FP16/BF16 宽行初始 tile 4096→8192 | FROZEN / V011（45.16） | V011 45.16；V016 测量未完成 |
| **R31A 宽 D 路径** | `kWideFp32CachedTileElems=7680` 的 FP32 CachedRows；V016 加 D=32768 full-y 分派；V021 推迟 store 等待 | R31A lineage（45.00） | V016 45.00；V021 本地混杂 |
| **FULL-R029 / MODE-X 五模式** | 宿主/内核分派 taxonomy：NORMAL / SPLIT_D / MERGE_N / SINGLE_N / MULTI_N（按 D、outer、UB、核数分档） | 弱基线 / 独立实现 | FULL-R029 4/15 RE；MODE-X 正确性在 SPLIT_D、非对齐 D、BF16 失败；后续 FRESH/R015B 无源码 |

## 5.2 相同点

1. **都在处理「一行放不进 UB / tile 粒度」问题**：WIDE 加宽 tile、R31B/R31A 用 full-y 缓存 + 分派、五模式用 SPLIT_D/整行驻留分档。
2. **都是 shape-conditioned**：按 D（和隐含 rows）切换路径或参数。
3. **tile-UB 权衡是共用底层**：UB-LIVENESS-X 的 tile-budget-matrix 显示 2048→4096 在多档 D 上可行，但 4096 以上会挤占双缓冲/参数区。
4. **R31A 与 R31B 的宽路径同源**（相似度 0.947），不是两套独立架构。

## 5.3 不同点

| 维度 | WIDE-X-FRESH4 | R31B 宽 D | R31A 宽 D | 五模式 taxonomy |
|---|---|---|---|---|
| 改动粒度 | 单常量 + tmp 尺寸 | 管线/缓存/队列/ tile | 分派 + tile + store 等待 | 整套运行时分档 + 多条 kernel 路径 |
| 基线强度 | 弱父，Official 19.72 | Champion 45.16 | 45.00 | 弱/失败 |
| dtype 覆盖 | 三 dtype 同一 tile 策略 | FP32 full-y 与 LP 分路；V016 改 FP16/BF16 tile | 以 FP32 CachedRows 为主 | 五模式含 FP16 对齐 MULTI_N、MERGE_N 上限 D≤2000 |
| rows 策略 | 未按 rows 分档 | full-y / multi-row 尝试过（V003/V004 失败） | full-y 单行为主 | SINGLE_N/MERGE_N/MULTI_N 显式按 outer 分档 |
| 与 UB 预算关系 | 只放大单 tile | UB 预算驱动（V003/V016 声明） | 固定 7680 | 宿主算 rowFactor/ubFactor（本题无 tiling 结构体） |
| 验证深度 | 本地合格，Official 弱 | Official Champion | Official 45.00 | 正确性从未全过 |

## 5.4 去重结论（研究空间判断，非路线决定）

**FACT**

- 「单纯把宽路径 tile 从 2048 改到 4096」这一条已被 WIDE-X-FRESH4 在弱父上验证（-17% 本地），**在 Champion 基线上对应假设是 R31B V016（4096→8192，FP16/BF16）**，属于同一「tile 加宽」思路的更强基线重测，与全新机制有区别。
- 「按 (D, rows, dtype) 选择不同 tiling 档位」的完整五模式 taxonomy **从未在 Champion 基线实现或验证**。历史实现（FULL-R029、MODE-X）均正确性失败；EXT-ASCEND-X 移植三因子 tiling 也 27/27 FAIL。
- R31B/R31A 已有**隐式** shape 分派（full-y / LP / CachedRows / generic），但不是官方五模式的显式 taxonomy（SPLIT_D 内核内 D-tile 累加、MERGE_N 多行联合归约、SINGLE_N 单核事件流水等）。

**EVIDENCE**

- `本地实验/WIDE-X-FRESH4/V001/{source-meta.json,local-result.json,MAIN-REVIEW.md}`：`kWideTile = 4096`，D32768/D16384 双双 -17%。
- `本地实验/R31B/V016/source-meta.json`：FP16/BF16 8192-element tile seed。
- `本地实验/R31A/V021/source-meta.json`：`kWideFp32CachedTileElems=7680`。
- `归档/历史工作区/MODE-X/HANDOFF_V001.md`：五模式定义与失败点（SPLIT_D、非对齐 D、BF16）。
- `技术路线/技术路线总表.md` §九之二：「R029 五模式 tiling | 未按 taxonomy 重做 | 官方五模式分派未实现」。
- `研究/BATCH-RESIDENT-X/next-hypotheses.md`：官方阈值摘要 + EXT-ASCEND-X 失败对照；MERGE_N 联合归约被标为 BATCH/R029 领地。
- `研究/SCHED-ROWGROUP-X/next-hypotheses.md`：明确排除吸收五模式 taxonomy（会与 R029/MIX-A/R31B 重复）。

**OPEN QUESTION**

1. 在 Champion 基线上，**显式**五模式分派（尤其是 SPLIT_D 内核内两段与 MERGE_N 多行联合归约）是否仍有独立收益，还是已被 R31B 的 full-y + LP + tile 策略隐式覆盖？
2. tile-UB 权衡的「最优 tile」是否随 (D, dtype, rows) 三元变化——若是，是否存在 WIDE/R31B/R31A 都未覆盖的中间档（例如 FP32 D=12288/16384 的 tile=6144/8192）？
3. 五模式中 **SINGLE_N 事件流水**（单核单行手工 MTE/V 重叠）与 R31B LP 管线、ASYNC-TRIPLE-X 的重叠假设是否本质同一轴。
4. 官方 MERGE_N 的 D≤2000 多行合并与 MIX-A 的 localRows==1 约束、BATCH-RESIDENT-X 的批量 DMA 的领地边界。

**去重前置的可回答部分（满足 Planning 要求的「哪里相同、哪里不同」）**

- 相同：都是 shape/tile/UB 问题；tile 加宽这类思路已被 WIDE（弱父）与 R31B V016（强父，未测完）覆盖。
- 不同：五模式的**显式多路径 taxonomy**（尤其 SPLIT_D 内核内归约、MERGE_N 联合归约、SINGLE_N 流水）在 Champion 上是未验证空间；它与「单常量 tile」不是同一机制。
- 历史「五模式」是否仍有独立空间：**从证据看，taxonomy 层面未被 Champion 覆盖，但每一条模式单独是否有效，历史实现均未给出可信答案（全正确性失败）**。因此该空间是「独立但高风险、需先过正确性」的类型，不是与 WIDE/R31B tile 轴的简单重复，也不能直接把 WIDE 的 -17% 外推过来。

# 9. Git / Revision Understanding

| 项 | 规则 |
|---|---|
| 提交粒度 | 一个独立事实 = 一次 `git add <明确路径>` → commit → push |
| 禁止 | `git add .`、大包提交、force push、盲目 reset、`git clean` 删证据 |
| 分离 | Route 分支推送与共享控制（`调度/`）提交分开 |
| Revision 声明 | 修改前记 ROUTE / REVISION / DIRECT_PARENT / PARENT_SOURCE_SHA / PARENT_SCORE / SINGLE_HYPOTHESIS / CONTEXT_CLASS / WHY_NOT_DUPLICATE |
| OFAT | 一个性能 Revision 只验证一个概念机制；`SINGLE_CHANGE_AUDIT=PASS` 才有 Online 资格 |
| Build/Correctness Fix | 可留在原假设内；禁止借 FIX 加性能机制 |
| 身份 | 本地 SHA = server3 SHA；线上 `LOCAL_SHA == SIDECAR_SHA == REMOTE_SHA`，不一致 → `INPUT_IDENTITY_MISMATCH` |
| 证据五件套 | `submission.asc` / `submission.sha256` / `source-meta.json` / `diff.patch` / `local-result.json`（Online 另加 `result.json`） |
| 记录同步 | ① Revision 目录 ② `全版本记录.tsv` ③ `路线成绩表.tsv` / `技术路线图.md` ④ 有 Online 时 `本地线上校准.tsv` |
| 被拒版本 | 不能作下一个独立性能改动的父版（V015、V019/V020 等） |
