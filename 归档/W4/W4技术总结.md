# W4 五路线技术总结

本文件只总结已经结束的 W4 五条路线。所有成绩状态以各 worktree 的实际证据和正式主线记录为边界；没有把 Local 数字转换成 Official 分数。

## ROW-SCALE-HOIST-X

- 67 个 Revision（V001-V067），研究轴是不同 FP16/BF16/FP32 consumer 中 row `invRms` scale 的位置、gamma/bias 顺序及转换边界。
- V058（源码 commit `909f8641d76baa3b0643afcaba890f4b5b8733d2`，SHA `6c4a11c5...`）编译和 FP16 `[128,128]` correctness 通过；描述性 median delta 为 `-23.605%`，但 Parent stability、baseline drift 和并发负载使 verdict 为 `MEASUREMENT_BLOCKED`，Current Local Best 仍为 V026。
- V062（源码 commit `6581a1e8db4c2adbdfc09a701a5c31a42e2901a3`，SHA `1dd6fb4b...`）编译和 BF16 `[128,128]` correctness 通过；描述性 median latency delta 为 `-27.206%`，但稳定性 CV/MAD 和并发负载导致 `MEASUREMENT_BLOCKED`，没有 Online。
- V057/V061 等 sibling 的 correctness failure 被保留且没有被错误地当成 V062 parent；V063-V067 继续拆分 FP32 narrow/batched order，late evidence 仍是 compile/correctness-only 或 noisy measurement，未形成 Official 结论。
- 关键证据：`本地实验/ROW-SCALE-HOIST-X/V058/RESULT.md`、`V062/RESULT.md`、两版 `source-meta.json`、以及各 Revision declaration；完整源码索引见 `索引/revision-source-index.tsv`。

## MODE-DISPATCH-CUTOFF-X

- 111 个 Revision（worktree 目录名为 `本地实验/R-W4-4/V001-V111`），研究轴是 FP32 small-batch dispatch cutoff 的 OFAT 调整。
- V074（源码 commit `180ac9904856159c8e61be22fda074832e0a5cb`，SHA `d3a471cc...`）将 `kSmallFp32BatchMaxWidth` 从 4096 调到 8192。Candidate 在 8184 和 8200 失败，8192 通过；只对共同通过的单一 shape 做了 noisy partial local，`+3.059%`，明确 `LOCAL_SCORE_COMPARABLE_TO_OFFICIAL=NO`、`NEEDS_ONE_MORE_LOCAL`、`ONLINE=NOT_ELIGIBLE`。
- V096（源码 commit `717462a2756a5a9d9a4dbc17ae0a28cfcbd03d49`，SHA `7f44a290...`）将 cutoff 调到 1008；三 shape 的 partial local 为 `1.033084x`，但 Candidate 分布 noisy、`NEEDS_ONE_MORE_LOCAL`、`NOT_PROMOTED`，source-meta 的 Official Score 为空且 Online 未运行。
- V001 的编译诊断、V074 的父版 C15 已知 correctness failure、以及 V096 的三 shape raw timing 均保留在原 worktree；未将 partial ranking 当作 Official。
- 关键证据：`本地实验/R-W4-4/V074/partial-ranking/V074-PARTIAL-RANKING-RESULT.md`、`V096/local-result.json`、`V096/source-meta.json`、`V096/v096-compile-result.txt`。

## SYNC-BARRIER-ELISION-X

- 81 个 Revision（V001-V081），研究轴是不同 active path 中单个 PipeBarrier、event handoff 或同步边界的删除/移动。
- V002 和 V006 都有 compile/correctness pass，但 local 数据明确 noisy/rejected；V006 的 `+24.060984%` 是 single-shape route-local paired 数字，不可与 Official 比较，Current Local Best 仍为 R31B V011。
- V081 是未提交的有效源码（SHA `f62c2692...`），compile 与 9/9 correctness 通过，但三次 Local 分数方向不一致（`-1.654%`、`+2.210%`、`-5.955%`），verdict 为 `LOCAL_REJECTED_NOISY`。原始 runner 内部标签称 V080 的差异也在 declaration/source-meta 中保留，没有改写 raw log。
- 关键失败风险是删除同步后可能让 ReduceSum/输出消费者读取未完成结果；所有 correctness failure、noisy measurement 和未提交 V081 源码均保留。关键证据：V002/V006/V081 的 `REVISION-DECLARATION.md`、`source-meta.json` 和 local/correctness result。

## STAGING-LIVENESS-X

- 34 个 Revision（V001-V034），研究轴是 FP32 wide-row pipeline 中 MTE3/V release wait 与 `SyncMTE2ToV` 的位置关系。
- V034（源码 commit `038edbe2f7de694232dc1b94e8cf62ae75fb8db4`，SHA `75131108...`）为 compile pass；最初 route-owned 资产没有 correctness runner，后续 route-local synthetic runner 对 Parent/Candidate 的 T14 都失败，Candidate 与 shared wide-FP32 path 的 failure 不能证明独立回归。Local 没有合法分数，Online 被禁止。
- 重要边界：`full_link` 的 no-op host main 和 compiler-ABI probe 不是 correctness；V034 后续 T14 contract recheck 仍定位为 shared-path unstable numerical failure，不能写成 Official 或 Local Best。
- 关键证据：`V034/REVISION-DECLARATION.md`、`V034/CORRECTNESS-BLOCKER.md` 及 `support/results/` 下的 T14 receipt。

## ALIGNED-TAIL-DATACOPY-X

- 仅 V001，研究目标是对齐尾部 DataCopy/尾块路径；没有独立线上候选。
- `本地实验/ALIGNED-TAIL-DATACOPY-X/V001/submission.asc` 是未提交但有效的 include-style Candidate，实际 SHA-256 为 `a8c19a1972207acc67e3fb0cd393cc70b0a4b183d1eaf5610edf80c2879b15e3`，与 R31B V011 Parent 源码字节相同；它已作为去重源码纳入 `归档/W4/源码/a8c19a19...submission.asc`，Revision 索引明确标为 `UNKNOWN/UNCOMMITTED`。
- Route-owned exact wrapper/build/correctness assets 曾缺失；Parent contract build 通过但 Candidate target 未生成，保留的 Parent full-suite 仍有六个 FP32-wide failure。没有把 Parent contract check 误报为 Candidate compile/correctness，也没有运行 Online。
- 关键证据：`V001/COMPILE-BLOCKER-20261006.md`、`ASSET-RECOVERY-CHECK-20261006.md`、`DIRECT-BUILD-ENTRY-CHECK-20261007.md`、`PARENT-RUNNER-CONTRACT-20261008.md`。

## 统一收口结论

五条路线都保留完整 Revision 源码历史；没有任何一条的现有证据可以替换正式 Champion。Planning 声明的前两名只在 `官方结果摘要.tsv` 作为未核实输入保留，正式成绩字段统一为 `NOT_RECORDED`，见 `冲突与证据界限.md`。
