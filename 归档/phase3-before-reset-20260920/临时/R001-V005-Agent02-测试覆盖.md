## 已执行 case 的形状归纳

`main.asc` 将 `rank=2` 映射为 `[rows,D]`，`rank=3` 映射为 `[1,rows,D]`，`rank=4` 映射为 `[1,1,rows,D]`。据此，当前服务器记录已经形成以下覆盖：

| dtype | 2D | 3D | 4D | 非对齐 D | 宽行 / 分块 |
| --- | --- | --- | --- | --- | --- |
| FP16 | 有 | 有 | 有 | `1/31/33/67/127/129/1000` | `4096/8192/32768` |
| BF16 | 有 | 有 | 有 | `1/31/33/67/127/129/1000` | `4096/8192/32768` |
| FP32 | 有 | 有 | 有 | `1/31/33/67/127/129/1000` | `4096/32768` |

这里的 FP32/BF16 结论来自服务器补充日志，不来自原始 16 探针入口。FP32 日志中的 5 例均在 `atol=1e-4, rtol=1e-4` 下通过；BF16 日志同时保留了题面容差结果和严格位级结果，二者不能合并成一个“位级全等”的结论。

## 具体缺口

1. 原 16 个 FP16 探针没有数值比对，因此只能证明 Kernel 能运行完，不能证明 16 个 case 的输出正确。
2. 平台模板的 `gen_data.py` 和 `verify_result.py` 依赖 NumPy，不能作为无 NumPy 的 FP32/BF16 验证入口。
3. 三 dtype、BF16 和 D 边界日志没有保存生成参考值的脚本、完整命令和比较阈值。它们能证明已有运行与日志中记录的比对结果，但复核者无法只靠 V005 目录重新生成完全相同的参考。
4. BF16 在严格位级参考中有 1 个差异；在题面容差日志中 7/7 通过。提交前应保留这两个结果，并以题面正式阈值作为最终判断依据。
5. 没有性能数据，也没有新的 CANNJudge 结果可用于当前 V005 判断。

## 建议的最小复现实验命令

当前已有日志已经覆盖请求的轴，不需要为覆盖本身重新编译。若要补一份可重复的无 NumPy运行记录，可复用服务器现有可执行文件和 `gen_probe.py`；该生成器只依赖 Python 标准库。先用当时 `npu-smi info` 确认空闲设备，下面的 `7` 仅沿用已有日志示例：

```bash
ssh cann-server3
source /home/data4t2/lelinfeng/cann_game/.toolchains/cann-9.0/cann-9.0.0/set_env.sh
cd /home/data4t2/lelinfeng/cann/实验/V005/工程

DEVICE=7
run_case() {
    dtype="$1"; d="$2"; rows="$3"; rank="$4"; seed="$5"
    PROBE_D="$d" PROBE_ROWS="$rows" PROBE_DTYPE="$dtype" \
        PROBE_SEED="$seed" python3 gen_probe.py || return $?
    PROBE_DEVICE="$DEVICE" PROBE_D="$d" PROBE_ROWS="$rows" \
        PROBE_RANK="$rank" PROBE_DTYPE="$dtype" \
        timeout 30 ./add_rms_norm_bias_custom || return $?
}

run_case fp32 64 2 2 1201
run_case fp32 67 17 3 1202
run_case fp32 4097 17 4 1203
run_case bf16 64 2 2 1301
run_case bf16 67 17 3 1302
run_case bf16 4097 17 4 1303
```

这 6 个 case 的作用是：每个 dtype 各覆盖一次 2D 对齐宽度、一次 3D 小 D 尾块、一次 4D 的跨 4096 分块且非对齐 D；`rows=17` 还能覆盖完整行组与末尾短行组。该命令只能给出运行状态和输出文件，不能替代精度比对。

若需要数值结论，应在同一目录用纯 Python 标准库读取 `input/*.bin` 与 `output/output.bin`，按 `fp16/fp32/bf16` 解码，计算 `y=x+residual`、最后一维平方均值加 epsilon、开方、gamma 缩放和 bias 加法，再输出 `max_abs`、`max_rel`、错误元素数，并使用题面对应阈值。当前 V005 目录没有保存这个纯 Python 参考器，所以本轮不新增脚本、不执行补测。
