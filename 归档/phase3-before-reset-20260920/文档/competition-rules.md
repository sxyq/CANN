## 4. 计分与精度要求

- 共 **15 个测试点**（用户提供，页面未明文，待确认），全部通过才计分。
- 计算必须与 PyTorch 组合 `rms_norm(x + residual, (D,), gamma, eps) + bias` 对齐。
- 精度表（题面原文）：

| 数据类型 | 相对误差 | 绝对误差 |
| --- | --- | --- |
| float32 | < 1e-4 | < 1e-4 |
| float16 | < 1e-3 | < 1e-3 |
| bfloat16 | < 1e-3 | < 1e-3 |
| int32 | 完全准确（题面模板遗留，输入不含 int32，待官方澄清，不影响实现） | — |

- 输入数值范围：不超出各自数据类型的原生表达范围。
- 确定性要求：多次执行结果完全一致（不可含随机性）。
- 性能要求：正确性达标前提下优化性能、充分利用 NPU 特性（题面原文）。

## 5. 合规边界（用户约束，最高优先）

1. 核心计算必须在昇腾 NPU 上以 Ascend C 完成；**禁止** Host 代算、空 Kernel、按测试用例写死结果、绕过正常计算流程。
2. 输入输出处理：仅按张量接口正常搬入/计算/搬出；不得引入与题目无关的参数或作弊路径。
3. 保留主项目既有用户改动：不得 reset/checkout/清理全仓库或覆盖无关文件；比赛内容只允许在当前独立 CANN 仓库内增改。
4. 不创建第二套工程、备份工程或重复 App（不复制 `源码/` 之外的工程副本；`提交/` 只是打包产物目录）。
5. 凭据零写入：密码/Token/Cookie/授权头不得进入源码、文档、日志、截图或 Git。
6. 无真实昇腾 NPU 与 CANN 环境时，不得声称编译/精度/性能已通过；所有 NPU 侧结论明确标注“未在真实 NPU 验证”。
7. 最终上传/提交是外部操作：准备、构建与本地验证完成后必须先汇报，用户明确确认后才可执行。
