## 2. 题目与边界

### 2.1 计算语义（A，题面+golden）

```text
y       = x + residual
rms     = sqrt( mean(y^2, axis=-1) + epsilon )   # eps 在 mean 之后、开方之前
z       = y / rms * gamma                        # 除法，不是乘 1/rms
output  = z + bias                               # bias 在归一化之后
# 全程 FP32 中间计算，末尾一次 cast 回原 dtype
```

权威实现为平台模板 `scripts/AddRmsNormBias.py`。官方开源非量化 AddRmsNorm 均无 bias；量化版 `AddRmsNormQuant` 的 offset 不是本题 bias。

### 2.2 输入输出与规格（A）

| 项 | 值 |
| --- | --- |
| 输入 | `x`、`residual`：`(..., D)` 同形同型；`gamma`、`bias`：`(D,)` |
| 输出 | 与 `x` 同 shape 同 dtype |
| dtype | fp16 / bf16 / fp32（枚举 0/1/2） |
| rank | 2D / 3D / 4D；batch∈[1,8192]，seq∈[1,32768]，D∈[64,32768] |
| 非对齐 | D 可能不是 32 的整数倍 |
| epsilon | float，默认 `1e-5`，由 `run_kernel` 末参传入 |
| 特殊值 | NaN/Inf 按公式传播且不崩溃；同输入多次结果一致 |
| 测试点 | 15，全过才计分；每点 iterations=5 |
| 精度（题面） | fp32 相对/绝对 <1e-4；fp16/bf16 <1e-3 |
| 本地 verify | `np.isclose(rtol=1e-3,atol=1e-3,equal_nan=True)` + 失配 ≤0.1%（判题端是否同口径未证实） |
| 计分 | 单点 `100/(1+log₁.₅(t/T))`，T 为实时最优；性能唯一计分 |

### 2.3 平台与合规（A/B）

- 目标 CANN `9.0.0`；kernel 类型 vector；直调单文件 `kernel.asc`。
- 入口：`extern "C" void run_kernel(..., int64_t availableCoreNum, aclrtStream stream, float epsilon)`；内部 `__global__ __vector__`；无 `main()`、无 tiling 结构体。
- residual add、平方、归约、eps、sqrt、归一化、gamma、bias 必须在 Kernel 内完成；禁止 Host 代算、空 Kernel、写死输出。
- `GET_TILING_DATA_WITH_STRUCT` 等 tiling 宏「暂不支持 Kernel 直调工程」（A）。
- A2 上 Add/Mul/Muls/Sqrt/Rsqrt/ReduceSum **不支持 bfloat16_t**，bf16 必须 Cast→fp32→Cast。
- 当前机器无 CANN/NPU；V001 平台 15/15 Compile Error（`pipe_`）；V002 平台收到截断文件（首行 `return false;`），**2955 行完整版从未被平台真正编译过**。

## 8. 路线组合分析

1. **两遍与单遍能否共存**  
   可以。首版用 R001；D 进入 R002 护栏（保守 D≤4096）时切单遍，超限回退 R001。O4/5/6 均给出分档方案。

2. **γ/b 驻留与流水能否共存**  
   可以。R014 与 R013（双缓冲）可同用，但 UB 需重算；首版不宜同时叠满。

3. **尾块与不同分块能否共存**  
   可以。R009 挂在任意 tile 尺寸上；R012（32B 行块）是分核层防御，与 tile 无关；R010 仅在 R009 真机证伪时替换。

4. **FP32/FP16/BF16 是否需要不同路径**  
   计算链相同（R017 强制）。差异在：bf16 无 A2 算术必须 Cast 中转；输出 R018；tile 尺寸可按 dtype 调（fp32 tile 常减半）。

5. **小 D/大 D/不同 outer 是否分分支**  
   应分：outer 形态影响 R016/R008 选择；D 影响 R001/R002 与 R005/R006；但分支数量必须收敛，避免 R003 的巨型多分支编译风险。

6. **多条路线能否放进同一 `kernel.asc`**  
   可以，且这是实际策略：一个文件内保留「两遍主干 + 单遍护栏 + 尾块 + FP32 + Divs」即可；不要复制数十个 Process 变体。

7. **组合后对精度/UB/访存/并行/编译的影响**  
   - 精度：R017+R019+R020+R018 为刚性组合。  
   - UB：R001 低占用；R002+R013 叠加需预算表。  
   - 访存：R002、R014、R015 降流量。  
   - 并行：R016 默认；R008 兜底。  
   - 编译：R023 收敛体量；R021 真机环境。

8. **必须真机验证的组合**  
   R009 写出哨兵；R007 count/work；R012 多核并发；R013 收益；R011 参数形态；R018 真机 RNE；R021 整链编译。

9. **仅作研究参考**  
   R004（对照）、R008（默认）、R014 的 GPU 机制层、R022 全部生成器产物。
