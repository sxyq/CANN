## 3. 推荐实现（首选组合）

路线 = 两遍扫描 Pass1 平方和归约 → Pass2 归一化+gamma+bias 输出；按 outer 行均分 AI Core；DataCopyPad 搬入补 0 / 搬出真实字节；ReduceSum（count 版）分块 ≤4096 + 块间标量合并；FP32 全中间计算 + CAST_RINT 输出。与官方 `ops-nn/AddRmsNormQuantV2`（公式同构，A）和 `ops-transformer` NORMAL/SPLIT_D 结构一致（A）。

**代码级必做（提交前）：**
1. 入口 `extern "C" __global__ __aicore__` → `extern "C" __global__ __vector__`，与模板逐字对齐（矛盾 4，改动成本极低）。
2. half tile 4096 → 2048（ReduceSum count 上限争议，统一分块 ≤4096；fp32 tile=2048 已安全）。

**Kernel 计算链（精度视角，A6 建议）：** `Cast(CAST_NONE)→Add(fp32)→Mul 平方→分块 ReduceSum(≤4096)→块间标量合并→Muls(1/D)→Add(eps)→Sqrt(向量)或正确舍入 rsqrt→Muls(1/rms)→Mul(gamma fp32)→Add(bias fp32)→Cast(CAST_RINT)`。

## 4. 替代路线（仅作备选，不进 V001）

| 路线 | 适用 | 结论 |
| --- | --- | --- |
| 单遍存 y（y 留 UB） | 小 D（fp32≤4096 / half≤8192） | 第二候选：访存 5ts→3ts；大 D 退化两遍 |
| 大 tile（D≤8192 一行一块） | half/bf16 | 第二候选（性能向），需先解 count 上限 |
| 手工向量归约（二分累加 172 vs ReduceSum 242 cycles） | 性能冲刺 | 性能优化候选：Add 折叠 + WholeReduceSum + 双缓冲 + gamma/bias 驻留 + 行末一次 GetValue |
| 手工尾块（DataCopyCustom/GetValue 重排） | DataCopyPad 不可用的判题机 | 官方降级路线（910 系在用） |
| 低精度中间计算 | — | **不建议**：fp16 累加必溢出、bf16 域加法 ~25% 元素翻转 |
| tile 跨核分配 | — | **不建议**：无 grid sync，跨核归约被通信吃掉 |
| CUDA/Triton/PyTorch 直接迁移 | — | **仅研究参考**：算法结构可借鉴，执行机制不可照搬（位级结果不可移植） |
| TileLang-Ascend / Triton-Ascend / AKG 等自动生成 | — | 产物形态与直调模板不匹配，不作为提交路径 |

## 5. 精度结论（CPU 实验 + 官方文档，未真机验证）

- 判题 golden = 输入各自量化 → FP32 计算 → cast 回原 dtype；判定 `np.isclose(rtol=0.001, atol=0.001, equal_nan=True)` 逐元素 + 失配 ≤0.1%（A/B，读模板源码；判题端是否一致未证实）。
- **fp32 / fp16 必过**；**bf16 是唯一风险**，两条硬约束：归约分块 ≤4096（整行顺序归约 D=32768 实测 mismatch 0.16% 挂）；sqrt 正确舍入（裸 rsqrt 误差 2^-14 时 0.4~1.2% 全挂，向量 Sqrt 0 ulp 最稳）。
- `CAST_RINT` = RNE（A），与 numpy 一致；**A2 的 Add/Mul 不支持 bfloat16_t，必须 FP32 域计算**；中间 Cast 时机必须与 golden 同链（S8 反例）。
- 输入 NaN/Inf 沿 rms 污染整行，禁止 clamp/分支。

## 6. 最重要风险（真机第一验证批）

| # | 风险 | 说明 | 验证方法 |
| --- | --- | --- | --- |
| 1 | SoC 型号/DataCopyPad 支持 | 老 Atlas 训练系（910A/B）不支持 DataCopyPad；dav-2201=910B/A2 系为推断 | 真机 `npu-smi info` + 编译运行最小用例 |
| 2 | DataCopyPad UB→GM 搬出写方向 | A 级"精确写回" vs C 级"padding 覆盖相邻行"，直接威胁 D 非 32 倍数尾块 | D=67/129/1000 搬出后逐字节核对相邻行 |
| 3 | ReduceSum(count) 上限 | 4096 / 16320 / 受 UB 限制三方冲突 | 2048/4096/8192 扫描实测 |
| 4 | sqrt 精度（bf16 生死线） | 标量 sqrtf 精度无文档；rsqrt 2^-14 必挂 | 向量 Sqrt vs 标量 sqrtf vs rsqrt 对照 |
| 5 | CAST_RINT 逐位等价 | RNE 规则文档 vs 硬件行为 | 真机非整数值舍入对照 |
| 6 | FetchEventID 事件槽 | A2 槽 0-7，循环内反复调用是否溢出 | 真机长循环观察同步错乱 |
| 7 | 判题端判定细节/15 点配置 | 平台不开放测试用例 API | 登录提交页 + 泛化覆盖矩阵 |
| 8 | 上传表单字段 | 直调 kernel.asc vs 旧 4 字段 | 登录提交页确认 |
| 9 | 9.0.0 头文件签名 | `workLocal`→`sharedTmpBuffer`、ISASI、dynUBufSize=nullptr | 安装后核对 kernel_operator.h |

## 7. 下一步执行计划

**本地可做（无 NPU）：**
1. 提交前两处代码改动（§3）：入口限定符 + half tile 2048。
2. CPU 同链验证实现（脚本 /tmp/agent06_numerics/ 可复现），对改动后算法再过一遍测试矩阵（dtype×rank×D×outer + 边界格）。

**真机后（按顺序）：**
3. 环境：Linux 昇腾 → CANN 9.0.0 + 配套 HDK（26.0.RC1/25.5.2/25.5.1）→ `npu-smi info` → 跑通模板 run.sh 默认 FP16 [1,64]。
4. 第一验证批：§6 的 1→2→3→4→5→6。
5. 精度矩阵：按测试矩阵在真机跑 15 点泛化覆盖，逐点记录误差（fp32<1e-4；f16/bf16<1e-3），结果写 `提交/结果-YYYY-MM-DD.md`。
6. 性能优化阶梯：v1 正确性 → msOpST 计时 → v2 gamma/bias 驻留 → v3 减标量同步/向量化 sqrt → v4 双缓冲（按 Profiling 的 MTE2 vs Scalar 占比决定优先级）。
7. 上传：全部闭环、用户明确确认后，按直调格式提交；记录到 `提交/历史-YYYY-MM-DD.md`。
