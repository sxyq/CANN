## 2. 判定口径说明（关键）

判题脚本 `verify_result.py` 的逻辑：**用 NPU 输出 bin（同 dtype）与同 dtype golden bin 比对**，流程为：
1. BF16 两者先 `astype(float32)` 再比较；FP16/FP32 直接比较。
2. `isclose(a, b, rtol, atol, equal_nan=True)`，即 `|a-b| <= atol + rtol*|b|`。
3. 失配比例 `error_rate = (失配数+缺元素)/总数`；若 `error_rate <= tol` 则**通过**。

**默认模板 spec**：`(float16, rtol=0.001, atol=0.001, tol=0.001)`。
**赛题精度要求（题面）**：FP32 rel/abs < 1e-4；FP16/BF16 rel/abs < 1e-3。
→ 本矩阵按「FP32 用例 rtol=atol=1e-4、tol=1e-3；FP16/BF16 用例 rtol=atol=1e-3、tol=1e-3」推演；最终以赛题发布的 `case_output_specs` 为准。

**两种口径的差别（影响 BF16 结论）**：
- 口径 A（与同 dtype golden 比对）：BF16 **应通过**（见实测 0.009%–0.012% 失配 < tol）。
- 口径 B（与 FP64 真值比对）：BF16 **无法判定/必不过**（格式固有 ulp≈3.9e-3）。
- 实际判题为口径 A。

## 3. 矩阵与期望结论

### 3.1 常规随机输入（无特殊值）

按 dtype × rank × D × outer 给出结论。rank 与 outer 对数值精度**无独立影响**（每行独立归约，rank 仅 reshape、outer 仅行数），故结论按 dtype×D 归纳，rank/outer 标注适用范围。

| dtype | D | 期望结论 | 依据（本机实测） |
| --- | --- | --- | --- |
| FP32 | 全部（1…32768） | **应通过** | vs FP64 真值 maxRel ≤ 1.8e-2（个别近零元素）；vs 同 dtype golden 零失配；D=1024 maxRel 9.6e-5 < 1e-4 |
| FP16 | 全部（1…32768） | **应通过** | vs 同 dtype golden 零失配（D=1024/32768 实测 fail=0）；vs FP64 真值 maxRel 4.8e-4 < 1e-3 |
| BF16 | 1, 31, 32, 33, 64, 127, 128, 129, 1024 | **应通过**（已知风险） | vs 同 dtype golden：D=1024 exact 99.98%、fail=1/8192=0.012% < tol 0.1% |
| BF16 | 4096, 32768 | **应通过**（已知风险） | vs 同 dtype golden：D=32768 fail=1517/16.7M=0.009% < tol 0.1%；失配均为 1-ulp 边界翻转 |

> 已知风险（BF16）：依赖 `tol=0.001` 容忍；若判题改为 `tol=0`（严格逐元素相等），归约顺序差异造成的 1-ulp 边界翻转可能使少数元素判不过（R1/R2）。
> 分块/顺序归约、rank、outer 不改变上述结论（实验 C：D=32768 各分块相对误差 < 1e-5）。

### 3.2 特殊值输入

| 特殊值 | dtype | 期望结论 | 说明 |
| --- | --- | --- | --- |
| 全 0（eps=1e-5 保驾） | 全部 | **应通过** | 输出 = bias（golden 同），无除零 |
| 含 1 个 NaN | 全部 | **应通过** | 输出 NaN；`equal_nan=True` 判过（与 golden 一致） |
| 含 ±Inf | 全部 | **应通过** | `Inf/Inf=NaN` → 整行 NaN；与 golden 一致 |
| 量级 \|v\|≥256（FP16 溢出边界） | FP32 | **应通过** | FP32 无溢出 |
| 量级 \|v\|≥256 | FP16/BF16 | **应通过**（已知风险 R7） | 候选先 `CAST_NONE→FP32` 再平方，完全消除 FP16 溢出；**仅当实现错误地在 FP16 中平方时才 Inf 污染** |
| 大小混合（近零行 + 大值行） | 全部 | **应通过** | 近零行受 eps 位置影响（见下）；正常实现（eps 在 sqrt 内）安全 |
| 近零残差（mean(y²)<<eps） | 全部 | **已知风险（R6/R8）** | 若 eps 位置写错，输出偏差可达 28 倍；eps 在 sqrt 内则安全 |

### 3.3 实现缺陷专项（反向验证，用于定位 bug）

| 缺陷 | 期望结论 | 触发/量化 |
| --- | --- | --- |
| eps 放在 sqrt 外 | **无法判定（必过不了）** | 近零行 rms 偏差 -96.5%、输出差 28 倍；普通行仅 ppm |
| FP16 中直接平方（错误实现） | **无法判定** | \|y\|≥256 → Inf 污染整行 |
| sqrtf 被低精度近似替换（误差~1e-3） | **已知风险** | 可能压线或超 FP16/BF16 的 1e-3 预算 |
| CAST_RINT 非 RNE | **已知风险（R5）** | BF16 失配率上升（仍 ≤1 ulp） |

### 4.2 在判题环境（NPU）复核完整矩阵
对每组 (dtype, rank, D, outer, 特殊值)：
1. 用 `scripts/AddRmsNormBias.py` 的 `impl` 生成 golden bin；
2. 用候选 kernel 生成 output bin；
3. 调用 `scripts/verify_result.py <case_id>`，读取 `case_output_specs` 中的 (dtype, rtol, atol, tol)；
4. 判定 `PASSED`/`FAILED`，并记录 `Mismatched` 比例与 `Max diff`。

### 4.3 矩阵枚举示例（伪代码）
```python
dtypes = [np.float32, np.float16, bfloat16]
ranks  = [(outer, D) for outer in [1, 64, 512, 8192]
                     for D in [1,31,32,33,64,127,128,129,1024,4096,32768]]
# 其中 rank 维（2D/3D/4D）通过在 outer 之外再 reshape 实现，如 (2,3,4,D) 表 3D
specials = ['none','zeros','nan','inf','large256','mixed','nearzero']
for dt in dtypes:
  for (outer, D) in ranks:
    for sp in specials:
      run_case(dt, outer, D, sp)   # 生成 golden+output，verify，记录结论
```

## 5. 结论速查

- **FP32 / FP16**：所有常规与特殊组合 → **应通过**（双口径均稳过）。
- **BF16**：常规与特殊组合 → **应通过**，但标记「已知风险」——依赖 `tol=0.001` 容忍 1-ulp 边界翻转；`tol=0` 时可能失守（R1/R2）。
- **需忽略**：rank、outer、分块大小对精度无实质影响（可不作为精度验收变量）。
- **无法判定（需真机）**：sqrtf/rsqrt 指令实际精度（R3/R4）、CAST_RINT 舍入模式（R5）、最终 `case_output_specs` 取值。
- **实现缺陷类**（eps 位置、FP16 内平方）须为**无法判定（必不过）**，应在实现阶段杜绝。
