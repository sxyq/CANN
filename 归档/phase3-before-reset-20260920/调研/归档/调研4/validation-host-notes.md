## 3. 对照基准

- **golden**：`/Users/sunyiyang/Downloads/addrmsnormbias_problem_1742_template/scripts/AddRmsNormBias.py` 的 `impl`（numpy 组合实现，内部统一 FP32，末尾转回原 dtype）。

## 4. 结果一：算法结构等价性（21 组）

`kernel_sim_v002.py` 结果摘要：

| 组别 | 结果 |
| --- | --- |
| fp16（D = 64 / 67 / 96 / 129 / 192 / 576 / 1000 / 1024 / 4096 / 4097 / 32768） | 失配率全部 **0.0000%** |
| bf16（D = 64 / 129 / 1024 / 4096 / 32768） | 失配率全部 **0.0000%** |
| fp32（D = 64 / 129 / 2048 / 2049 / 32768） | 失配率全部 **0.0000%** |
| 判定为 CHECK 的用例 | **无** |

**结论（CPU 口径）**：V002 的算法结构对 `D` 非 32 倍数（67 / 129 / 4097）与 `D = 32768` 这两种易错形态均与 golden 等价；分块边界不引入可观测误差。

同时记录到两个**离群观测**，在结果二中单独隔离：

- fp16、D = 4097 时「vs golden 最大相对误差」= 9.17e-4，逼近 1e-3 阈值；
- fp16、D = 32768 时 = 7.66e-4。

## 5. 结果二：差异来源隔离（压力测试）

### 5.1 分块累加顺序不是主要来源

`kernel_sim_v002_stress.py` 实验 B：分块（tile = 4096）累加 vs 整体累加，在 D = 4096 / 4097 / 8192 / 8193 / 32768 上，平方和相对差 ≤ **8.9e-8**，由此产生的 rms 相对差 ≤ **7.3e-8**。

→ 分块归约本身**不是**误差来源，可放心使用 `tile ≤ 4096`。

### 5.2 归一化除法路径是主要来源

V002 用 `scale = 1.0f / rms` 后 `Muls(y, scale)`；golden 用 `y / rms`。两条路径在实数域等价，在浮点域**舍入路径不同**。

`kernel_sim_v002_divpath.py` 以 P1 = `y / rms`（golden 路径）为参考，对比 P2 = `y * (1/rms)`（V002 路径）：

| dtype | 与 P1 不完全相等的元素数 | isclose 失配（rtol=atol=1e-3/1e-4） | 最大绝对误差 | 最大相对误差（\|ref\|≥1e-3） |
| --- | --- | --- | --- | --- |
| fp16，D ≤ 32768 | 0 ~ 3 / 最多 131072 | **0** | ≤ 4.88e-4 | ≤ 8.81e-4 |
| bf16，D = 32768 | 3 / 131072 | **0** | 9.77e-4 | **7.41e-3** |
| fp32，D = 32768 | 25166 / 131072（≈19%） | **0** | 4.77e-7 | 2.53e-5 |

**解读**：

- 差异元素数极少（bf16/fp16 ≤ 3 个 / 131072），但**单个元素的相对误差可达 7.4e-3**，即约 1~3 个 bf16 ulp（bf16 ulp ≈ 2^-8 ≈ 3.9e-3）。这是**量化分界翻转**，不是累积误差。
- fp32 上约 19% 的元素存在 1 ulp 差异，但绝对误差 ≤ 4.8e-7，远低于 1e-4 阈值，无风险。
- 在 `isclose(rtol=1e-3, atol=1e-3)` 判据下，**三种 dtype 的失配数均为 0**。

**由此得到一个关键未知量**：判题是否等价于模板的 `isclose + ≤0.1% 失配率` 语义。

- 若是 → V002 当前写法可通过；
- 若判题要求**每一个元素**都严格满足 < 1e-3 → bf16 上存在**失败风险**。

**建议的零成本缓解**：把 `Muls(y, scale)` 改为与 golden 同链的「先除」写法（`Divs(y, rms)`，或 `Mul(y, y, rms)` 后 `Div`），使舍入路径与 golden 逐位一致。**这一改动是纯收益（无额外指令成本），且能消除上述 1~3 ulp 差异。**

### 5.3 多种子扫描（40 种子 × D × 量级）

`kernel_sim_v002_stress.py` 实验 C（V002 即 P2 路径 vs golden）：

| dtype | 最大绝对误差 | 最大相对误差（\|ref\|≥1e-3） | 失配率 > 0.1% 的种子数 |
| --- | --- | --- | --- |
| fp16 | ≤ 1.95e-3 | ≤ 9.75e-4 | **0 / 40** |
| bf16 | ≤ 1.56e-2 | ≤ 7.58e-3 | **0 / 40** |

量级缩放取 1 / 10 / 100，D 取 1000 / 4096 / 4097 / 8192 / 8193 / 16384 / 32768。

→ 结论与 5.2 一致：**在 isclose+失配率容忍口径下安全；在严格逐元素口径下 bf16 有风险。**

### 5.4 fp16 平方和溢出边界

| \|y\| | fp16 域 `y*y` | fp32 域 `y*y` |
| --- | --- | --- |
| 250 | 62496 | 62500 |
| 255 | 65024 | 65025 |
| **256** | **inf** | 65536 |
| 1000 | inf | 1e6 |

→ fp16 最大正规数 65504，`sqrt(65504) ≈ 255.9`。
**低精度域累加（方案 S4）在 |y| > 256 时必然产生 inf，直接失败**；FP32 域累加彻底消除该风险。这为方案矩阵中 S4 的「不建议」判定提供了本机量化证据。

## 6. 未能验证的内容（明确清单）

1. **numpy 的 `ReduceSum` 语义与昇腾向量单元是否逐位一致** —— 本模拟用 `np.sum`（pairwise 树形），昇腾的归约顺序、是否使用 FMA、是否走多级归约均未知。**这是本模拟最大的不确定性来源。**
2. **`CAST_RINT` 在昇腾上的实际舍入行为** —— 本模拟假定等价于 IEEE RNE（numpy `astype`）。9.0.0 文档口径需真机复核。
3. **昇腾 `Rsqrt` 的近似误差** —— 实验中的 P3 用高精度 rsqrt，不代表昇腾向量指令的实际近似精度。
4. **`DataCopyPad` 的尾块搬出是否真实写回 padding** —— 纯搬运语义问题，CPU 模拟无法覆盖。
5. **UB 容量、指令调度、双缓冲流水** —— 纯 CPU 模拟无对应物。
6. **15 个测试点的真实 shape / dtype / epsilon 组合** —— 平台未公开。
