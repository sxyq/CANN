## 2. 题目和边界

### 2.1 计算语义（官方题面，A 级）

`y = x + residual`，沿最后一维执行 RMS 归一化，再执行 `gamma` 缩放和 `bias` 加法：

- 归一化分母：`rms = sqrt(mean((x+residual)²) + epsilon)`（epsilon 加在 mean 之后、开方之前，默认 1e-5，由判题端传入）。
- 输出：`out = (x+residual) / rms * gamma + bias`；输出 shape/dtype 与 x 相同。
- golden 链（模板源码 A 级）：输入各自量化 → FP32 内部计算 → cast 回原 dtype；numpy `mean` 为 pairwise、`sqrt` 正确舍入、cast 为 RNE。
- NaN/Inf 语义：行内 NaN 污染整行；+Inf 与 -Inf 同行经 `inf/inf` 得 NaN；判题 `equal_nan=True`；禁止 clamp/截断/分支（调研1 Agent06、调研5 agent-06、调研6 agent06 CPU 复核一致）。

### 2.2 输入输出与范围（A 级，六轮一致）

- 输入：`x`、`residual`（`(...,D)`）、`gamma`、`bias`（`(D,)`）、`epsilon`；输出同 x。
- dtype：fp32 / fp16 / bf16（`TensorInfo.dtype` 枚举 0=fp32/1=fp16/2=bf16）。
- rank：2D/3D/4D；batch∈[1,8192]、seq∈[1,32768]、D∈[64,32768]，**D 可非 32 倍数**（67/129/1000 为六轮共同关注的边界）。
- 广播关系：gamma/bias 沿最后一维广播；最后一维以外展平为 `outer` 行。
- 接口：CANN 9.0.0 Direct Invocation 直调工程，`run_kernel(GM_ADDR x, const TensorGroupInfo& info_x, …, int64_t availableCoreNum, aclrtStream stream, float epsilon)`，内部 `<<<blocks,nullptr,stream>>>` 启动核函数；提交物为含 `run_kernel` 的单文件 `kernel.asc`（`code_template=npu_kernel_dev`）。

### 2.3 判分与精度（A 级）

- 15 个测试点全部精度通过才计分；性能为唯一计分维度：单点 `100/(1+log₁.₅(t/T))`，T=该点全局最优时间，总分=15 点均值，同分按提交时间；`iterations=5`；`ranking_submission_mode=latest`（取最后一次成绩）。
- 精度阈值：fp32 相对/绝对 <1e-4；fp16/bf16 <1e-3。本地模板 `verify_result.py` 为 `np.isclose(rtol=0.001, atol=0.001, equal_nan=True)`+失配容忍 0.1%；**判题端是否同口径未证实**（六轮共同缺口）。
- 榜上 15 点 TBest（调研3/5 抓取）：1.47μs ~ 8656.25μs，后两点（3750.12/8656.25μs）数量级更高，为性能主战场；shape 不可见不能反推。

### 2.4 合规边界（A 级 + 项目约定）

- residual add、平方、最后一维归约、epsilon、平方根、归一化、gamma、bias 必须在 Ascend C Kernel 内完成；禁止 Host 代算、空 Kernel、写死输入输出。
- 归约及中间累加优先 FP32；FP16/BF16 只在输入搬运和最终输出保留目标类型。
- 提交版本号 `V00N`；当前候选 V002（2955 行，存在 M8/M9 已裁决缺陷，未再提交）；V001 保留平台失败记录。
- 不写入凭据；CANNJudge 上传须经用户明确确认（本次汇总未执行任何外部提交）。

### 2.5 当前环境限制

本机 macOS，无 CANN 编译器、无昇腾 NPU。全部内容为资料核对/源码阅读/CPU 参考计算/静态分析；无任何 CANN 编译、NPU 精度或性能验证发生。CANN 9.0 仿真器 cannsim 仅支持 950PR，A2/910B 无本地仿真捷径（调研5 agent-08，C 级）。

## 5. 归并路线详细说明

> 状态值使用统一枚举。六轮中所有"可编译/可跑/达标"均为预判或 CPU 模拟，无真机证据。

### R001 两遍扫描（类别：计算与融合）

- **核心原理**：Pass1 逐 tile 计算 `Σy²`（y=x+residual 在 FP32 域）；Pass2 重读输入做归一化+gamma+bias 输出。与官方 ops-transformer SPLIT_D/NORMAL 结构同构。
- **实施步骤**：按行分核→逐 tile CopyIn→Cast FP32→Add→Mul 平方→ReduceSum→块间标量累加→行末得 rms→Pass2 重读→Muls/Divs→Mul(gamma)→Add(bias)→CAST_RINT→有效字节写回。
- **条件**：任意 dtype/D/outer；UB 低（逐 tile，fp16 tile 4096 约 88~108KB）；无 SoC 限制。
- **可组合**：R017（分核）、R007/R009（尾块）、R004/R021（归约）、R019（精度链）、R014（gamma/bias 驻留）、R011（多行合并）、R015（双缓冲）、R022。
- **不可组合**：与 R002 互斥（同一行路径二选一，可按 D 运行时分支）。
- **优势**：正确性基线、实现最简、任意 D 可跑、UB 占用最低；**M12 修正：第二遍可 L2 命中（192MB），真实成本 6~10B/元素之间，+67% 流量口径被高估**。
- **代价**：访存 5·N·s（fp16 口径，调研6）~7·D·S（调研4 口径），比单遍多 40%~67%。
- **失败条件/反例**：不分块时 fp32[1,32768] 四份 512KB>192KB UB 溢出；1.4× GM 流量在性能敏感点（TBest 后两点）是劣势。
- **实验状态**：`CPU 已验证`（调研4 kernel_sim_v002 21 组 PASS 失配 0；调研6 main_precision_check 三 dtype 0 失配）；未开始真机。
- **证据等级**：A（官方 SPLIT_D 同构）+B。
- **来源**：S034、S035、S037、S046；原始位置：调研1 Agent10 §6 #1、调研3 §11、调研4 S1、调研6 方案矩阵 S1。

### R002 单遍 UB 暂存 y（类别：计算与融合）

- **核心原理**：一次读 x/residual，y（FP32 副本）驻留 UB，算完 rms 直接归一化输出，省第二遍 GM 读。
- **实施步骤**：整行 CopyIn→Cast→Add 得 y 留 UB→Mul→ReduceSum→rms→归一化 epilogue→写回。
- **条件（D 分水岭多口径，保留为变体）**：①调研1 Agent04：D≤4096(fp32)/8192(half)；②调研2 Agent10 纠偏：D≤4096（峰值 80~112KB）；③调研5 M1：D≤官方单行因子 fp16/bf16≤12288、fp32≤10240；④调研6 严格模型：fp16/bf16 ≤22528、fp32 ≤11264，回退阈值 D≥24576/12288。**共同结论：超限必须回退 R001 护栏**。
- **可组合**：R017、R007/R009、R004/R005、R019、R014、R015（受 UB 约束 tile 减半）、R022。
- **不可组合**：R001（互斥分支）；D 大时与 R012 大 tile 冲突（UB）。
- **优势**：省 28.6%~40% GM 流量；同步次数少（每行一次归约）。
- **代价**：UB 峰值高（D=32768 fp32 单行四份 512KB 不可行；fp16 D=32768 单遍三块 64KB×3=192KB 恰好打满、无双缓冲空间）。
- **失败条件/反例**：fp16[1,30000] 需 240KB>192KB；fp32[128,32768] 同；调研6 反例输入已列。
- **实验状态**：静态分析/推算（UB 预算未真机实测）；`CPU 已验证`（算法链路部分经调研6 脚本验证）。
- **证据等级**：B/C（推算）+A（官方 MERGE_N/MULTI_N 单行思想旁证）。
- **来源**：S046、S094；调研1 Agent04 §3.1、调研2 Agent10 B10-2、调研5 agent-10 M1、调研6 agent07 §3.4。

### R003 低精度中间计算——否决对照（类别：计算与融合）

- **核心原理**：全程 fp16/bf16 累加（仅作对照实验，不可用于提交）。
- **CPU 定量证否**：fp16 顺序累加 D=1024 失配 83%~99.9%（调研3）/0.13%（调研6 分布差异）；fp16 向量和 D=32768 溢出；bf16 顺序累加 D=32 起挂、全程 31%~65%/50%+/98.96% 失配（三套脚本口径不同、方向一致）；|y|≥255.94 时 fp16 平方=inf（RuntimeWarning 实证）。
- **失败条件**：任何 dtype 任何大 D。
- **实验状态**：`CPU 已验证`（证否）；不可作为提交路线。
- **证据等级**：A（IEEE-754 机理）+CPU 实验（调研4 numerics_experiments、调研6 Q6/main_precision_check）。
- **来源**：S066-S073；各轮数值报告。

### R004 ReduceSum 接口归约（类别：归约与数学）

- **核心原理**：官方 `ReduceSum(dst, src, sharedTmpBuffer, count)` + `GetValue(0)`（V_S/S_V 事件同步成对）。
- **实施步骤**：分块 ≤4096 → 每块 ReduceSum → 块间标量合并（行末一次 GetValue）。
- **条件**：A2 仅 half/float（bf16 须先 Cast）；src 32B 对齐；sharedTmpBuffer ≥ `RoundUp(count/64,8)×8`（fp32）；**count 上限三口径**：官方"≤UB 限制"（A）≈4096（B 实测口径，XJTUACM S7）≈16320（B 源码注释口径，<255 repeat）——工程统一按 ≤4096 规避；A2 `srcInnerPad` 仅支持 true。
- **可组合**：R001/R002、R019、R021。
- **优势**：接口简单、正确性锚点（cann-samples 0_naive 同构）；**代价**：软仿实现通常最慢、内部含 scalar wait 阻塞流水。
- **失败条件/反例**：count 超真机上限；fp16 源直接归约遇 |y|≥256 得 inf（ReduceSum 内部不处理累加溢出，官方 A 级）。
- **实验状态**：`CPU 已验证`（算法链路）；接口行为 `无法验证：缺少环境`。
- **证据等级**：A。
- **来源**：S012、S018、S058、S249；调研1 Agent02 §1.2、调研5 agent-02 定案 3。

### R005 手工向量归约（类别：归约与数学）

- **核心原理**：Add 折叠到 64 槽（src1RepStride=0 广播）+ WholeReduceSum；或 findPowerTwo 二分折叠；或 BlockReduceSum+WholeReduceSum 组合（256 fp32：8.44μs vs 13μs，官方最佳实践 A 级）；或 Newton 迭代 rsqrt 两轮 `y*(1.5-0.5*x*y*y)`（rms_norm_quant_story 第 6 步）；VF RegAPI 寄存器数据流（高风险变体，仅 950 系样例，`UpdateMask` 会破坏 count 标量须重赋值）。
- **条件**：WholeReduceSum A2 支持、fp32 mask∈[1,64]、repeatTime∈[0,255]（单次 16320）、half 溢出饱和 65504；二分累加 172 cycles < ReduceRepeat 242 cycles。
- **可组合**：R001/R002、R014、R019。
- **优势**：去标量同步、性能候选；**代价**：折叠点/别名/掩码易错；1~3 ulp 边界翻转风险。
- **失败条件/反例**：掩码算错（C 级案例）；掩码易错清单见调研3 agent09。
- **实验状态**：`未开始`（性能候选，真机后做）；官方源码级证据 A。
- **证据等级**：A（官方 rms_norm_base.h 写法）+B。
- **来源**：S026、S035、S037、S050；调研1 Agent03 §2.5、调研5 agent-10 M3。
- **推荐级别分歧（保留）**：调研1/5/6 列性能候选；调研4/6 方案矩阵列"仅研究参考"（无收益判断）——两视角并存，以真机 profile 定夺。

### R006 标量同步削减（类别：归约与数学）

- **核心原理**：GetValue/SetValue 为官方文档明文"仅调试用，性能极低"；削减每 tile 同步次数。
- **变体**：①行末一次取数（同步 outer×tiles→outer）；②多行合并取数（[8192,64] 形态 GetValue 8192→~256 次）；③SPR 读取 GetReduceRepeatSumSpr（**仅 Ascend 950PR/DT ISASI，A2 有编译与未定义行为风险——裁决弃用**）；④向量 Sqrt+倒数广播替代标量读回；⑤跨核 DataCache 一致性（DataCacheCleanAndInvalid，C18）。
- **可组合**：R001/R002、R004/R005、R019。
- **失败条件/反例**：GetValue 滥用致 `aclrtSynchronizeStreamWithTimeout 507000`；V002（405 行版）SPR 误用+缺 V_S 同步为致命缺陷判决（调研2）。
- **实验状态**：`未开始`（设计级）。
- **证据等级**：A（官方文档）+C（实测口径）。
- **来源**：S052、S014；调研1 Agent07 §2.4、调研2 Agent10 B10-7、调研6 agent09 C18。

### R007 DataCopyPad 尾块（类别：数据搬运与尾块）

- **核心原理**：GM↔UB 非 32B 对齐用 DataCopyPad：搬入 `{isPad=true, leftPadding=0, rightPadding=补齐, paddingValue=0}` 补 0（0² 不污染归约）；搬出 blockLen=valid×sizeof(T) 精确字节（官方称 dummy 自动丢弃）。
- **关键定案**：**字段顺序官方为 `{isPad, leftPadding, rightPadding, paddingValue}`（9.0.0 表 6+官方示例双证）；始终按成员名逐字段赋值，禁止裸聚合初始化**（历史流传 `{isPad,paddingValue,left,right}` 不被支持）。
- **条件**：GM 侧 1B 对齐、Local 侧 32B；padding ≤32B；Atlas A2 训练/800I A2/200-500 A2/A3/950 支持（老训练系列与 310P 推理不支持）；A2 不支持 PaddingMode（Compact）。
- **可组合**：R001/R002、R009（混合双轨）、R017、R019。
- **优势**：官方非对齐标准方案；**代价**：非对齐有实价（A2 实测尾块不齐 -21.6% GM→UB、-47.5% GM→L1；950PR 仅 -1.8%）。
- **失败条件/反例**：**写方向语义冲突（六轮最重要矛盾）**：官方 A 级"精确写回/丢弃 dummy" vs 社区 C 级"32B burst 覆盖相邻段"——调研5 M2 补证闭环：社区案例实为调用侧把 blockLen 主动取整 32B 的用法问题；安全条件=三参 DataCopyPad+blockLen=真实有效字节数；**保留真机哨兵值验证项（D=67/129/1000 + 相邻行分属不同核）**。
- **实验状态**：`CPU 已验证`（补 0 对归约无污染）；写方向 `无法验证：缺少环境`（真机第一验证项）。
- **证据等级**：A（API 文档）+C（反例案例）。
- **来源**：S005、S008、S010、S045、S248；调研3 agent02 §2.1、调研5 agent-10 M2。

### R008 手工尾块（类别：数据搬运与尾块）

- **核心原理**：不依赖 DataCopyPad 的尾块处理，官方降级路径。
- **变体**：①DataCopyCustom（官方 rms_norm_base.h：GM→UB AlignUp 多搬+padding 被 mask 忽略；UB→GM 对齐部分先搬、尾部 GetValue/SetValue 移到 buffer 头部整块写出；`__CCE_AICORE__==220` 走 DataCopyPad、非 220 用之）；②无 Pad 降级（冗余数据参与计算+mask 掩脏、先 Duplicate 清零、搬出>32B 用 UnPad/GatherMask、<32B 目标 GM 清零+SetAtomicAdd——MTE 级，区别于仅 950 的 SIMT asc_atomic_add）；③VF+UpdateMask（`__simd_vf__` 64 元素分块、末块只覆盖余数，规避 32B 限制）。
- **可组合**：R001/R002、R017、R019。
- **优势**：判题机为老系列时的官方替代；**代价**：标量重排性能低-中；实现难度中-高。
- **失败条件/反例**：裸 DataCopy 写非对齐尾块会把邻居写成 -1（搬 11 half 实写 16，官方 A 级案例）——黑名单。
- **实验状态**：`未开始`（R007 的备选）。
- **证据等级**：A（官方源码在用）。

### R009 对齐双分支搬运（类别：数据搬运与尾块）

### R019 FP32 全中间计算链（类别：精度与数据类型）

- **核心原理**：fp16/bf16 输入搬入→`Cast(CAST_NONE)` 升 FP32→Add/Mul/归约全 FP32→epilogue→`Cast(CAST_RINT)` 回目标 dtype→搬出。A2 上 Add/Mul/Muls/Sqrt/Rsqrt/ReduceSum 均不支持 bfloat16_t（Add 为 9.0.0-beta.2 明文，Mul/Div 同族推断 B 级）。
- **依据链**：fp16 累加溢出（|y|≥256 inf）+bf16 坍塌（CPU 定量）+A2 指令缺失+GPU 全实现 acc FP32 双重收敛（跨生态互证）。
- **Cast 细节**：fp32→bf16 支持 RINT/FLOOR/CEIL/ROUND/TRUNC；**CAST_RINT=RNE 与 numpy/PyTorch 一致；TRUNC/FLOOR 失配 40.4~40.7%**；bf16/half→fp32 无损。**M8 发现：V002（2955 行版）代码行 2805 实为 CAST_ROUND，与三处文档记录 CAST_RINT 矛盾——裁决改回 CAST_RINT（RINT 0 失配且对扰动免疫；ROUND 在 A2 矩阵内、bf16 实测 0.001% 能过但非最优）**。
- **M9 发现**：V002 fp16 宽行路径 half 域 Add（行 2330/2720）与 half 域 epilogue（行 2733-2737）违反本红线（大数值必挂）——裁决统一 FP32 域；注意官方 ops-nn half 分支有 half Add 先例（B 级张力，保留）。
- **可组合**：一切计算路线的强制前提。
- **失败条件/反例**：S8 案例——中间全程 fp32（数学更精确）反而对不上 golden 的 bf16 中间结果；**判题比的是与参考一致，不是与真值一致**（golden 本身就是 FP32 中间链，故本路线与 golden 同链反而是对的；S8 案例针对的是"改运算次序/精度路径"类优化）。
- **实验状态**：`CPU 已验证`（六轮多套脚本：同链失配 0）。
- **证据等级**：A。
- **来源**：S006、S019、S048、S066-S073；调研1 Agent06、调研4 agent06、调研5 agent-06、调研6 agent06。

### R020 归一化数学路径选择（类别：精度与数据类型）

- **核心原理**：归一化执行路径的数值选择——**首选 `Sqrt`（向量 0 ulp 或正确舍入）+ `Divs`（先除）**；epsilon 位置 `sqrt(mean(y²)+eps)`。
- **CPU 实证**：`Divs(y,rms)` 与 golden 逐位一致（全部 dtype/形状失配=0，36 组探查 maxabs 恒 0）；`Muls(y,1/rms)` bf16 在 6/33 配置 1–28 元素越界（比例 ≤0.0003%，未翻车但非零），且风险分布相关：大 outer 小 D (8192,64) scale≥1 时 1-3 失配元素（bf16 maxabs 达 1.562e-02≈15.6×阈值、fp16 1.953e-03≈2×atol）——**判题数据未知时 Muls 必须排除（黑名单）**；`1/Sqrt+Mul` 与 `Rsqrt+Mul` 同源误差；rsqrt 需 ≤2^-20（2^-14 时 bf16 0.39~1.17% 全挂；tilelang #1225 反例）；eps 外置变体全零行 bf16 失配 0.0549~0.064%（必挂级）。
- **官方变体（保留）**：ops-nn 归约链 `Muls(avgFactor)` 前置（reduce 前缩放 1/N）vs 本项目"reduce 后除 N"——精度行为可能不同，真机对照（调研1 风险 R7）；ops-nn 用 `1/sqrt` 取倒数+Muls——与 Divs 裁决存在张力，官方先例 B 级保留。
- **冲突（保留）**：调研6 agent02 §5.1 推荐 Rsqrt+Muls（避免除零）vs agent6/10 裁决 Sqrt+Divs——**除零论据被推翻（eps 内置保证 rms>0）**；最终裁决 Divs+Sqrt，Rsqrt 留作性能候选单独真机验证。
- **实验状态**：`CPU 已验证`（Divs 恒等；调研4 Divs bit_eq=True）。
- **证据等级**：A+CPU。
- **来源**：S008、S060、S064；调研4 数值参考脚本（divpath/stress）、调研6 数值参考脚本（precision_matrix/muls_probe）、调研6 agent10 C-1/C-5。

### R021 归约分块与累加顺序控制（类别：精度与数据类型）

- **核心原理**：顺序累加误差 O(√D·2^-24)、pairwise O(log D·2^-24)、Kahan O(2^-24)；**bf16+整行顺序+D=32768 实测 0.159% 挂；任何分块（32~4096）<0.01%**——统一 chunk ≤4096（工程保守值，规避 count 上限争议）；归约尾块必须用中性元 0 参与。

- **来源**：S066-S068；调研1 Agent06 §2.6、调研3 agent06 §1、调研4 agent06 Q2、调研5 E2、调研6 Q3/Q5。

## 8. 路线组合分析

1. **两遍扫描（R001）与单遍 UB 暂存（R002）能否共存**：能——按 D 运行时分支（同一 kernel 内 `if (D≤阈值) 走单遍 else 走两遍`），调研3/6 均按此设计（第二候选=S7+S2 护栏）。注意组合后代码路径数增加，与 R022 的 kernel 大小红线（jump 偏移 int16、裁剪至数百行）存在张力：调研6 裁决"收敛为数百行量级"、V002 的 ~20 Process 变体被判复杂度风险。**推荐：首版仅 R001；性能版再以最小分支引入 R002**。
2. **gamma/bias 驻留（R014）能否与流水线（R015）共存**：能——驻留 buffer 与双缓冲输入队列分属不同 TBuf/TQue；但 UB 预算须合并核算（驻留 D≤8192 half 约 32KB+双缓冲 tile 减半后仍需 ≤192KB；fp16 D=32768 单遍三块 192KB 打满时二者不可兼得）。真机 InitBuffer 实测定案。
3. **尾块处理（R007/R008/R009/R010）能否与不同分块方式共存**：能——尾块机制与 tile 大小（R012/R013）、行/多行分配（R017/R011）正交；R009 对齐双分支天然要求"对齐主循环+尾块慢路径"，与 R011 多行一次 DMA 组合时行间 padding 须按 32B 规划（R010）。
4. **FP32/FP16/BF16 是否需要不同路径**：计算链统一 FP32（R019，三 dtype 同路径）；**分块参数需按 dtype 分档**（fp16/bf16 tile 4096 / fp32 tile 2048；单遍 D 分水岭 fp32 更严）；bf16 输出必须 CAST_RINT（R019 变体）；fp16 无溢出风险由 FP32 链消除。V002 的 dtype 分派变体过多被判复杂度风险——首版应统一计算链、仅 tile 参数分档。
5. **小 D/大 D/不同 outer 是否可选不同分支**：官方五模式（R016）即此思想的 A 级范式（SPLIT_D/SINGLE_N/MERGE_N/MULTI_N/NORMAL）；本题可行且建议按 outer 与 D 分档，但受 R022 kernel 大小红线约束，变体数控制在 3~4 个以内。
6. **多条路线能否放入同一个 kernel.asc**：能且必须（判题形态就是单文件）；推荐组合（六轮收敛结论）：
   - **首版（立即）**：R017+R001+R019+R007+R004+R022（+R020 Divs/Sqrt、R021 分块 ≤4096、uint64 基址、逐字段 Pad 赋值、`__global__ __vector__`）。
   - **第二候选（首版 15/15 全过后）**：R017+R002（D 护栏）+R019+R007/R008+R004。
   - **性能候选（正确性闭环后）**：R002+R012+R017 混合+R015+R011+R005（BlockReduceSum 评估）+R014+R006。
7. **组合后影响**：精度——R019/R020/R021 为不可动摇前提，任何性能组合不得绕过；UB——R002+R012+R014+R015 组合须逐项核算（多口径已列）；访存——R014（−22%）+R002（−28.6~40%）+R011 叠加为主要收益来源；并行——R017 与 R018 互斥；编译——变体数与代码行数直接受 R022 jump 偏移红线约束。
8. **哪些组合必须真机验证**：R007 写方向（D=67/129/1000 哨兵）、R010 多核 32B（fp16[8,70]）、R004 count 上限（2048/4096/8192 扫描）、R015/R014 收益与 UB、R002 D 分水岭（InitBuffer 实测）、R020 硬件舍入（CAST_RINT vs numpy RNE 逐位）、R005 手工归约 ulp、R027 全部性能数字。
9. **哪些只能作研究参考**：R003（证否对照）、R018（否决）、R023（GPU/编译器迁移，不可提交）、R005 的 VF RegAPI 变体（950 系样例+正确性风险）、R006 的 SPR 变体（950 系专用）、调研2 发现/ 目录的 OpenAI 方法论 6 文件（流程参考）。
