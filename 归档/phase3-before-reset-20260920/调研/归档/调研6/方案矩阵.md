## 2. 推荐级别裁决理由（逐条）

- **S1 首选**：访存最多（5N·s），但 UB 占用最低、实现最简单、与官方 `split_d` 两遍法一致，是"先保证 15/15 全过"的最优骨架。性能是唯一计分维度，但**全过是准入门槛**。
- **S3 首选**：CPU 实证已证否低精度中间累加（bf16 50%+ 失配）；FP32 全中间是**必需项**而非优化项。
- **S7 首选**：官方仓库（ops-transformer / ops-nn）多核范式高度统一为"按行切分、尾核拿余数行"，可直接照搬。
- **S9 首选**：官方 A 级文档明确 UB→GM 不污染相邻内存，且这是处理非 32 倍数 D 的标准做法。
- **S11 首选**：官方 `ReduceSum` 存在且 A2 支持 half/float；手工归约（S12）没有收益。
- **S13 首选**：判题形态就是它，没有替代。
- **S2 第二路线**：省 40% 带宽，但以"整行常驻 UB"为代价，存在明确 D 上限（fp16/bf16 ≤ 22528、fp32 ≤ 11264），超限必须回退 S1。
- **S5 第二路线**：大 tile 减少 DMA 轮次，但需 UB 预算支撑，属性能优化项。
- **S8 第二路线**：outer < 核数时（如 outer=8、48 核）必须按 tile 切 D，但跨核归约代价高，只在必要时启用。
- **S10 第二路线**：S9 的备选，若真机证明 DataCopyPad 在本环境有问题才启用。
- **S6/S12 仅研究参考**：小 tile 流水复杂、手工归约无收益，性价比低。
- **S4/S14 不建议**：S4 已被 CPU 实证证否；S14 的 GPU 机制在昇腾上无对应物，**不得**作为提交方案。

## 3. 明确列入黑名单的做法

1. 用 `Muls(y, 1/rms)` 或 `Rsqrt` 替代 `Divs` + `Sqrt`（bf16 精度风险，CPU 实测 1–28 元素越界）。
2. bf16 路径直接进入 `Add`/`Mul`/`Muls`/`Div`/`ReduceSum`（A2 不支持，C14）。
3. 用裸 `DataCopy` 写非 32B 对齐尾块（会把邻居写成 -1，C12）。
4. 巨型多分支 kernel（2955 行 + ~20 变体 → `out of jump/jumpc imm range`，C3 官方 A 级）。
5. 低精度（fp16/bf16）中间累加（S4，已证否）。
6. 按旧字段序 `{isPad, paddingValue, leftPadding, rightPadding}` 初始化 `DataCopyPadExtParams` —— **始终按成员名赋值**。
7. 把 `TPipe` 作为 kernel 类成员（V001 `pipe_` 冲突同款）。
8. 用 `uint32_t` 计算 `row * D` 的行基址（大张量溢出）。

## 5. 反例与失败条件（每个推荐方案的可证伪条件）

> 所有"验证方法"均为**在有 CANN/NPU 的机器上执行**的动作；本机未执行。

### S1（两遍扫描）
- **失败输入**：`fp32`，`[1, 32768]`。若不做 D 维分块，需同时持有 y(128KB)+output(128KB)+gamma(128KB)+bias(128KB) = **512KB > 192KB UB** → UB 分配失败或结果异常。
- **验证**：真机跑该 shape，预期 UB 报错或输出 NaN/inf；对照"分 tile 版本"应通过。

### S2（单遍保存中间）
- **失败输入**：`fp16`，`[1, 30000]`（非对齐）。单遍需 y(60KB)+output(60KB)+gamma(60KB)+bias(60KB) = **240KB > 192KB UB**。或 `fp32, [128, 32768]`（单行四份 512KB）。
- **验证**：真机跑 S2 上述 shape 预期 UB 溢出；同 shape 跑 S1 应通过 → 证实"超界回退 S1"的护栏必要。

### S3（FP32 全中间计算）
- **反证输入**：`fp16`，`[64, 1024]`，uniform(-2,2)。若平方和在 fp16 累加 → CPU 实测失配 **0.13% > 0.1%** 翻车；bf16 全程低精度 **50%+ 失配**。
- **验证**：离线 CPU 复现（见 `数值参考脚本/agent06_precision_matrix.py` Q6 分支）；真机同 shape 对比 golden。

### S7（以行分配 AI Core）
- **失败输入（32B 踩踏）**：`fp16`，`[8, 70]`（outer=8 < 48 核，D=70 → `D·s=140B`，`140 mod 32 = 12`）。8 行分给 8 核，第 i 行尾与第 i+1 行头落在同一 32B 缓存行，并发 DMA 写回污染邻居。
- **验证**：真机 `blockNum=8` 跑该 shape，核对第 i 行末 12B 与第 i+1 行首是否被污染；按 `k·D·s≡0(mod 32)` 分组后复跑应消失。

### S9（DataCopyPad 尾块）
- **失败输入**：`fp16`，`[1, 70]`。若用裸 `DataCopy(outputGm, yLocal, 70)`，硬件按 32B 粒度搬 16 half，把尾部 `Global[11..15]` 写成 **-1**（C12 原文）。
- **验证**：真机裸 DataCopy 写回，检查尾 5 元素 == -1；改用 `DataCopyPad` + 真实有效 blockLen 复跑应正常。

### S11（ReduceSum 归约）
- **失败输入（溢出）**：`fp16`，`[1, 32768]`，y 取值 uniform(250,255)。`y*y` 在 fp16 下 = inf（Q4：`|y|≥256` 溢出）→ `ReduceSum` 得 inf → `rms=inf` → output=NaN。ReduceSum 内部不处理累加溢出（C11 官方明文）。
- **失败输入（对齐）**：A2 上 `srcInnerPad` 仅支持 `true`；尾块未 pad 到 32B 对齐时结果错误。
- **验证**：真机复现"fp16 源 ReduceSum"预期 NaN；改为入口 `Cast` 到 fp32 后 `ReduceSum(fp32)` 应通过；D 非 32 倍数用例对比 `srcInnerPad` true/false。
