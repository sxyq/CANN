### 0.2 下载模板核对（A 级，`/Users/sunyiyang/Downloads/addrmsnormbias_problem_1742_template/`）

模板共 8 个文件：`CMakeLists.txt`、`data_utils.h`、`kernel.asc`、`main.asc`、`run.sh`、`scripts/{AddRmsNormBias.py, gen_data.py, verify_result.py}`。

已逐字确认的关键事实（这是本轮所有方案的硬约束）：

1. **判题形态是「直调」不是 msopgen 算子包**：`kernel.asc` 只定义
   `extern "C" void run_kernel(GM_ADDR x, const TensorGroupInfo& info_x, GM_ADDR residual, …, GM_ADDR output, …, int64_t availableCoreNum, aclrtStream stream, float epsilon)`，
   内部用 `add_rms_norm_bias_custom<<<blockNum, nullptr, stream>>>(...)` 启动 `__global__ __vector__` 核函数。文件被 `#include` 进 `main.asc`，**不得有 `main()`、`#pragma once`**。
2. **元信息通过 `TensorGroupInfo` 运行时传入**：`struct TensorInfo { const int64_t* shape; int64_t numDims; int32_t dtype; }`，dtype 枚举 `0=fp32 1=fp16 2=bf16 …`。→ shape/rank/dtype 只能在 kernel 内运行时分支，**没有 tiling 结构体、没有 Host 侧 shape 常量**。
3. **核的可用数量来自 `availableCoreNum`**（`main.asc` 用 `ACL_DEV_ATTR_VECTOR_CORE_NUM` 查询），不是 `GetBlockNum()`。
4. **默认编译架构 `dav-2201`**（`CMakeLists.txt` 中 `SOC_ARCH` 默认值，可由 `NPU_ARCH` 覆盖）。
5. **golden 用 FP32 全链路计算**（`scripts/AddRmsNormBias.py`）：`y=x+r` → `rms=sqrt(mean(y*y,axis=-1)+eps)` → `out=y/rms*gamma` → `out+bias` → 最后一次性 cast 回原 dtype。**注意是 `y / rms`，不是 `y * (1/rms)`**。
6. **本地判定口径**（`scripts/verify_result.py`）：`np.isclose(rtol=1e-3, atol=1e-3, equal_nan=True)` 逐元素 + 允许失配比例 `tol=1e-3`（0.1%）。模板只生成 1 个用例（FP16 `[1,64]`，`epsilon=1e-5`），**判题端的 15 点配置与判定口径平台未开放**。
7. `run.sh`：`cmake .. && make -j4` → `python3 ../scripts/gen_data.py` → 拷 `input/case0/*` → `timeout 120 ./add_rms_norm_bias_custom` → `python3 ../scripts/verify_result.py 0`。**超时 120 秒**。
