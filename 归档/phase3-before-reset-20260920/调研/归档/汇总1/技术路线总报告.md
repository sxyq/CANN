## 2. 题目和边界

### 2.1 计算语义（官方题面，A 级）

`y = x + residual`；沿最后一维 D 求 `rms = sqrt(mean(y², axis=-1) + epsilon)`；`output = (y / rms) * gamma + bias`；末尾一次性 cast 回原 dtype（golden 为 FP32 全链路内部计算）。来源：调研1 Agent01 §2、调研2 §2.1（公式）、调研4 agent01 L24–108、调研6 agent10（S273 AddRmsNormBias.py）。

### 2.2 输入输出与约束（官方题面/模板，A/B 级）

| 项 | 值 |
| --- | --- |
| 输入 | `x`、`residual`、`gamma`、`bias`（`bias` 一维 `[D]`），输出 `output`，外加标量 `epsilon` |
| dtype | fp32 / fp16 / bf16；直调 `TensorInfo.dtype` 编码 0=fp32 / 1=fp16 / 2=bf16 |
| rank | 2D / 3D / 4D（`outer` = 最后一维以外展平行数） |
| D | [64, 32768]，**不保证 32 的整数倍**（存在 67/129/1000 等非对齐点） |
| outer | [1, 8192+] |
| 接口 | CANN 9.0 Direct Invocation：`run_kernel(GM_ADDR, TensorGroupInfo, …, availableCoreNum, aclrtStream, float epsilon)` → `<<<blocks,nullptr,stream>>>` 启动 `__global__ __vector__` 核函数；提交物为直调 `kernel.asc` |
| 判题 | 15 测试点全部通过才计分；单点 `100/(1+log₁.₅(t/T))`；性能是唯一计分维度；`iterations=5` |
| 精度门槛 | fp32 相对/绝对 <1e-4；fp16/bf16 <1e-3；本地模板 `verify_result.py` 为 `np.isclose(rtol=0.001,atol=0.001,equal_nan=True)` + 失配 ≤0.1%（判题端是否一致未证实） |

以上来自：题面（A）、官方直调模板 8 文件（A/B）、contest API（A）；15 点具体 shape/dtype 配置平台不开放（不可确认）。

### 2.3 CANN / Ascend C / 昇腾要求（官方文档，A/B 级）

- Target：CANN 9.0.0，直调工程 `find_package(ASC)` + `--npu-arch=dav-2201`（模板默认，判题 SoC 未正式确认）。
- A2 上 `Add/Mul/Muls/Div/ReduceSum` **不支持 bf16**（9.0.0-beta.2 明文，Mul/Div 为同族推断 B 级）；bf16 必须 `bf16→fp32→计算→cast 回`。
- `DataCopyPad`：GM→UB 自动补 0；UB→GM 丢弃 dummy（A 级）；`DataCopyPadExtParams` 字段序官方为 `{isPad,leftPadding,rightPadding,paddingValue}`（与旧笔记冲突，真机验证项）。
- `ReduceSum`：count 版结果在 `dst[0]`，`sharedTmpBuffer`（9.x 曾名 `workLocal`）按公式分配；能力上限存在 4096/16320/受 UB 限制三方争议。
- `GetReduceRepeatSumSpr` 为特定硬件接口（A 级存在但可移植性不透明），通用走 `ReduceSum + V_S/S_V + GetValue(0)`。
- 入口 `__global__ __vector__`（模板逐字）与 `__global__ __aicore__`（框架模式）均合法，提交对齐模板。

### R001 两遍扫描（类别：计算与融合）
- 核心原理：Pass1 逐 tile 求 y² 平方和并归约出整行 rms；Pass2 重读/重算 y，做 `y/rms*γ+b` 写回。
- 实施步骤：按行→按 tile CopyIn(Pad)→Cast FP32→Add(x+r)→Mul 平方→ReduceSum(≤4096)→块间标量合并→标量 rms=sqrt(sum/D+eps)→Pass2 重读→Muls/Divs 归一化→Mul(γ)→Add(b)→CAST_RINT→CopyOut（写回长度=有效字节）。
- 输入条件：无（通用）；dtype：fn16/bf16/fp32；D：任意，含大 D（32768）；outer：任意；SoC：A2 系（dav-2201 推断）；UB：tile 级 ~76–108KB。
- 可组合：R003/R006/R007/R009/R011/R013/R015；与 R008、R004 不可组合。
- 优势：正确性基线、任意 D 可跑、与官方 NORMAL/SPLIT_D 同构、工程防御已被 V001/V002 学费覆盖。
- 代价：访存翻倍（GM 口径 10B/元素；L2 命中后 6–10B，M12 修正）。
- 失败条件/反例：单行四份同留 UB 超 192KB（fp32 [1,32768]）→ 必须行内切 tile；D≤UB 单行因子时纯带宽浪费；每行标量同步×2。
- 实验状态：`CPU 已验证`（21 组同链模拟 0 失配，调研4 kernel_sim_v002.log）；`未开始`（CANN 编译/NPU）。
- 证据等级：A/B（官方样例同构）+ 本地 CPU 实验。
- 来源：调研1 research-report §10 #1；调研2 Agent03 L45–74；调研3 agent10 §2 #1/§3；调研6 agent10 S1。

### R002 单遍 y 驻留 UB（类别：计算与融合）
- 核心原理：一次读 x/residual，y(FP32 或 half 副本) 整行驻留 UB，一次归约后直接 epilogue，省一次 GM 读。
- 实施步骤：CopyIn→Cast→Add 得 y 驻留→Mul 平方→一次 ReduceSum→标量 rms→消费 UB 中 y 做仿射→Cast→CopyOut；D>阈值回退 R001。
- 输入条件：D 上限；dtype：fp16/bf16 D≤4096（保守，推理上界 12288/22528）、fp32 减半（11264）；outer 任意。
- UB：单遍峰值 80–112KB（fp16 D≤4096 推算）；fp16 D=32768 时四缓冲 240KB 超限。
- 可组合：R003/R005/R007/R009/R011（D≤4096 单次 ReduceSum count 在限内）；与 R004/R008 不组合。
- 优势：GM 5D–6D（省 28.6–40%），标量同步次数降一个数量级；小中 D 首选性能路径。
- 代价：UB 规划精细；y 存 half 副本引入中间量化（V002 宽行变体已因精度风险被要求回退 FP32 域）。
- 失败条件/反例：fp16 [1,30000]（240KB>192KB）；fp32 [128,32768]（单行 512KB）→ InitBuffer 超限 EB0000；D=4097 off-by-one 走错档。
- 实验状态：`CPU 已验证`（作为 R001 同链的一部分：D≤4096 用例 0 失配）；`未开始`（真机 UB 预算）。
- 证据等级：B（Agent07 UB 数学）+ CPU。
- 来源：调研2 research-report §10 #2/§12；调研3 agent10 §2 #2/§4；调研6 agent10 S2/C-4。

### R003 FP32 全中间计算（类别：精度与数据类型）
- 核心原理：fp16/bf16 输入 Cast(CAST_NONE) 提升 FP32，平方/归约/仿射全部 FP32，输出单次 Cast(CAST_RINT)。强制红线，非性能选项。
- 实施步骤：Cast→FP32 链→Cast 回；中间 Cast 时机必须与 golden 同链（S8 反例：全程 fp32 反而对不上 golden bf16 中间）。
- 失败条件/反例：任何低精度中间累加必挂（bf16 全程失配 98.96%，main_precision_check.log §5；fp16 D=1024 失配 0.13–2.4%）；`|y|≥256` 时 fp16 平方 inf；A2 无 bf16 算术。
- 实验状态：`CPU 已验证`（0 失配跨 dtype/shape）；`未开始`（真机）。
- 证据等级：A（题面=FP32 中间）+ CPU 实验。
- 来源：调研1 §6；调研2 Agent06 L18–25；调研6 agent10 S3、main_precision_check.log §5。

### R004 低精度中间计算——对照/黑名单（类别：精度与数据类型）
- 核心原理（反模式）：全程 fp16/bf16 域平方/累加/仿射。
- 失败条件/反例（五条独立否决）：fp16 D=1024 失配 >0.13%；|y|≥256 平方溢出；bf16 8 位尾数 D≥32 起失配；大数值加法 inf→NaN；A2 无 bf16 加乘。
- 实验状态：`CPU 已验证`（作为反例：bf16 98.96% 失配、fp16 `|y|≥256` inf）；结论=不建议。
- 证据等级：A（Agent06 定量实验）。
- 来源：调研1 §10 #4；调研3 agent10 §2 #4；调研6 agent10 S4/log §5。

### R005 大 tile（类别：UB 分块与流水）
- 核心原理：tile 尽量大（8192 档）减 DMA 轮次与同步。
- 失败条件/反例：T=8192 fp32 ≈224KB（双缓冲会超 192KB）；count=8192 撞 ReduceSum 上限争议；fp16 D=32768 整行 128KB+ 队列逼近 184KB。
- 实验状态：`未开始`（仅静态预算）。
- 证据等级：B（Agent07 大块搬运数据；训练营 1.55x 为 950PR 不可直接引用）。
- 来源：调研3 agent10 §2 #5；调研5 E1 数值不可引用声明。

### R006 小 tile（类别：UB 分块与流水）
- 核心原理：分块 ≤1024/2048/4096，块间 FP32 标量/向量合并；大 D 必须；精度最稳、尾块最简单。
- 失败条件/反例：tile 过小（≤512）→ 每行 tile 数多 → GetValue 标量同步放大；中块 8KB/次 +148%、小块 128B 时 MTE2 占 98.9%。
- 实验状态：`CPU 已验证`（chunk=4096 失配 0；块间合并差 ≤8.9e-8/8.6e-6）；`未开始`（真机）。
- 证据等级：A/B（Agent06 实验 + A2 样例实测 B 级）。
- 来源：调研1 §10 #6；调研4 kernel_sim_v002_stress.log；调研6 agent10 S6。

### R007 按行分配 AI Core（类别：并行与核分配）
- 核心原理：outer 行按核均分（每核行数差 ≤1），行内归约确定、无核间同步。
- 实施步骤：`each=outer/blocks; extra=outer%blocks; count=each+(block<extra)`；`blocks=min(availableCoreNum, outer)`；`GetBlockNum()` 自适应。
- 失败条件/反例：outer<核数（如 outer=1, D=32768）单核空转；**32B cache line 撕裂**：行间紧凑布局 + D×sizeof(T) 非 32B 倍数 + 多核并发写回 → 相邻行尾头同 cache line 被踩；D=50 fp32（200B）即触发。
- 变体：行块 32B 边界对齐分配（k×D×s≡0 mod 32）；output 每行 stride 补齐 32B + Host 多留 32B。
- 实验状态：`未开始`（真机多核并发写回验证）；V001/V002 已在平台实施（提交失败非本路线失败）。
- 证据等级：B（官方 CalculateBlockParameters 同构 + 模板 main.asc）。
- 来源：调研2 research-report §7（L123–127）；调研6 agent10 S7、反例 S7。

### R008 按 tile 分配 AI Core——否决（类别：并行与核分配）
- 核心原理（反模式）：同一行的 D 切给多核 + 跨核归约（WholeReduceSum/workspace）。
- 失败条件/反例：直调单文件无跨 block barrier 对应物；`GET_TILING` 直调禁用；强行实现会 hang 而非报错（浪费提交次数）；跨核累加顺序不定。
- 实验状态：`未开始`（仅分析）；结论=不建议。
- 证据等级：A/C（官方直调限制 + 社区 hang 案例）。
- 来源：调研6 agent10 S8、反例 S8；调研4 agent10 裁决（S8 不建议）。

### R009 DataCopyPad 尾块（类别：数据搬运与尾块）
- 核心原理：GM→UB 非对齐尾块 DataCopyPad 补 0（0² 不污染归约）；UB→GM 三参 DataCopyPad 写有效长度，dummy 由框架丢弃（A 级）；分母永远是原始 D，不是 aligned/calc 长度。
- 变体：V-a 逐字段赋值 / Designated Initializers（**禁聚合初始化**——字段序冲突真机验证项）；V-b 对齐双轨（对齐主体 DataCopy 快路径 + 尾块 Pad，erf 样板）；V-c output 行 stride 补齐。
- 失败条件/反例：`{isPad,0,right,0}` 聚合初始化在两序下语义相反；D=67 rightPadding 误填 left → 整行右移全错；写方向若真机证伪覆盖相邻行（D=67/129/1000 哨兵核对）；非对齐端到端 -21.6%（性能损失）；裸 DataCopy 写非 32B 倍数把尾部写 -1 污染。
- 实验状态：`未开始`（真机第一验证项）；`CPU 已验证`（补 0 语义部分，同链模拟）。
- 证据等级：A（官方文档/示例）+ C（社区实测冲突保留）。
- 来源：调研3 agent10 §1.1/§1.4-2；调研4 agent10 裁决 1/2；调研6 agent10 S9/C-2、反例 S9。

### R010 手工尾块（类别：数据搬运与尾块）
- 核心原理：对齐块 DataCopy + 尾段 ≤31 元素（不足 32B）`GlobalTensor::SetValue` 逐元素或 mask/Duplicate/GatherMask 重排——DataCopyPad 被证伪/不可用时的官方降级（910 系实际在用 DataCopyCustom）。
- 失败条件/反例：全标量修补在大 outer TLE（as_strided 案例 aiv_scalar_ratio 31.5%）；mask 长度/偏移算错越界。
- 实验状态：`未开始`。
- 证据等级：B（910 系官方在用）+ C（社区案例）。
- 来源：调研1 §10 #10；调研6 agent10 S10、反例 S10。

### R011 ReduceSum 归约（类别：归约与数学）
- 核心原理：`ReduceSum(dst, src, work, count)` 结果在 dst[0]；A2 count 版"方式二"；分块 ≤4096 规避上限争议。
- 变体：V-a 主线 `GetValue(0)` + `SetFlag/WaitFlag<V_S>` + `PipeBarrier<PIPE_V>`；V-b `GetReduceRepeatSumSpr`（A 级存在、可移植性不透明，仅备选）。
- 实施要点：`sharedTmpBuffer`（workLocal）公式 `RoundUp(count/64,8)*8`（count≤4096 需 ≤512 float；V002 用 1024 安全）；`srcInnerPad=true`（A2 仅支持 true）。
- 失败条件/反例：fp16 源归约在 |y| 接近 256 时 inf → NaN（必须先 FP32）；count 上限争议（4096/16320/受 UB 限制）；性能上"三条归约路线中软仿最慢"。
- 实验状态：`CPU 已验证`（分块归约误差）；`未开始`（真机计速/上限）。
- 证据等级：A（官方签名/方式二）+ D（work 公式推导）。
- 来源：调研2 Agent02；调研3 agent10 §1.2；调研4 agent10 裁决 4；调研6 agent10 S11/C-3。

### R012 手工向量归约（类别：归约与数学）
- 核心原理：Add 折叠到 64 槽（src1RepStride=0 广播）+ WholeReduceSum / ReduceRepeat 二分累加（172 vs 242 cycle）；官方 ops-nn 即此写法。
- 条件：WholeReduceSum 单次上限 64×255=16320（D 大需分段）；mask 连续模式 fp32 ∈[1,64]；half 溢出饱和 65504（FP32 归约不限）；220/AIV 参数形态 `(MASK_PLACEHOLDER,1,0,1,0)` 依赖 `g_coreType==AIV`（B 级源码先例，官方文档未直接给出）。
- 失败条件/反例：BinaryRepeatParams 参数错误（srcRepStride/dstRepStride 口径）→ 结果错/CE；手写归约顺序与 golden 不同 → bf16 边界翻转 1–3 ulp。
- 实验状态：`未开始`。
- 证据等级：A（官方性能指南）+ B（ops-nn 源码）。
- 来源：调研5 agent10 M3/V3；调研6 agent10 S12；调研1 §10 #12。

### R013 纯 Ascend C 直调单文件（类别：编译与接口）
- 核心原理：手写 `kernel.asc`（单文件、`#include "kernel_operator.h"`、无 main/tiling 宏），入口逐字对齐模板 `run_kernel` + `__global__ __vector__`；唯一合法提交形态（TVM/MLIR/IREE/Triton/TileLang/PyPTO/msopgen 均不能产出直调 kernel.asc）。
- 实施要点：dtype 0/1/2 分派三实例；保留标识符扫描（禁 `pipe_`/`block_idx`/`ubuf`/`tid`——V001 15/15 CE 教训）；uint64_t 全链寻址；`using namespace AscendC;` 兜底。
- 失败条件/反例：V001 `pipe_` 宏冲突 CE；V002 上传内容截断（首行 `return false;`）→ 从未真正编译；巨型多分支 kernel（2955 行 ~20 变体）触发 `out of jump/jumpc imm range`。
- 实验状态：`无法验证：缺少环境`（本机无 CANN）；平台记录：V001/V002 均 Compile Error（非本路线失败，是通道问题）。
- 证据等级：A（模板/题面）+ 本地提交记录。
- 来源：调研1 Agent01 §5；调研6 agent10 S13、去重（V001/V002 归类）、S279/S280。

### R014 GPU/CUDA/Triton 迁移参考（类别：计算与融合，研究参考）
- 核心原理：借数据流/精度策略（行驻留+掩码+FP32 累加三件套、单遍存寄存器 vs UB 分档、分块循环大 D 组织），不抄指令。
- 已核实参考：PyTorch RowwiseMomentsCUDAKernel、vLLM fused_add_rms_norm_kernel、flash-attn ln_fwd_kernel / Triton _layer_norm_fwd_1pass_kernel、Triton 教程 05-layer-norm、llama.cpp rms_norm_f32。
- 不可迁移：warp shuffle/atomicAdd/grid sync/动态 shared memory/float4 16B 对齐/GPU mask 谓词。
- 失败条件/反例：直接翻译必挂（指令集/同步/内存层次无对应）；mojo_opset fused_add_rms_norm.py 是 Triton 实现（Ascend 后端 Future Work），仅作正确性对照。
- 实验状态：`未开始`（只做资料级分析）。
- 证据等级：A/B（官方源码）+ C（社区）。
- 来源：调研1 §5/§10 #14；调研3 agent10 §1.3；调研6 agent10 S14/S285。

### R015 归一化路径：Divs vs Muls vs Rsqrt（类别：归约与数学/精度路径）
- 核心原理：golden=`y/rms*γ+b`。`Divs(y,rms)`（Sqrt 后先除）与 golden 逐位一致；`Muls(y,1/rms)` （V002 现状）在 bf16 有 1–28 元素越界（max rel 5e-2 近零放大）；`Rsqrt+Mul` CPU 数学等价但硬件单次舍入 ~1 ulp 无法复现。
- 边界：epsilon 在 sqrt 内保证 rms>0 → "避免除零用 Muls"的理由不成立；`sqrt(mean+eps)` 与 `sqrt(mean)+eps` 必须取题面前者（后者小方差行失配 99.88%）。
- 失败条件/反例：Muls 路径在严格逐元素判定下 bf16 分界翻转；eps 外置反例（main_precision_check.log §4 bf16 36/65536 失配）。
- 变体：性能版若真机证明 Rsqrt 显著更快且过阈，可单独评估替换。
- 实验状态：`CPU 已验证`（Divs 逐位一致、Muls 越界、独立复现 3 种子 ×13 形状）；`未开始`（真机硬件舍入）。
- 证据等级：本地 CPU 实验（决定性）+ A（官方语义）。
- 来源：调研4 agent10 裁决 8 + kernel_sim_v002_divpath.* + agent10_verify.py；调研6 agent06 Q1/Q2/Q7 + main_precision_check.log。

### R016 CPU 参考同链验证与平台提交核验（类别：验证与提交）
- 核心原理：无 NPU 时用 numpy+ml_dtypes 实现与 golden 同链的模拟（含 CAST 模拟、分块归约、Sqrt/除法路径），只排除语义/分母/低精度三类问题，不能替代真机；提交前做上传完整性核验。
- 实施步骤：kernel_sim_v002.py（21 组 0 失配）→ stress（块间合并差）→ divpath（P1/P2/P3 对比）→ agent10_verify.py（39 组 0 失配）→ 调研6 precision_matrix/muls_probe/precision_check；提交核验：`wc -l`/md5/首末行回读/保留标识符扫描/UTF-8 无 BOM。
- 实验状态：`CPU 已验证`（多组 0 失配/反例复现）；`无法验证：缺少环境`（真机）。
- 证据等级：本地脚本 + 模板 verify_result.py（A）。
- 来源：调研4/数值参考脚本/；调研6/数值参考脚本/；调研5 validation-host-notes L33–41；AGENTS.md 实验分层要求。

## 8. 路线组合分析

| 问题 | 结论 |
| --- | --- |
| 两遍扫描(R001)与单遍暂存(R002)能否共存 | **能，且为推荐形态**：运行时 D 分档 `if(D<=4096/fp32 2048) SinglePass else TwoPass`（调研3 agent10 §4.1；调研6 agent10 C-4）。两遍的"重读重算"与单遍的"y 驻留"是同一 kernel 内的两个分支。 |
| gamma/bias 缓存(R001/2 变体 P1)能否与流水线共存 | 能：Init 阶段整行预载 UB 常驻，两遍 9D→7D、单遍 6D→5D；D 极大（fp16 D=32768 常驻 128KB）时与工作区冲突 → 大 D 退化为 Pass2 按 tile 搬入（调研3 agent10 §4.2）。 |
| 尾块方案(R009/R010)与不同分块方式(R005/R006) | 能：尾块是搬运层策略，与 tile 大小正交；R009 与 R001/R002/R005/R006 均组合；R010 仅在 R009 被真机证伪时替换（调研6 agent10 5.2-A）。 |
| FP32/FP16/BF16 是否需不同路径 | **需要分路径但共用 FP32 内核链**：fp32 直算；fp16 输入 Cast→FP32 链（防溢出）；bf16 必须 Cast→FP32（A2 无 bf16 算术）→CAST_RINT 回。三 dtype 共用 R003 计算链，入口分派 0/1/2 三个模板实例（R013）。 |
| 小 D/大 D/不同 outer 分支 | 能：D 分档（R001/R002）、tile 大小（R005/R006）与核分配（R007）按形状运行时选择；小 outer 大 D 退化单核多 tile；大 outer 小 D 多核按行均分。 |
| 多条路线放入同一 kernel.asc | 能：推荐组合 `R003+R001/R002(R007 分核)+R009+R011+R015+R013`（=V003 基线：首版"S7+S1+S3+S9/S11"；小 D 加 S2）。同一源码文件内分路径，注意体量控制避免巨型多分支（jump range）。 |
| 组合后的影响 | 精度：全 FP32 链 + Sqrt+Divs + CAST_RINT 锁定 0 失配目标；UB：两遍档 ~76–108KB、单遍档 80–112KB、双缓冲 148KB 均在 192KB 内；访存：两遍 6–10B、单遍 5–6B；并行：行均分无核间通信；编译：直调单文件 + 保留标识符扫描（pipe_ 教训）。 |
| 需真机验证的组合 | R009 写方向与字段序、R007 32B cache-line 撕裂、R011 count 上限、R015 硬件舍入（Divs vs Muls vs Rsqrt 真机 bf16）、R002 UB 预算、R005 双缓冲收益、R006 真机分块误差、判题 SoC。 |
| 仅研究参考 | R014（GPU 迁移）、R004（低精度，反例）、R008（跨核，否决）、R012（性能版待真机前置）。 |
