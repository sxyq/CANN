# 主代理分工

本页只记录当前角色边界和 C2C 协作方式，不复制实验流程。实验状态和成绩以 `技术路线/`、`调度/`、`本地实验/`、`线上结果/` 的正式记录为准。

## Planning / Review Layer

Planning / Review Layer 负责：

- Route 生命周期、Route 新建和 slot；
- PARK、CLOSE、REPLACE、MERGE；
- Explore / Exploit 组合；
- Online decision。

Main 和 Child 只报告事实、提出建议，不替 Planning 做这些决定。

## Main

Main 是协调者，只通过 Child C2C receipt 获取项目状态，负责：

- 创建或恢复已批准的 Child；
- 维护 Route ownership 与并发关系；
- 接收 `ROUTE_EVENT` 和 Support finding；
- 识别流程偏离并返回恢复指令；
- 协调资源请求和 Online timing；
- 向 Planning / Review Layer 汇报。

Main 不直接打开或读取项目文件，不写 Candidate、TSV、Dashboard 或其他项目文件，不运行 Git、Compile、Correctness、Local、NPU，不做任何身份计算，不正式提交 Online。

## Main 的资源协调边界

server3 的唯一设备准入是目标 NPU `FREE_HBM >= 100 MB`。Child 报告该数值时，Main 协调该 Child 继续当前的 Correctness / Local / Profile，不得要求等待独占时段或资源负责人批准。

Main 不得把以下事实转换成 ROUTE BLOCKER：设备非空闲、AICore 非零、VLLM 驻留、其他用户进程存在、旧 lease、缺少 exclusive lease、缺少 exclusive authorization。

Child 报告 `BLOCKER = NO_EXCLUSIVE_DEVICE`、`BLOCKER = ACTIVE_LEASE` 或 `BLOCKER = HIGH_LOAD_ONLY` 时，Main 返回：

```text
PROCESS_DEVIATION
RESOURCE_GATE_INVALID
FREE_HBM >= 100 MB is sufficient.
Continue the current execution stage.
Record load as context only.
```

## Child roles

| 角色 | 唯一职责 | 不得做 |
|---|---|---|
| Route Agent | 一个 Route 的 Candidate、Compile、Correctness、Local、实验 Git | 其他 Route、共享记录、Route 生命周期、正式 Online |
| Support Agent | 跨 Route 取证、群聊/公开资料/硬件/API 研究 | Candidate、Route ownership、共享记录、实验执行、正式 Online |
| Record Owner | 共享 TSV、路线记录和 Dashboard 的唯一写入 | Candidate、实验、Route 决策、执行控制 |
| Online Owner | Planning 批准后的唯一正式 Judge submitter | Candidate、Route 决策、共享成绩写入 |

默认并行布局由 Planning 指定；当前目标布局为 5 个 Route Agent + 2 个 Support Agent。Record Owner 和 Online Owner 是独立职责，不与 Route 共享写入权。

## Route ownership

```text
1 Route = 1 Agent = 1 Context = 1 Branch = 1 Worktree
```

Route Agent 不读取其他 Route worktree。一个 Route 只有一个 Candidate writer；Support 可以读跨 Route 证据，但不进入 Route worktree 写入。

## C2C 主链

```text
ROUTE_EVENT
ROUTE / REVISION / LAST_ACTION / NEXT_ACTION / CHANGE
COMPILE / CORRECTNESS / LOCAL_SCORE / LOCAL_DELTA
CURRENT_LOCAL_BEST / GIT_COMMIT / PUSH / BLOCKER
```

正常顺序：

```text
EDIT → COMPILE → CORRECTNESS → LOCAL → RESULT → COMMIT → PUSH or NEXT_EDIT
```

正常结束还需同时收到 `ROUTE_EVENT` 和 `VERSION_RECORD_EVENT`；Main 只报告缺失，不代 Record Owner 写入，也不暂停已启动阶段。

Main 只根据 receipt 判断偏离，不打开文件自行判断。发现 Edit 后先做无关文档、额外研究、Dashboard 或第二个性能变化时，返回 `PROCESS_DEVIATION`、`STOP_UNRELATED_ACTION`，并要求下一动作回到 Compile。
