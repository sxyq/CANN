# N03 V002 Golden Diagnosis

## Reproduction

- Shape: rows `16`, width `6144`; dtype `BF16`; device `d0` on `cann-server3/hwnput3`.
- Inputs are generated by the existing paired Runner. Each host value is encoded to BF16 with round-to-nearest-even before the same host buffers are copied to Parent and Candidate. `x`, `residual`, `gamma`, and `bias` are therefore identical for both launches.
- The paired Runner launches Parent and Candidate independently, synchronizes each launch, copies both outputs to host, and then compares each output with the golden calculation and with the other output.
- No Kernel source, DMA operation, synchronization operation, Scalar address calculation, or Tile traversal was changed for this diagnosis.

## Reproducible evidence

The diagnostic Runner was added to the existing `paired_runner.cpp` and committed separately as support commit `486f3373`. It prints the first failing elements and evaluates five row-sum references using the same decoded BF16 inputs and final BF16 output conversion.

| Reference used for RMS row sum | Failures | Max absolute error |
| --- | ---: | ---: |
| Existing sequential `float` accumulation | 58 | 0.0078125 |
| Sequential sum inside each 4096-element tile, then tile sum | 18 | 0.0078125 |
| Full-row balanced pairwise sum | 0 | 0 |
| Balanced pairwise sum per tile, then tile sum | 0 | 0 |
| `double` accumulation converted to `float` before RMS | 0 | 0 |

Parent and Candidate outputs remain exact matches: `mismatches=0`. The same 58 failures are printed for both binaries. For example, row `0`, column `2675` has `y=0.189081192`, sequential-reference output `1.046875`, pairwise/double-reference output `1.0546875`, and device output bits `0x3f87` (`1.0546875`). The diagnostic log contains the input bits and values for twelve such elements for each binary.

This reproduces a reference-order difference in the RMS reduction. The device result agrees with the balanced/tree or higher-precision row sum; the old CPU reference accumulates the full row sequentially in `float` and can cross a BF16 output rounding boundary.

## Tolerance finding

The old paired Runner declares failure when either `abs_error >= 0.001` or `rel_error >= 0.001`. That is stricter than the project BF16 mixed tolerance: `rtol=atol=2^-6=0.015625`, per-element condition `abs_error <= atol + rtol * abs(golden)`, matched ratio at least `0.99`, and maximum absolute error limit `1.0` (`max(1.0, 32 * BF16 ULP)`).

The case has `98304` output elements, so 58 differences still give matched ratio `0.999409993`. The observed `max_abs=0.0078125` and `max_rel=0.0075757578` are within the BF16 mixed tolerance and absolute limit. The common failure is therefore caused by the sequential reduction reference combined with the outdated `0.001` gate, not by an input mismatch or a Parent/Candidate divergence.
