# 自动化脚本契约

这里登记路线探索、线上提交和清理流程的机械化接口。当前只完成接口和安全边界登记，脚本本体尚未实现；未实现前不能把这些文件名当作可执行命令。

| 脚本 | 责任 | 必须拒绝的情况 |
| --- | --- | --- |
| `route_new_version.py` | 创建 `V00N` 目录、实验卡和版本元数据 | 覆盖已有版本或一次写入多个性能变量 |
| `route_fast_gate.sh` | 编译、最小运行、基础精度门禁 | 未指定明确版本目录、公共工具链或其他用户目录 |
| `route_package.py` | 回读首尾、入口、行数、字节数和 SHA-256 | 源码身份无法锁定 |
| `submit_enqueue.py` | 生成不可变线上提交任务 | 没有已推送 commit、Hash 或本地门禁结果 |
| `submit_worker.py` | 唯一浏览器 Worker、锁和两分钟限流 | 非 Worker 直接点击、页面异常或任务身份不一致 |
| `score_record.py` | 记录 15 点用时、提交 ID、官方分数和变化 | 用本地耗时伪造官方分数 |
| `score_compare.py` | 读取标准摘要并比较路线/全局 Champion | 读取其他路线 Agent 的隐式上下文 |
| `route_convergence.py` | 应用可配置的线上分数收敛判据 | 使用本地 profiler 代替官方分数 |
| `git_checkpoint.sh` | 检查状态、路径和检查点提交 | 覆盖无关工作树或执行 destructive reset |
| `cleanup_experiment.sh` | 校验版本内绝对路径后清理生成物 | 仓库根目录、用户根目录、公共工具链或宽泛变量 |

所有脚本都必须：

1. 使用显式的版本绝对路径，并在执行删除前打印和校验目标。
2. 保留源码、实验卡、结果摘要、必要文本日志、15 点摘要、官方分数、提交 ID、Hash 和清理前后空间。
3. 直接删除已归档的 `build/`、`input/`、`output/`、`prof_out/`、`PROF_*/`、对象文件和临时可执行文件，不放入回收站。
4. 不读取、输出或写入密码、Token、Cookie 和授权头。
