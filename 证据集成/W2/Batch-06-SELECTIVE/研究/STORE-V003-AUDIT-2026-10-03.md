# STORE-EPILOGUE-X V003 机制与 Official 覆盖审计

日期：2026-10-03
Route：`SELECTIVE-FASTPATH-CHAMPION-X`
范围：只读审计现有 `TRACK-B-HANDOFF.md`、公开版本材料与 CASE47/TINY 已发布研究。

## 结论

- `DISTINCT_MECHANISM=YES`：STORE V003 的核心改动是 FP32 wide 行输出的分块写回及发出时点。它与 CASE47/TINY 已发布的短行 epilogue、行分配、归约或 MTE2 假设具有不同的直接作用点。
- 这个结论只适用于机制层。CASE47/TINY 所指 Official case 是否包含 V003 可命中的输入，现有资料无法确认。
- `RECOMMENDATION=NEEDS_MORE_EVIDENCE`。缺少 Judge testcase ID 到输入 shape/dtype 的可靠对应表，也没有 Official case 的运行时分支命中记录。
- 本记录不决定路线暂停、关闭、合并、替换或新增 Revision。

## 适用输入与路径条件

V011 先把最后一维作为 `rowWidth`，把其余维度乘积作为 `rowCount`；dtype 0 为 FP32。`rowWidth > 8192` 进入 wide 路径，FP32 再进入 `ProcessWideFp32FullCacheRows`。V003 在该函数内要求 `tileCount >= 4` 且 `rowWidth % 8 == 0` 才执行合并分块写回；tile 数由 `rowWidth` 与所选 `tileWidth` 计算。

handoff 所列、使用 `tileWidth=4096` 的有利探针如下：

| 扁平 `rowCount` | `rowWidth` | dtype | `tileCount` | V003 写回条件 |
|---:|---:|---|---:|---|
| 8 | 16384 | FP32 | 4 | 满足 |
| 1 | 32768 | FP32 | 8 | 满足 |
| 1 | 16384 | FP32 | 4 | 满足 |

`rowCount=2` 且 `rowWidth` 为 16384 或 32768 时也会满足静态源码条件；handoff 将其列为方向混合或处于噪声范围，不作为有利目标。Official 输入是否精确落入前三组，或运行时是否选择相同 tile 与 block 分配，当前均无资料证明。

## CASE47 与 TINY 假设关系

| 已发布假设 | 与 V003 的关系 | 重叠判断 |
|---|---|---|
| CASE47 H1：短行 padded-UB 与 epilogue 算术 | 主要变化在 UB 行布局和短行 epilogue；列出的边界探针最高到 D=4097，低于 V003 的 wide 条件。 | 机制不同；按列出的范围不命中 V003 函数。case4/7 实际输入仍未知。 |
| CASE47 H2：active-core / rows-per-task | 改变 block 数或每个 block 的行数；V003 的分块 Store 按 block 内 `batchRows` 发出。 | 机制不同；若未来选到相同 wide FP32 输入，行分配会与 Store 发出数量及 event 使用产生交互。实际 shape 未知。 |
| CASE47 H3：D 维跨核分段归约 | 改变归约工作分配，V003 改变归约完成后的输出写回。 | 非重复机制；若目标同为 wide FP32，可能处在同一输入上。已发布记录将其标为当前调用面不可行。 |
| CASE47 H4：Very-Large D 的 tile 宽度 | 该假设改变 tile 宽度；V003 的 `tileCount`、`tileCount >= 4` 条件和 K=2 分界都依赖 tile 宽度。 | 有直接实现交互。CASE47 优先讨论 FP16/BF16，FP32 风险仍待处理；若扩到同一 FP32 shape，不应把两项改动并入同一验证。 |
| CASE47 H5：窄中路径 MTE2 与标量尾部 issue 顺序 | 适用 `128 < D <= 4096` 的窄中路径。 | 与 `rowWidth > 8192` 的 V003 路径不同。 |
| TINY H1：active-core count | 改变 host 侧 block 数；wide 路径同样接收该 block 数并计算 block 内行段。 | 机制不同；若 TINY 目标里有 V003 可命中的输入，会改变其行分组。case1/3/5 的 shape/dtype 未知。 |
| TINY H2：等行数 ownership 快速式 | 已发布假设针对非 wide 行的 ownership 算式。 | 按现有假设范围与 V003 wide 函数不同。 |
| TINY H3：通用单 tile loop | 要求 `D <= 4096` 且进入通用两遍路径。 | 与 V003 wide FP32 路径不同。 |
| TINY H4：缩小 value buffer | 要求 `rowWidth <= 8192` 且使用非 wide 行缓存。 | 与 V003 wide FP32 路径不同。 |
| TINY H5：省去未使用的 `paramReady` event | 适用 `128 < D <= 4096` 的窄中路径，涉及 MTE2 event。 | 与 V003 的 MTE3 输出 Store 路径不同。 |

因此，已发布假设中未发现与“把 wide FP32 行的输出写回分成两个连续块，并提前发出第一块”相同的直接机制。明确的实现交互在 tile-width 与 active-core 两个方向。其它 CASE47/TINY 假设即使机制不同，也不能据此断言 Official 输入集合互不相交。

## Official 证据与改善可能性

R31B V011 与 STORE V003 的 Judge case 记录均只有 `index`、`testcaseId`、状态、误差、耗时和分数，没有 shape、dtype 或实际分支字段。共享 `研究/OFFICIAL-CASE-ANALYSIS.md` 按耗时区间给 Tiny/Small/Wide 标签，并将形状描述写为推测，不能充当输入映射。

| Official case | testcase ID | V011 耗时 | STORE V003 耗时 |
|---:|---|---:|---:|
| 4 | `6a9a9a99bf41025d6013eb96` | 16.55 us | 16.65 us |
| 7 | `6a9a9a99bf41025d6013eba2` | 52.34 us | 52.00 us |
| 14 | `6a9a9a99bf41025d6013ebbe` | 16486.82 us | 16612.19 us |

case14 的时间差为 +125.37 us，约 +0.76%；它在 V011 上有较大时间差距的事实，不能证明该 case 是 FP32、D=16384/32768，或命中 V003。STORE Main 记录将 case14 写作潜在目标，当前没有输入映射证据支持该对应。

V003 可能改善匹配输入的原因是：V011 按 tile 发出 Store；满足条件时 V003 将每行写回限制为两个连续块，并让第一块写回与第二块计算交叠。handoff 汇总的 V003 相对 V002 Local 探针为 `8x16384 -5.64% (6/0)`、`1x32768 -3.15% (6/0)`、`1x16384 -2.90% (5/0)`。这些数据支持继续研究该写回调度，比较对象仍是 V002。

STORE V003 的 Official 总分为 44.38（15/15），低于 V002 的 45.07，也低于 V011 的 45.16。完整 donor 的 case14 耗时还略高于 V011。选择性版本若能只覆盖确切受益输入，理论上可以保留其他输入的 V011 行为；现有证据没有证明哪些 Official case 会命中，也没有 V011 与选择性候选的结果。

## 不能据此推断

- 不能把 Official case 1/3/5、4/7 或 14 归到任何具体 shape/dtype、M、D 或 Kernel 分支。
- 不能说任何 Official case 已命中 `tileCount >= 4 && rowWidth % 8 == 0`，也不能说 V003 已改善 case14。
- 不能把 V003 相对 V002 的 Local 百分比转成 V003 相对 V011 的结果；两段百分比不可相加。
- 不能由 full-donor 44.38 推算选择性分派的总分，亦不能由其 15/15 PASS 推断尚未实现的 fallback 分派正确性。
- 不能据机制不同宣称 CASE47/TINY 的 Official 输入与 V003 目标互不相交。

## 后续证据与建议

优先补充以 Judge testcase ID 为键的输入清单，至少包含完整 shape 与 dtype；若要证明源代码路径命中，还需按 V011 公式得到 `rowCount`、`rowWidth`，并记录运行时 `availableCoreNum`、`blockCount`、所选 `tileWidth` 与 `tileCount`。取得这些资料前建议维持 `NEEDS_MORE_EVIDENCE`。本轮不编译、不运行设备、不改 Candidate 或 runner，也不提出路线去留结论。
