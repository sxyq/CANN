# CANN 群聊提取工具

从 Android 手机 QQ 数据库增量提取「CANN 挑战赛」群的聊天记录，
自动筛选出对解题（提分）有价值的技术讨论。

**只提取指定群；数据库用完即删（不留副本）。**

## 快速开始

```bash
# 1. 手机连USB，开启 USB 调试，授予 root（KernelSU/Magisk）
# 2. 首次安装依赖
./run.sh --setup

# 3. 提取（日常只需这一条）
./run.sh
```

## 前置条件

| 条件 | 说明 |
|---|---|
| Android 设备 | 已开启 USB 调试 |
| adb | 装在 PATH（`brew install android-platform-tools`） |
| root | KernelSU / Magisk，且已给 shell 授权 |
| 依赖 | `sqlcipher3`（`./run.sh --setup` 自动装） |

## 命令

| 命令 | 说明 |
|---|---|
| `./run.sh` | **增量提取**（只取上次之后的新消息）+ 提分筛选 |
| `./run.sh --full` | 全量重新提取（忽略增量水位） |
| `./run.sh --status` | 查看增量状态（水位、累计、上次新增） |
| `./run.sh --reset` | 清除增量状态，下次按全量重来 |
| `./run.sh --group 901064769` | 指定群号（可重复指定） |
| `./run.sh --no-screen` | 只提取全部消息，不做提分筛选 |
| `./run.sh --keep-db` | ⚠️ 保留解密后的数据库（调试用，占 4GB+） |
| `./run.sh --setup` | 安装/检查依赖 |

## 数据安全

**数据库用完即删。** 每次运行会：

1. 手机端：`cp` 到 `/sdcard/Download/_cann_tmp.db` → `adb pull` → 立即 `rm`
2. 本机：拉到临时目录 → 解密 → 提取 → **立即删除密文与明文副本**
3. 无论成功、失败还是 `Ctrl-C`，`finally` 块都会清理干净

不留任何数据库副本。需要保留时用 `--keep-db`（调试用）。

## 只提取指定群

默认只提取 `config.json` 里配置的群（当前：`901064769` CANN挑战赛-西南赛区）。

流程上做了两处优化，避免多账号时的浪费：

1. 先拉**群信息库**（`group_info.db`，33MB）检查该账号是否有目标群
2. **只有包含目标群的账号**才会拉 4.3GB 主库

```
检查账号 180785996 是否包含目标群… 不含，跳过
检查账号 2435604294 是否包含目标群…
  群 901064769 = CANN挑战赛-西南赛区
拉取主数据库…
```

## 增量机制

第一次运行会全量提取，之后每次只取新增：

```
首次：rowid > 0        → 提取全部
再次：rowid > 上次水位  → 只提新增
```

水位记录在 `状态/incremental_state.json`，可随时用 `--status` 查看、
用 `--reset` 清除。

> 提示：群消息是**追加写入**的，`rowid` 单调递增，所以按 rowid 增量是安全的。
> 但如果你在手机上**清理过 QQ 数据**，rowid 会重置，此时需要 `--full`。

## 筛选规则

只保留与**赛题 `AddRmsNormBias`** 直接相关的内容：

**保留**
- 具体 case 的优化讨论（case1~case15 是同一算子的 15 个测试形状）
- 算子技术：归约、tile、对齐、尾块、流水线、双缓冲、融合、DataCopy、带宽、l2、指令开销、向量核、tiling
- 精度控制、溢出处理
- 性能极限判断
- 踩坑与避坑经验
- 标杆值（各 case 的时延数字）

**排除**
- 违规机制、赛事规则、平台操作
- 组队、报名、卡时、资源申请
- 榜单、通知
- 生活闲聊、AI 会员充值

规则在 `cann_extract.py` 的 `screen()` 函数里，可自行调整。

## 关键实现细节

以下都是**本机实测踩坑后修正**的，改动脚本前请注意：

### 1. 群号在 `40027` 列，不是官方文档说的 `40030`

官方 `nt_msg_db_util` 标注 `40030` = 群号，但**实测 `40030` 是空列（全 0）**。
用 `40030` 查会返回 0 条，误判为「该群无记录」。

### 2. 密钥推导

```
key = md5( md5(nt_uid) + rand )
```

`rand` 在**文件头 offset 0x2E** 起的 8 字节（不是 0x2A）。
文件头布局：

```
0x20 "QQ_NT DB" | 0x28 24 00 00 00 | 0x2C 12 08
0x2E <8 bytes rand> ← 这里 | 0x36 版本号 | 0x42 "HMAC_SHA1"
```

### 3. SQLCipher 参数

```
cipher_page_size = 4096
kdf_iter = 4000非默认 256000
cipher_hmac_algorithm = HMAC_SHA1     从文件头 0x42 读
cipher_kdf_algorithm = PBKDF2_HMAC_SHA512
```

必须**剥掉 1024 字节头**，否则报 `file is not a database`。

### 4. 库有损坏页，不能全表扫描

4.3GB 库直接 `SELECT` 报 `database disk image is malformed`。
必须用 `rowid` 游标分页 + 坏页跳过。

### 5. 验证解密成功不能只看 `count(*)`

错误 key 时 `SELECT count(*) FROM sqlite_master` **返回 0 而不报错**，
是假阳性。必须实际读到 `group_msg_table` / `c2c_msg_table` 等已知表名。

### 6. rowid 不能用作排序主键

同一 rowid 对应多条消息，按 rowid 排会输出全是 `1970-01-01`。
脚本用 `40050` 时间戳排序，并过滤 `t <= 1e9` 的无效行。

### 7. 昵称后缀会污染关键词判断

群成员昵称普遍带「（已报名）」，导致排除规则里的「报名」误命中。
脚本在判断前先剥离 `@昵称（已报名）`。

## 性能

实测 4.3GB 数据库：

| 阶段 | 耗时 |
|---|---|
| 拉取（USB 36MB/s） | ~115 秒 |
| 剥头 | ~7 秒 |
| 解密 + 查询 | ~3 秒 |
| **合计** | **约 2~3 分钟** |

增量运行只查询新增部分，耗时主要在拉数据库（可优化：后续可改为
只拉增量页，或在手机端预筛选）。

## 故障排除

**「未检测到已连接的 Android 设备」**
- 检查数据线、换线（有些线不支持数据传输）
- 手机「开发者选项 → USB 调试」是否开启
- 弹窗是否点了「允许」

**「未获得 root 权限」**
- KernelSU/Magisk 是否给「shell」或目标应用授予了 root
- KernelSU 需要在应用列表里给 com.tencent.mobileqq 或 shell 授权

**「解密失败：未找到已知表」**
- 确认 QQ 版本。本工具在 **QQ 9.2.5** 实测有效，
  大版本升级后文件头格式可能变化，需要重新确认 offset 0x2E

**「database disk image is malformed」**
- 脚本已内置坏页跳过，若持续报错可能是数据库严重损坏，
  尝试在手机上打开一次 QQ 让其正常写库后再提取

**依赖装不上（macOS）**
```bash
./run.sh --setup
```
会自动尝试预编译 arm64 轮子。若 Python 版本不匹配（需要 cp313），
先确认 `python3 --version`。

## 安全说明

- **只读操作**：只读取数据库，不修改 QQ 数据
- **零注入**：不 attach QQ 进程、不 hook、不启动 QQ
- 设备临时文件用完即删
- 数据库仅在内存/临时目录中解密，结束即清理（`--keep-db` 可保留）
