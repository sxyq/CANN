# 本地性能测试规范

本文件是当前有效规则；与归档旧规则冲突时以本文件为准。

本文件融合原 `phase4/control/local-timing-protocol.md` 与 `phase4/control/window-qualification-policy.md`，是本项目**唯一的**测时方法权威：MAIN-1 与 MAIN-2 共用，不接受路线自创的第三种测时方法。路线治理见 `实验总则.md`，Revision 与状态分离见 `执行约定.md`，设备资源与编译规则见 `服务器实验规范.md`。

## 0. 适用边界

- 本文件的设备窗口与负载要求**只**作用于 same-binary 资格验证、按形状测噪声底、Parent/Candidate 配对计时。
- 源码 SHA 核验、编译、链接、executable 身份采集、host build test、可安全执行的 NPU correctness **不等待**干净性能窗口（见 `服务器实验规范.md`）。
- 资格验证或测量期间不得修改 Candidate kernel 源码、SHA、架构或 Revision。
- 旧的“等 AICore 归零、等 VLLM 退出、排除 d7、等干净窗口”口径已废止；2026-09-24 的当日重试额度耗尽记录已过期，不阻止新的测量。

## 1. 设备准入与 lease

- 性能测量准入条件：**实时 HBM 使用率低于 100%** 且**不存在共享 lease 冲突**。
- `调度/服务器设备使用.tsv` 是追加式状态日志。按每个 `lease_id` 的**最后一行**判断当前状态：早先的 `LEASED` 后面已有 `RELEASED` 即不再占用；只有别的 `lease_id` 最后一行仍是 `LEASED` 才构成新预约的冲突。
- 同一 device 同一时段只运行一条性能路线，不跨 Main、不跨 Route 重叠；每条 lease 记录归属 Main 与 Route。
- 开测前实时读取设备、HBM、AICore 与进程；结束后记录并释放 lease。
- AICore 利用率与驻留进程**必须记录**为负载事实，但不单独停止 same-binary、噪声底或配对计时。
- **d7 与其他设备使用完全相同的条件**，没有特殊计时排除。
- 没有满足 HBM 条件的设备时不强测：继续源码核验、编译/链接、executable 身份采集、可安全执行的正确性工作与 Track-B。
- 设备与负载资格只限制 same-binary、噪声底与 Parent/Candidate 计时，不限制非计时工作。

## 2. 参考 harness

结构参考（已在用的最简完整 runner）：`runner_main.inc` 形态 —— 单进程、固定 warmup/repeat、导出全部样本（`*-samples.tsv`）与 jitter（`*-jitter.txt`），Parent 与 Candidate 通过宏选择 submission 共用同一 include 模式。

- 各路线 runner 必须收敛到该协议，**不得发明第三种方法**。
- 短缺样本导出、wall-clock-only、warmup=5/repeats=21、按 batch 平均的旧 harness 一律视为待收敛对象。
- 编排参考：Parent-only 窗口资格脚本、交错 P/C 脚本（P/C 相邻、前后各一次 `npu-smi` 快照）。
- 遗留 wall-clock 方法标记 `LEGACY_TIMING_METHOD`，只作历史证据；不得与当前协议样本混合，也永远不会变成 Official Score。

## 3. 统一测量协议

### 3.1 Warmup

- 默认 **45** 次 launch + 全 stream sync 后才开始计时采样（历史值 3–5、10 均已废止）。
- 依据：设备/驱动稳定需要约 40–45 次 launch；warmup=10 会让短 kernel 的第一个采样块整体未稳定，造成 same-binary 系统性失败。证据见原 `phase4/control/measurement-layer-b1b2-research-20260925.md`（迁移后按 `项目结构.md` 归档）。
- 干跑中若第一块中位数仍 >1.2× 第二块中位数，可放宽到 50–60。
- Correctness 的 D2H / golden compare **绝不**穿插在计时循环内。
- 换 warmup 后，该 Route 必须针对**确切形状**重新做 same-binary 验证，才能进行新的 P/C。

### 3.2 计数

| 阶段 | 数量 |
|---|---|
| 窗口资格 Parent 块 | ≥6 个进程 rep，保留 PRECHECK-A / PRECHECK-B 结构 |
| 每进程内计时样本 | ≥11（wall-clock 优先 21） |
| Candidate 配对窗口 | ≥4 组交错 pair，相邻 P/C（或 C/P 交替），同设备同形状 |

### 3.3 事件与同步位置

- 优先使用 **device events**（`aclrtRecordEvent` start/stop）包住单次计时 launch（或固定短 batch 后 ÷N），`aclrtSynchronizeEvent` 后再 `aclrtEventElapsedTime`。
- 同时记录 `device_us`（event）与 `wall_us`（steady_clock 包 launch+sync）用于诊断；**有 event 时以 `device_us` 判定**。
- 路线升级到 event 之前，结果中注明 method = WALL_CLOCK，噪声底按方法分别处理；wall-clock 不作为主判定。
- Warmup 每次 launch 后 sync；计时样本读时长前先 sync/event wait；launch 仍在飞行时不读样本。

### 3.4 分配与搬运

- 每进程分配一次，放在计时循环外；计时样本内无 `aclrtMalloc` / `aclrtFree` / host realloc。
- H2D 在 warmup 之前；D2H 只在计时循环之后（正确性核对在计时段之后，不在样本之间）。

### 3.5 样本顺序

- 窗口资格：仅 Parent，PRECHECK-A ×N → 间隔 → PRECHECK-B ×N。
- P/C：交错，绝不“先全部 P 再全部 C”。
- 同 binary 噪声底：同一 executable 跑 N 次，不混 Parent/Candidate。

### 3.6 Jitter 统计

每进程样本集：median、mean、stdev、CV = stdev/mean、min、max、max/min、MAD、p10、p90、绝对跨度（max−min）。跨窗口资格 rep：对 rep 中位数算同一组统计（当前门槛基于此）。

## 4. 窗口资格（Window Qualification）

在任何 Candidate 上测之前：

1. 仅 Parent 基线，≥4–6 个样本（PRECHECK-A）
2. 短间隔
3. 再次 Parent 基线 ≥4–6 个样本（PRECHECK-B）
4. **两个块同时**满足才 `QUALIFIED`：
   - CV ≤ 0.15
   - max/min ≤ 1.30
   - 记录 median/min/max/CV/robust spread/进程/HBM/AICore
5. 否则 `WINDOW_UNQUALIFIED`：释放设备，不测 Candidate。

重试预算：每条路线最多 **2** 次独立窗口资格尝试。两次都失败 → `NEEDS_ONE_MORE_LOCAL` + `MEASUREMENT_BLOCKED (SERVER_RESOURCE_BLOCKED)`；**不是** `LOCAL_REJECTED`，**不是** PARK。

固定 CV/max-min 门槛是**临时**门槛。下一次会话先用 same-binary 建立该形状的噪声底，再判断这个形状/dtype/方法是否仍适用 CV ≤ 0.15。

## 5. Same-binary 噪声底

- 每条 Route 在任何新 P/C 之前，必须用该 Route 的 **Direct Parent** 与**确切探针形状**，在本协议下重跑 same-binary。小形状 PASS 不解锁中/大形状或其他 Route。
- 生命周期：aclInit / setDevice / stream / malloc / H2D 各一次；warmup 一次；测量块在**同一进程**内完成；D2H/清理一次。
- 形状判定（主统计量，见第 7 节）：
  - **PASS**：全样本 MAD/median ≤ 0.10 **且** |B1_med − B2_med|/median ≤ 0.10
  - **NEEDS_VALIDATION**：MAD/median > 0.10（但未达下一条）
  - **MEASUREMENT_PROTOCOL_BLOCKED_FOR_SHAPE**：MAD/median > 0.25 或 block drift > 0.25 —— 这是测量协议/宿主问题，**不是 Route 失败**；改进 harness 或宿主环境，绝不改 Candidate kernel 来“修”它
- 全分布离群点计入 MAD/median；低 core/trimmed CV **不得**覆盖高 MAD/median。
- 冷进程 rep 中位数属于 `PROCESS_REINIT_NOISE`，不得作为本地筛选的主统计量；优先单长进程 + 进程内分块 + 交错 pair。
- 重复 batch（短 kernel 的可选校准）：只有在 same-binary 上先验证、且同时降低 MAD/median 与 block drift 才启用，并把 `REPEAT_BATCH_N` 写回本协议；默认 **N=1**。

## 6. Parent/Candidate 配对计时

- 同设备、同形状、同 dtype、同 runner、相邻时间窗的交错 P/C。
- 计时边界、warmup、采样数、统计量、顺序与原始记录全部遵循本文件。
- 保留全部 raw samples、Parent jitter、Candidate jitter、paired delta、方向一致性、设备/HBM/AICore/进程快照与负载分类。
- **不得事后按结果删样本或改 outlier 规则。**
- 只有 PASS 形状上才跑该 Route 的 P/C。

## 7. 离群点策略（任何新 P/C 之前预注册）

看过 Candidate 结果之后不得更改。

1. 进入判定的主统计量只有：每块 `DEVICE_EVENT_US` 的 median、全块 MAD/median、全块 p10/p90、交错 P/C 块中位数的 paired delta（按 pair 报告）。
2. raw 样本永久保留：每个 `*-raw.tsv` 都在；主表不删样本、不做 winsorize、不“去掉慢样本”。
3. core / trimmed 统计（如中位数 ±20% 内样本）只作**次级诊断**，必须标注，不得单独用于声称 PASS 或 ONLINE_CANDIDATE。
4. 不得引入以 Candidate 身份或结果方向为键的事后离群规则。
5. 窗口/形状资格在 Candidate 运行之前，用同样的主统计量在仅 Parent 的 same-binary 数据上完成。

## 8. 本地结论（Local verdict）

每个性能 Revision 必须单独形成 server3 本地结论；完整定义与 Local Best 链规则见 `实验总则.md` 第 F 节。合格枚举：

```text
LOCAL_ACCEPTED
LOCAL_REJECTED
NEEDS_ONE_MORE_LOCAL
MEASUREMENT_BLOCKED
CORRECTNESS_FAILED
BUILD_FAILED
INVALID_SOURCE_IDENTITY
```

无结论记 `NOT_COMPLETE`；唯一可暂记的例外是 `MEASUREMENT_BLOCKED`，且必须含 `BLOCK_REASON`、`DATE`、`SHAPE`、`DEVICE`、`SAME_BINARY_RESULT`、`RETRY_REQUIRED`。`PENDING` 不是结论。

- `LOCAL_REJECTED`：正确性通过，但配对测量显示稳定退化。
- `NEEDS_ONE_MORE_LOCAL`：方向混合、证据不足或差异落在噪声范围内（含窗口资格两次失败的情形）。
- `LOCAL_ACCEPTED`：身份、compile、link、correctness、same-binary 与有效配对测量全部通过，改善稳定且超过该形状噪声范围；只有它可以推进 `LOCAL_BEST`。
- `MEASUREMENT_BLOCKED`：设备、负载、same-binary 稳定性或身份不满足测量条件；不把缺少测量当作零收益。
- 负载污染的数据保留为污染证据，不用于强性能结论。

## 9. Local 与 Official 分离

- 本地百分比与 proxy **不是** Official Score；`STRONG_POSITIVE_LOCAL_SIGNAL` 之类本地信号标签永远不等于线上结果。
- Official 只能来自统一 Judge Owner 的正式提交，流程见 `线上提交规范.md`。
- 线上成绩不得反向替代该 Revision 的本地结论。
- 每个正式结果都要写入 `调度/本地线上校准.tsv`（见 `线上提交规范.md` 第 5 节）。
- 具体成绩、形状结论与历史信号一律查 `技术路线/路线成绩表.tsv`、`技术路线/全版本记录.tsv` 与 `本地实验/<ROUTE>/<REVISION>/`，本文件不记录任何分数。
