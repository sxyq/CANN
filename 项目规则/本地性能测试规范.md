# 本地性能测试规范

本文件说明 Local 测量的数据采集和解释方式。测量结果是记录材料，不改变源码执行路径，也不创建额外流程。

## 测量记录

每次测量尽量保存：

- Parent/Candidate 的 raw latency、median、mean、stdev、CV、min、max、MAD、p10、p90；
- `device_us`、需要时的 `wall_us`、Local delta；
- shape、dtype、runner、warmup、repeat 次数和执行顺序；
- 开测前后的 device load、HBM、AICore 和进程快照；
- 原始数据路径、统计摘要、jitter、重复性观察和异常原因。

样本不足、负载影响、结果未改善或没有执行测量时，保留已有 raw data，并如实填写 `LOAD_NOTE`、`LOAD_QUALITY` 和 `LOCAL_SCORE=NONE`。不补造数值，不按结果方向删除样本，不把 Local 数值写成 Official 结果。

## 推荐方法

1. Parent 和 Candidate 使用相同 shape、dtype、runner、计时边界和设备条件。
2. warmup 和数据搬运放在计时样本之外。
3. 分配、释放和 host realloc 不放入计时循环。
4. 优先使用 device event，同时保留 wall-clock 作为诊断信息。
5. Parent/Candidate 交错采样，避免把两个时间段的负载差异误认为性能差异。
6. 永久保留 raw samples，并记录原始数据和统计方式。

## 输出字段

```text
ROUTE
REVISION
PARENT
SHAPE / DTYPE
METHOD
SAMPLE_COUNT
PARENT_RAW_LATENCY
CANDIDATE_RAW_LATENCY
PARENT_MEDIAN
CANDIDATE_MEDIAN
LOCAL_DELTA
JITTER
FREE_HBM
DEVICE_LOAD
AICORE_LOAD
OTHER_PROCESS_PRESENT
LOAD_QUALITY
REPEATABILITY
LOCAL_SCORE
INTERPRETATION
```

Local 与 Official 的对应关系写入 `调度/本地线上校准.tsv`。设备安全和停止原因见 `服务器实验规范.md`；不创建后台轮询任务。
