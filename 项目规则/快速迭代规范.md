# 快速迭代规范

本文件是 Route Agent 高周转迭代的唯一 canonical 入口。它补充而不替代 `实验总则.md`、`执行约定.md`、`服务器实验规范.md`、`本地性能测试规范.md` 与 `Git工作流程.md`；不得据此绕过路线归属、Planning / Review Layer、Main Review、正确性门禁或 Online 权限。

## 1. 每个 Revision 的规则重读与 RULE_RECALL

每个 Revision（包括 V001 及后续版本）开始 EDIT 前，必须真实重新读取：

```text
AGENTS.md
.agents/skills/cann-mainline/SKILL.md
.agents/skills/cann-route-executor/SKILL.md（存在时）
项目规则/快速迭代规范.md
项目规则/执行约定.md
项目规则/服务器实验规范.md
项目规则/本地性能测试规范.md
项目规则/Git工作流程.md
```

读取完成后必须输出新的 `RULE_RECALL`，逐条短句复述本轮适用要求，至少覆盖：Route / context / branch / worktree 隔离、单一变化（OFAT）、`ONE CHANGE → COMPILE → CORRECTNESS → LOCAL → RESULT → COMMIT` 顺序、资源与安全边界、Correctness 通过后才可测 Local、Parent/Candidate 可比测量与原始证据保留、Local / Official 分离、失败保留、显式路径暂存、禁止 `git add .` / force push / reset / rebase / clean，以及 120 秒规则。不得写 `SAME`、`UNCHANGED` 或以往轮次引用代替逐条复述。

RULE_RECALL 不授予新 Revision、路线生命周期或 Online 决策权限；既有 Planning / Main 门禁仍然有效。

## 2. 单变化与执行顺序

- 每个 Revision 只验证一个概念性性能变化；参数、阈值、指令位置或 buffer 变化应分别作为独立变化。
- EDIT 后下一实验动作是 Compile；不得先写长文档、更新 Dashboard、做无关研究、全仓库 hash 或叠加第二个性能变化。
- Compile / Correctness / Local 按现行项目规则执行；Correctness 未 PASS 不得测性能。Build Fix / Correctness Fix 不得顺手引入新的性能机制。
- 只读准备下一参数允许进行，但不得提前修改 Candidate；负结果、失败和工具失败必须保留。

## 3. Local Result 到下一次 EDIT

Local Result 产生后，立即只做短判断：`IMPROVED`、`NEUTRAL` 或 `REGRESSED`；随后完成：

```text
RESULT → COMMIT → NEXT EDIT
```

从取得 `LOCAL_RESULT_TIMESTAMP` 到开始下一次 Candidate EDIT 的目标为：

```text
RESULT_TO_NEXT_EDIT_SECONDS <= 120
```

该计时只约束结果后的空转区间，不要求服务器 Compile、Correctness 或 Local 本身在 120 秒内完成。不得因长 Markdown / 总结、重新研究路线、重复 SHA / manifest / source identity / 环境扫描、等待 clean window / lease / VLLM / AICore、或更新 Dashboard 而超过 120 秒。每轮记录 `LOCAL_RESULT_TIMESTAMP`、`NEXT_EDIT_TIMESTAMP` 与 `RESULT_TO_NEXT_EDIT_SECONDS`；超过目标必须记录 `WHY_OVER_120_SECONDS`，且不得以上述禁止事项作理由。

## 4. 隔离与安全

一个 Route 只对应一个 Agent、context、branch 和可写 worktree。不得读取或修改其他 Route 的 Candidate、worktree、证据或 Local Best，不共享 Candidate writer，不杀停/迁移其他用户任务，不删除 lease，不覆盖已有证据。高负载按现行资源规则记录，不自行把等待 clean window 作为阻塞理由；不得自行提交 Online。
