# 实验总则

本文件描述当前实验记录、工作树和数据保存方式。历史 W2/W3/W4 材料继续保留在原目录，当前工作不从历史材料恢复旧流程。

## 角色和范围

- Main 负责需求范围、协调和汇总。
- Route Agent 只处理自己的源码、工作树和实验结果。
- Support Agent 负责资料、API 和独立研究。
- Record Owner 维护共享账本。
- Online Owner 只在用户明确点名时调用既有线上脚本。

## 单因素实验

每个变化尽量只表达一个技术假设，并记录 Parent、Candidate、shape、dtype、设备、命令、原始输出、结果和解释。失败、负结果、未执行和资源不足都保留，不用缺失数据替代真实结果。

```text
EDIT -> VALIDATE AS NEEDED -> RESULT -> COMMIT
```

验证项目按实际任务选择，验证结果用于说明实验事实。

## 工作树和共享记录

- `1 Route = 1 Agent = 1 Context = 1 Branch = 1 Worktree`，路线之间不覆盖彼此的未提交文件。
- 共享记录只由其既有所有者维护，不创建重复账本或第二套状态入口。
- Git 采用精确路径分批本地提交，详见 `项目规则/Git工作流程.md`。
- 保留源码、凭据、SQLite、Keychain、运行缓存、实验结果和 Git 历史。

## 资源与安全

服务器访问、设备资源和用户进程保护见 `项目规则/服务器实验规范.md`。资源错误或可能影响其他用户任务时停止当前操作并记录原因，不操作其他用户任务。

## 后台任务

除用户明确要求外，不创建 automation、scheduled task、cron、crontab、at、systemd timer、launchd timer、watchdog 或 detached sleep loop。
