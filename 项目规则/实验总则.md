## Route 生命周期

Planning / Review Layer 负责路线池、Route 新建、继续、暂停、PARK、CLOSE、REPLACE、MERGE、Route slot，以及当前授权范围之外的 Online 决策。当前 W4 用户授权为 `ONLINE_AUTHORIZATION_SCOPE=W4_BEST_OF_ROUTE_VALIDATED_CANDIDATES_ONLY`：每条现有 W4 Route 至多提交一个通过资格要求的路线内最佳 Candidate，无需逐 Route 等待 Planning 批准。Main、Route Agent、Support Agent、Record Owner 不正式提交；Online Owner 是唯一正式 Judge submitter，并按 `项目规则/线上提交规范.md` 核对每条 Route 的资格。

## 角色边界

| 角色 | 负责 | 明确不负责 |
|---|---|---|
| Main | Child 管理、C2C 协调、向 Planning 汇报；本地只读 Git、源码、实验证据和共享状态 | 写入文件、实验命令、NPU、Online、身份计算 |
| Route Agent | 一个 Route 的 Candidate、Compile、Correctness、Local、版本 Git | 其他 Route、共享记录、Route 生命周期、正式 Online |
| Support Agent | 跨 Route 研究、群聊/公开资料/硬件/API 取证 | Candidate、Route ownership、共享记录、正式 Online |
| Record Owner | SLOT-3；主工作树内获准规则和四份共享记录 | Route ownership、Candidate、实验、Dashboard、归档、其他工作树 |
| Online Owner | 当前授权范围内唯一正式 Judge submitter，并核对资格 | Candidate、Route 决策、共享成绩写入 |

Route ownership 固定为：

```text
1 Route = 1 Agent = 1 Context = 1 Branch = 1 Worktree
```

每个 Child 只在自己的指定工作树运行命令；跨 Route 已提交证据通过本工作树 `git show` 读取，不读取其他工作树未提交文件。Record Owner 的唯一工作树为 `/Users/sunyiyang/Desktop/Project/cann`、分支 main，Route 禁止写主目录。结束当前安全闭环后关闭旧 Agent，确认关闭后用空槽开 fresh context 接手下一 Route；同 Agent 不换 Route，关闭 Agent 不改变 Route 生命周期。

每 Route 本轮新增性能版上限 10，连续 3 个有效 numeric Local 无改善报告 `STAGNATION_3`；研究、旧结果恢复和重复不新增性能版；无效测量、构建或精度失败不计入有效 Local 和连续无改善次数。真实失败版本仍保留事件，详细计数见 W4 控制规则。

## 实验主链

```text
ONE CHANGE → COMPILE → CORRECTNESS → LOCAL → RESULT → COMMIT → VERSION_RECORD_EVENT → NEXT CHANGE
```

每个 Revision 只包含一个小技术变化。Compile 失败只处理 Compile 问题；Correctness 失败只处理 Correctness 问题。每次 Local 结果都独立报告，Local 改善才更新 `CURRENT_LOCAL_BEST`。正常完成满足 `LOCAL SCORE REQUIRED`，并提供 numeric Local score/delta、Parent/Candidate raw samples 与 medians、shape/dtype、device、free HBM、load note 和 current best。Compile/Correctness 失败保留证据、commit/status 和 `VERSION_RECORD_EVENT REQUIRED`。Local 缺失时不得开启下一普通 Revision。`NEXT REVISION BLOCKED UNTIL PREVIOUS EVENT EXISTS`。

每个新 Revision、resume、Route switch、Child restart、reconnect、context restore 或 long interruption 后，Route Agent 必须在 Candidate edit 前完整重新读取 `AGENTS.md`、对应 Skill、`项目规则/W4持续探索控制契约.md`、`项目规则/实验总则.md`、`项目规则/执行约定.md`、`项目规则/服务器实验规范.md`、`项目规则/本地性能测试规范.md` 并发送新的 `RULE_REFRESH_RECEIPT`；同版 Compile/Correctness direct fix 前至少重读 `AGENTS.md`、对应 Skill、`项目规则/执行约定.md`，只做直接修复，编辑后下一实验动作必须是 `COMPILE`。无对应 receipt 不得 edit。已批准 Route 内普通下一 Revision 为 `NO MAIN APPROVAL REQUIRED`；`Main MUST NOT MANUALLY MICRO-MANAGE EVERY REVISION`。

用户控制更新、规则文件变化、HANDOFF、Child pool 重建和主要 Git 状态重新核对也触发 Main 完整重读；Main 的状态回复为 `CHECKPOINT_ONLY`。只要存在可执行工作，就继续路线轮转并发送下一动作。

最终目标是由 Official 正式结果超过当前 Verified Project Champion；分数、Champion 和动态进度只引用正式记录或有来源的最新 receipt，不能从 Local-only stacking、用户指令、旧聊天或无来源摘要推导。

## 资源准入

server3 的 Compile、Correctness、Local、Profile 使用同一个准入条件：

```text
目标 NPU FREE_HBM >= 100 MB → 该阶段允许立即执行
```

AICore utilization、Vector/Core busy、VLLM、其他用户进程、device 非idle、系统 load 高、缺少 exclusive lease、缺少 exclusive authorization、旧lease 或未知 lease owner 只作为测量上下文记录，不影响执行。lease 只用于协调记账。唯一有效的停止条件见 `服务器实验规范.md`。

Main 不得把上述任一事实转换成 ROUTE BLOCKER。

服务器不可达只停止受影响 Route 的 server-dependent 动作；保留最后完成动作、精确 `NEXT_ACTION` 和 `BLOCKER=SERVER3_UNAVAILABLE`，等待新的正式可达记录。R4 的旧 `RESUME_BEFORE_V014` receipt 不代表本轮重新连通测试；连接恢复后六项规则入口必须重新读取并发送新的 `RULE_REFRESH_RECEIPT`。

记录由 Record Owner 异步写入，不能成为实验开始、Compile、Correctness、Local 或 Online 的前置条件。失败、负结果、工具失败和未完成结果均保留。
