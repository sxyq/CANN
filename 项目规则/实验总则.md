# 实验总则

本文件描述当前实验记录、工作树和数据保存方式。历史 W2/W3/W4 材料继续保留在原目录，当前工作不从历史材料恢复额外执行链。

## 角色和范围

Main、Route、Support、Record 和 Online 是工作内容的说明。任务按用户指定范围直接使用已有源码、工具、实验目录和记录。

## 实验记录

每个变化尽量只表达一个技术假设，并记录 Parent、Candidate、shape、dtype、设备、命令、原始输出、结果和解释。失败、负结果、未执行和资源不足都保留，不用缺失数据替代真实结果。

常见记录顺序为：

EDIT -> VALIDATE AS NEEDED -> RESULT -> COMMIT

验证项目按实际任务选择，验证结果只用于说明实验事实。

## 工作树和共享记录

- 不覆盖其他路线的未提交文件。
- 共享记录沿用已有所有者和正式位置，不创建重复账本或第二套状态入口。
- Git 采用精确路径分批本地提交，详见 项目规则/Git工作流程.md。
- 保留源码、凭据、SQLite、Keychain、运行缓存、实验结果和 Git 历史。

## 资源与后台任务

服务器访问、设备资源和用户进程保护见 项目规则/服务器实验规范.md。资源错误或可能影响其他用户任务时停止当前操作并记录原因，不操作其他用户任务。

没有用户明确要求时，不创建 automation、scheduled task、cron、crontab、at、systemd timer、launchd timer、watchdog 或 detached sleep loop。
