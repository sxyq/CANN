当前 W4 授权为 `USER_AUTHORIZED_W4_MULTI_SUBMISSION`：每条现有 Route 至少提交两个不同源码身份的真实 Candidate，长期目标不少于 30 次。Local 观察可形成 best/second-best 或 `PROVISIONAL_LOCAL_RANK`；Local 缺失或不稳定、Correctness 覆盖不全和缺少逐次批准不构成提交条件。Main 协调并交接候选，Route Agent 只在自己的 worktree 修改，Online Owner 是唯一正式提交者并使用唯一脚本。只遵守平台实际强制要求、账号权限、真实配额及服务器安全。

动态分数、Local Best、设备可达性和服务器连接状态只引用正式共享记录或最新 Child / Record receipt，不在规则正文中固化为永久技术事实。来源冲突时报告 `STATE_SYNC_GAP`，保留各来源和时间，不自行推断。

### 历史 W3 R4 RESUME_BEFORE_V014 回执处理

用户转交的 R4 回执可包含以下状态：

```text

ROUTE = R4 MULTIROW-PANEL-RMS-CHAMPION-X
REVISION = RESUME_BEFORE_V014
READ = YES (all six required rule paths)
CURRENT_PARENT = V013
CURRENT_LOCAL_BEST = V009
NEXT_ACTION = EDIT
BLOCKER = server3 unavailable: SSH timed out
```

该回执是已完成规则重读的用户转交记录，具体内容由 Record Owner 写入共享事实；它只证明回执生成时已读六项入口，不代表本轮重新连通测试，也不能用于宣称当前网络状态已经重新确认。当前 `SERVER3_UNAVAILABLE` 只影响需要 server3 的 R4 动作：实际等待连接恢复，保持 `NEXT_ACTION=EDIT` 为待执行动作，不编辑 Candidate，不启动 V014，不产生新的 Revision，也不产生 `VERSION_RECORD_EVENT`。连接状态必须以新的正式记录为准。

当新的正式记录确认 server3 可达后，任何下一 Candidate edit 前都必须重新完整读取 `AGENTS.md`、当前角色 Skill、`项目规则/实验总则.md`、本文件、`项目规则/服务器实验规范.md`、`项目规则/本地性能测试规范.md`，并发送新的 `RULE_REFRESH_RECEIPT`；掉线前的旧回执不能复用。新回执有效后，R4 的精确下一动作才是针对当前工作状态只做一个 Candidate edit，随后立即进入 `COMPILE`。`CURRENT_PARENT=V013` 只表示回执中的当前工作快照，不强制 V014 使用 V013 作为 Direct Parent；`LATEST_COMPLETED`、当前工作状态和正式 `DIRECT_PARENT` 分开记录，下一单因素 Parent 按已批准 Route 规则自选并声明，`CURRENT_LOCAL_BEST=V009` 保留。恢复本身不产生版本事件。等待期间不得创建计时器、轮询循环或后台任务。

规则优先级为：当前用户指令；`AGENTS.md` 与当前角色 Skill；本文件及其他 `项目规则/` 入口；历史材料只作参考。事实优先级为：最新 Route receipt > 最新 Record receipt > 当前正式记录 > 旧聊天。用户指令定义范围和处理方式，不构成测量结果；没有正式来源的 Official、shape、Best 或 Champion 必须保持 `UNKNOWN`/`NONE`，来源冲突报告 `STATE_SYNC_GAP`。

Main 每次状态回复的第一部分固定为：


## 唯一执行顺序

```text
ONE CHANGE
→ COMPILE
→ CORRECTNESS
→ LOCAL
→ RESULT
→ COMMIT
→ VERSION_RECORD_EVENT
→ NEXT CHANGE
```

一个 Revision 只表达一个小技术变化。这个约束直接作用于版本内容，不另设审核阶段。Local 改善可以连续积累，但每一步都必须完成上面的完整顺序；多个独立变化不得合并到一个 Revision。

## 阶段处理

- Compile 失败：只处理 Compile 问题，再次 Compile；
- Correctness 失败：只处理 Correctness 问题，保留失败证据；
- Local 结果：保留 raw samples、Parent/Candidate 比较、delta、jitter、free HBM、device load 和 repeatability；
- 负结果：提交并保留，不提升为 Local Best；
- 有效改善结果：提交，成为当前 Local Best 候选；本轮不 push。

正常完成满足 `LOCAL SCORE REQUIRED`：必须有 numeric Local score/delta、Parent/Candidate raw samples 与 medians、shape/dtype、device、free HBM、load note 和 current best。Compile 或 Correctness 失败也保留证据、commit/status，并发送 `VERSION_RECORD_EVENT REQUIRED`。`NEXT REVISION BLOCKED UNTIL PREVIOUS EVENT EXISTS`。

每个新 Revision、resume、Route switch、Child restart、reconnect、context restore 或 long interruption 后，Route Agent 在 Candidate edit 前重新读取 `AGENTS.md`、对应 Skill、`项目规则/W4持续探索控制契约.md`、`项目规则/实验总则.md`、本文件、`项目规则/服务器实验规范.md`、`项目规则/本地性能测试规范.md`，并先发送 `RULE_REFRESH_RECEIPT`；无 receipt 不得 edit。已批准 Route 内普通下一 Revision 为 `NO MAIN APPROVAL REQUIRED`；`Main MUST NOT MANUALLY MICRO-MANAGE EVERY REVISION`。
