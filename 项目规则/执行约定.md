# 执行约定

本文件是当前执行的完整有效要求入口。Route 具体字段仍见 `.agents/skills/cann-route-executor/SKILL.md`；角色边界见 `实验总则.md`；本文件的要求清单不得被摘要替代。

当前控制范围是 `ACTIVE PORTFOLIO W4`。15 条授权路线、5 个持久 Child、轮转、回执、路线处置和退出条件统一见 `项目规则/W4持续探索控制契约.md`。W3/W2 只作历史来源；共享记录与 W4 控制不一致时报告 `STATE_SYNC_GAP`，不得补造动态事实。

## 当前目标与动态状态

目标是让 W4 15 条路线按单因素 Local 闭环持续推进，并让每个结果、失败和停止位置可由 receipt 与正式记录复核；最终目标是以 Official 正式结果超过当前 Verified Project Champion。分数、Champion 和动态进度只引用正式记录或带来源的最新 receipt。

Online 当前为 `PAUSED`。Main 只能向 Planning / Review Layer 报告事实和建议，Route Agent 不能恢复 Online；只有 Planning 改变 Online 决策后，指定 Online Owner 才能正式提交。Local 循环不因 Online 暂停而停止。

动态分数、Local Best、设备可达性和服务器连接状态只引用正式共享记录或最新 Child / Record receipt，不在规则正文中固化为永久技术事实。来源冲突时报告 `STATE_SYNC_GAP`，保留各来源和时间，不自行推断。

### 历史 W3 R4 RESUME_BEFORE_V014 回执处理

用户转交的 R4 回执可包含以下状态：

```text
RULE_REFRESH_RECEIPT
ACTIVE_PORTFOLIO = W3 (historical receipt)
ROUTE = R4 MULTIROW-PANEL-RMS-CHAMPION-X
REVISION = RESUME_BEFORE_V014
READ = YES (all six required rule paths)
CURRENT_PARENT = V013
CURRENT_LOCAL_BEST = V009
NEXT_ACTION = EDIT
BLOCKER = server3 unavailable: SSH timed out
```

该回执是已完成规则重读的用户转交记录，具体内容由 Record Owner 写入共享事实；它只证明回执生成时已读六项入口，不代表本轮重新连通测试，也不能用于宣称当前网络状态已经重新确认。当前 `SERVER3_UNAVAILABLE` 只影响需要 server3 的 R4 动作：实际等待连接恢复，保持 `NEXT_ACTION=EDIT` 为待执行动作，不编辑 Candidate，不启动 V014，不产生新的 Revision，也不产生 `VERSION_RECORD_EVENT`。连接状态必须以新的正式记录为准。

当新的正式记录确认 server3 可达后，任何下一 Candidate edit 前都必须重新完整读取 `AGENTS.md`、当前角色 Skill、`项目规则/实验总则.md`、本文件、`项目规则/服务器实验规范.md`、`项目规则/本地性能测试规范.md`，并发送新的 `RULE_REFRESH_RECEIPT`；掉线前的旧回执不能复用。新回执有效后，R4 的精确下一动作才是针对当前工作状态只做一个 Candidate edit，随后立即进入 `COMPILE`。`CURRENT_PARENT=V013` 只表示回执中的当前工作快照，不强制 V014 使用 V013 作为 Direct Parent；`LATEST_COMPLETED`、当前工作状态和正式 `DIRECT_PARENT` 分开记录，下一单因素 Parent 按已批准 Route 规则自选并声明，`CURRENT_LOCAL_BEST=V009` 保留。恢复本身不产生版本事件。等待期间不得创建计时器、轮询循环或后台任务。

Main 在开始任务、resume、context compaction、reconnect、模型切换、收到新指令、派发 Child 前，以及每次项目状态、执行或 Planning 回复前，都必须重新读取：

1. `AGENTS.md`；
2. `.agents/skills/cann-main-orchestrator/SKILL.md`；
3. `项目规则/W4持续探索控制契约.md`；
4. `项目规则/实验总则.md`；
5. `项目规则/执行约定.md`；
6. 涉及 server3 时读取 `项目规则/服务器实验规范.md`；
7. 涉及 Local 时读取 `项目规则/本地性能测试规范.md`。

Main 只能报告真实已读路径；未读取的入口不得标记为当前依据。阅读不使用计时器，也不以身份计算作为证明。平时可用短确认说明已完成逐项核对；用户要求完整复述时，必须当场展开以下全部项目，短确认不能替代实际重读：

- 目标、当前阶段、`ACTIVE PORTFOLIO W4`、15 条授权路线、5 个持久 Child 与历史 W3/W2 范围；
- Main、Route Agent、Record Owner、Planning、Support、Online Owner 的读写边界；
- `ONE CHANGE → COMPILE → CORRECTNESS → LOCAL → RESULT → COMMIT → VERSION_RECORD_EVENT → NEXT CHANGE`，以及 Local 的 numeric score/delta、Parent/Candidate raw samples 与 medians、shape/dtype、device、free HBM、load note、current best 字段；
- Compile / Correctness / Local 失败证据、commit/status、负结果保留和版本事件要求；
- 新 Revision、resume、reconnect、context restore、long interruption：Candidate edit 前完整读取六项入口并发送新的 `RULE_REFRESH_RECEIPT`；
- 同版 Compile/Correctness direct fix：Candidate edit 前先重读 `AGENTS.md`、当前角色 Skill、`项目规则/执行约定.md`，再发送注明读取范围的 `RULE_REFRESH_RECEIPT`，然后只做直接修复，编辑后下一实验动作必须是 `COMPILE`；中间不插入阅读；
- 版本事件先于下一普通 Revision，Record Owner 的异步写入不能延误已经在途的 Compile、Correctness、Local 或 commit；
- 已批准 Route 自主连续执行无需 Main 逐版批准，并复用 owner、context、branch、worktree；
- `FREE_HBM >= 100 MB` 的统一执行条件、允许立即继续的负载情况和四类真实停止条件；
- Online 当前为 `PAUSED`，只有 Planning 可改变 Online 决策，只有指定 Online Owner 可正式提交；
- 禁止项、状态优先级、`STATE_SYNC_GAP`、Git 暂存/提交边界、禁用调度任务和安全边界；
- 研究消息只按 `claim → evidence → hypothesis → experiment` 传递；
- 停止范围、最后完成动作、精确 `NEXT_ACTION` 和恢复条件。

## 禁止项与授权边界

以下要求全部持续有效：

- 禁止 `force push`、`reset`、`clean`、history rewrite、删除失败证据、杀停或迁移其他用户任务、多个写入者修改同一 Route；
- 禁止范围外的性能 edit、未经批准的新 Route、把 Local-only stacking 当作 Official 验收、猜测 Official、猜测 shape、best-of-run 或无来源 Champion；
- 禁止 Main 直接编辑任何项目文件，禁止 Route Agent 正式提交 Online，禁止把 Dashboard 当作执行控制点；
- 禁止 autonomous schedules，包括 automation、scheduled task、cron、crontab、at、systemd timer、launchd timer、watchdog 和 detached sleep loop；
- 子 Agent 只使用当前运行时的 `tools.multi_agent_v1__spawn_agent`、`tools.multi_agent_v1__wait_agent`、`tools.multi_agent_v1__send_input`、`tools.multi_agent_v1__close_agent`，复用已有 `agent_id`，总数最多 10 个，只用返回的 `agent_id` 管理；禁止 `create_thread`、`fork_thread`、`handoff_thread`、线程 ID 和 `codex://threads/<threadId>`；
- 无关调研、Online 认证、旧 W2 材料和 Dashboard 任务不得插入、延误、暂停或替代当前已批准 Route 的 Local 循环；这些事项也不能取消已批准 Route 内普通下一版无需 Main 逐版批准的授权。

以上禁止项不改变当前已批准 Route 的普通版本自主连续执行、owner/context/branch/worktree 复用、单因素 Local 闭环和 `FREE_HBM >= 100 MB` 资源语义。

## Git 与调度安全

规则、Route Candidate、实验证据和共享记录分开提交；每个实验版本使用独立 commit，失败和负结果同样保留。只使用 `git add <specific paths>`，禁止 `git add .`、`git add -A` 和 `git add --all`；不混入其他 Route、共享记录或用户已有改动。外部 push 只在用户明确授权时执行。禁止 reset、clean、force push、history rewrite 和 rebase。

未经用户明确要求，不创建 automation、scheduled task、cron、crontab、at、systemd timer、launchd timer、watchdog 或 detached sleep loop。等待 server3 恢复时不使用计时器、轮询循环或后台任务。

Main 可窄范围只读刷新 `技术路线/全版本记录.tsv`、`调度/当前任务.tsv`、`技术路线/路线成绩表.tsv`，必要时读取 `技术路线/技术路线图.md`，并优先最新 Child receipt / Record receipt。这个例外只允许读取，不允许 Main 写入文件、运行 Git、Compile、Correctness、Local、NPU 或身份计算，也不允许读取 Candidate、Route 私有 worktree、实验目录或归档材料。

## 规则优先级、事实优先级与状态输出

规则优先级为：当前用户指令；`AGENTS.md` 与当前角色 Skill；本文件及其他 `项目规则/` 入口；历史材料只作参考。事实优先级为：最新 Route receipt > 最新 Record receipt > 当前正式记录 > 旧聊天。用户指令定义范围和处理方式，不构成测量结果；没有正式来源的 Official、shape、Best 或 Champion 必须保持 `UNKNOWN`/`NONE`，来源冲突报告 `STATE_SYNC_GAP`。

Main 每次状态回复的第一部分固定为：

```text
ACTIVE_PORTFOLIO=W4
| ROUTE | LATEST_COMPLETED | CURRENT_LOCAL_BEST | NUMERIC_SCORE/DELTA | CURRENT_ACTION | NEXT_ACTION |
| W4-R01 ... W4-R15 | ... | ... | ... | ... | ... |
```

这 15 行必须从 `技术路线/全版本记录.tsv`、`调度/当前任务.tsv`、`技术路线/路线成绩表.tsv` 与最新 receipts 逐项核对；缺失使用 `UNKNOWN`/`NONE` 并报告 `STATE_SYNC_GAP`，不得从用户指令或旧聊天补数。具体路线身份和 Child 分配见 W4 控制文件。

发生真实资源或连接停止条件时，只停止受影响 Route 的当前 server-dependent 动作，保留已取得证据和失败信息，发送包含 `LAST_ACTION`、`NEXT_ACTION`、`BLOCKER` 的 receipt。不得把停止扩大到其他 Route，也不得开始下一 Revision。服务器不可达时，精确下一动作是等待新的正式可达记录；可达后必须完成对应规则重读和新 receipt，才执行回执中的 `NEXT_ACTION`。

## 唯一执行顺序

```text
ONE CHANGE
→ COMPILE
→ CORRECTNESS
→ LOCAL
→ RESULT
→ COMMIT
→ VERSION_RECORD_EVENT
→ NEXT CHANGE
```

一个 Revision 只表达一个小技术变化。这个约束直接作用于版本内容，不另设审核阶段。Local 改善可以连续积累，但每一步都必须完成上面的完整顺序；多个独立变化不得合并到一个 Revision。

## Route 与 worktree

```text
1 Route = 1 Agent = 1 Context = 1 Branch = 1 Worktree
```

Route Agent 只读写自己的 Candidate 和证据，不读取其他 Route worktree，不写共享 TSV 或 Dashboard。Main 只通过 C2C receipt 协调，且只窄范围读取三份共享记录；Record Owner 是共享记录唯一写入者。

## 阶段处理

- Compile 失败：只处理 Compile 问题，再次 Compile；
- Correctness 失败：只处理 Correctness 问题，保留失败证据；
- Local 结果：保留 raw samples、Parent/Candidate 比较、delta、jitter、free HBM、device load 和 repeatability；
- 负结果：提交并保留，不提升为 Local Best；
- 改善结果：提交、及时 push，并成为当前 Local Best 的候选。

正常完成满足 `LOCAL SCORE REQUIRED`：必须有 numeric Local score/delta、Parent/Candidate raw samples 与 medians、shape/dtype、device、free HBM、load note 和 current best。Compile 或 Correctness 失败也保留证据、commit/status，并发送 `VERSION_RECORD_EVENT REQUIRED`。`NEXT REVISION BLOCKED UNTIL PREVIOUS EVENT EXISTS`。

每个新 Revision、resume、Route switch、Child restart、reconnect、context restore 或 long interruption 后，Route Agent 在 Candidate edit 前重新读取 `AGENTS.md`、对应 Skill、`项目规则/W4持续探索控制契约.md`、`项目规则/实验总则.md`、本文件、`项目规则/服务器实验规范.md`、`项目规则/本地性能测试规范.md`，并先发送 `RULE_REFRESH_RECEIPT`；无 receipt 不得 edit。已批准 Route 内普通下一 Revision 为 `NO MAIN APPROVAL REQUIRED`；`Main MUST NOT MANUALLY MICRO-MANAGE EVERY REVISION`。

## W4 DURABLE CONTROL POINTER

`项目规则/W4持续探索控制契约.md` 是当前 W4 的强制执行入口。它规定控制重读触发、`CONTROL_REFRESH_RECEIPT`、`USER_DIRECTIVE_RECEIPT`、15 条路线、5 个持久 Child、路线切换、规则回执、单因素 Revision 闭环、失败结果、Record Owner、Online `PAUSED`、资源条件、周期性 `PORTFOLIO_REVIEW`、`MAIN_FINAL_GATE`、Child 事件后的下一步要求和宿主受限时的恢复方式。新控制更新必须在安全边界同步到该文件及受影响核心入口。

Main 每次用户状态回复只是 `CHECKPOINT_ONLY`。只要存在活动 Child、可执行路线、待研究、待重新取得资格或待指纹任务，就继续轮转并发送下一动作；不能因一次轮询、一次轮转或一次状态回复自行结束。

Main 在每次用户状态、执行或 Planning 回复前执行 `RULE REFRESH REQUIRED` 与 `STATE REFRESH REQUIRED`，只读刷新权威规则和共享状态，至少读取 `技术路线/全版本记录.tsv`、`调度/当前任务.tsv`、`技术路线/路线成绩表.tsv`，必要时读取路线图，并优先最新 Child receipt / Record receipt。冲突写 `STATE_SYNC_GAP`；Main 不读取 Candidate、Route 私有 worktree、实验目录，不执行 Git、Compile、Correctness、Local、NPU。

Build Fix 或 Correctness Fix 不得顺手加入新的性能变化。

## 阶段间的资源准入

Compile、Correctness、Local、Profile 之间不插入额外的资源审批。Compile PASS 后查询目标卡 `FREE_HBM`，`>= 100 MB` 即执行 Correctness；Correctness PASS 后 `FREE_HBM >= 100 MB` 即执行 Local。负载高、其他进程存在、lease 存在或缺少独占权限都不得成为停止理由；这些事实只写入记录的负载上下文。
