# Git 工作流程

本文件只描述本地源码、实验记录和文档的 Git 保存方式。远端协作和自动发布配置不属于本项目本地执行链。

## 提交顺序

每个独立变化使用一个本地提交，失败结果和负结果同样保留。提交信息直接说明修改对象和原因，避免把不相关路线、实验结果或用户已有改动混入同一提交。

```text
EDIT -> LOCAL VALIDATION -> RESULT -> COMMIT
```

验证可按当前任务需要执行；没有执行的项目如实记录，不生成虚假结果。提交完成后保留工作树状态和提交号，便于继续下一项变化。

## 暂存范围

- 使用 `git add <specific paths>`，按文件或精确路径暂存。
- 不使用 `git add .`、`git add -A` 或 `git add --all`。
- 同一文件含有无关变化时，只纳入本任务实际修改的部分。
- 不改写历史，不删除失败证据，不覆盖凭据、运行数据或其他用户的工作。

## 分批提交

按仓库和职责分批提交：规则与工具、文档、源码注释、测试资料分别形成清晰提交。一个仓库完成当前批次后，再处理下一个仓库；提交信息使用简短、具体的中文或英文描述。

## 工作树安全

保留当前分支、提交历史、工作树和用户数据。除用户明确要求外，不推送、不创建远端对象、不启用自动流程，也不新建同类脚本或重复执行链。
