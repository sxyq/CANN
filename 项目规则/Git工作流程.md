# Git 工作流程

本文件描述本地源码、实验记录和文档的保存方式。默认只使用本地 Git。

## 本地提交

- 每个独立变化使用一个本地提交，失败结果和负结果同样保留。
- 提交信息直接说明修改对象和原因，不把无关路线、实验结果或用户已有改动混入同一提交。
- 使用 git add 的精确路径；不使用 git add .、git add -A 或 git add --all。
- 同一文件含有无关变化时，只纳入本任务实际修改的部分。
- 不改写历史，不删除失败证据，不覆盖凭据、运行数据或其他用户工作。

## 分批提交

按仓库和职责分批提交：规则与工具、文档、源码注释、测试资料可以分别形成清晰提交。用户要求批量处理时，继续使用精确路径和现有本地提交入口。

## 工作树与远端

保留当前分支、提交历史、工作树和用户数据。默认不推送、不创建远端对象、不添加远端审查、自动构建或自动发布配置。用户明确要求远端操作时，沿用现有对象和入口，不创建同类替代实现。
