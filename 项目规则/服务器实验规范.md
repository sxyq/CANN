# 服务器实验规范

本文件是 server3 访问、资源安全和实验操作的唯一说明。测量字段见 `本地性能测试规范.md`；Route 循环见 `.agents/skills/cann-route-executor/SKILL.md`。

## 访问与目录

- 使用项目已配置的 `cann-server3` 入口；凭据只通过本机安全凭据提供，不写入源码、日志或仓库；
- 实验只使用项目专用目录，Route 之间保持目录隔离；
- 不使用跳板，不无提示提权，不在 server3 上执行正式 Judge 提交；
- 连接、工具链版本、SoC、设备号、目录和命令写入该 Revision 的实验记录。

## 性能修改后的第一动作

```text
Candidate performance edit
→ server3 Compile
```

性能编辑之后，下一项实验动作必须是 server3 Compile。Compile 失败时只处理编译问题，然后继续 Compile；Compile 通过后才进入 Correctness，再进入 Local。

## 资源准入

server3 设备准入的唯一正常条件：

```text
目标 NPU FREE_HBM >= 100 MB
→ Compile、Correctness、Local、Profile 均允许立即执行
```

对四个阶段一致适用。Compile 通过后查询目标卡 FREE_HBM，仍`>= 100 MB`即进入 Correctness；Correctness 通过后 FREE_HBM 仍 `>= 100 MB`即进入 Local，不再插入其他资源检查。

以下事实都**不是**执行 Gate，只记录不阻塞：

- AICore utilization 非零；
- Vector / Core busy；
- VLLM 驻留；
- 其他用户进程存在；
- device 非 idle；
- 系统 load 较高；
- 没有 exclusive lease；
- 没有 exclusive authorization；
- 存在旧 lease、未知 lease owner；
- 不存在所谓 clean window。

不得因为上述任何情况等待、暂停 Route、拒绝 Correctness、拒绝 Local、要求独占 NPU、要求资源负责人批准，或要求旧 lease 先释放。

lease 只是 coordination / bookkeeping metadata，不是执行权限。`ACTIVE_LEASE`、`STALE_LEASE`、`UNKNOWN_LEASE`、`NO_LEASE` 都不阻塞实验。不得为了运行实验删除、覆盖、伪造或重写他人的 lease；正确做法是忽略其准入语义。

## 资源安全

- 设备选择统一按 `FREE_HBM >= 100 MB`，可用 `工具/server3-resource-policy.sh` 的 `choose_eligible_device`；
- 多卡并行时每张卡独立分配，一个设备同一时段只运行一条性能路线；
- 使用 `调度/服务器设备使用.tsv` 记录设备分配和释放；
- 性能采样前后记录 HBM、AICore、进程和负载事实；
- 磁盘空间不足时暂停新增实验数据生成，不删除其他用户文件、公共工具链、模型权重或既有证据；
- 不能因为 AICore 非零、VLLM 驻留或其他用户进程存在而杀停任务。

## 唯一有效的停止条件

只有以下情况可以因设备资源停止：

1. 所有可用 NPU `FREE_HBM < 100 MB`；
2. 真实执行出现 OOM、allocation failure 或 runtime resource failure；
3. 启动自己的任务会实际破坏、终止或覆盖其他用户任务；
4. server3 不可连接。

不得把 load 高、AICore busy、存在其他进程、存在 lease 或没有独占访问写成 BLOCKER。

## 进程与数据保护

禁止停止、杀掉、重启、迁移或修改其他用户的进程、服务、容器、数据和系统配置。禁止覆盖其他 Route 的工作目录。实验失败、Compile 错误、Correctness 错误和 Local 负结果都保留。

## 操作记录

每个版本至少记录连接时间、主机、用户、工具链/SoC、NPU 编号、实验目录、Compile 命令、Correctness 返回码、Local 命令、耗时和停止原因。Correctness 与 Local 分开记录，Local raw samples 和设备负载交由本地性能规范统一描述。

未经用户明确要求，不创建 automation、scheduled task、cron、crontab、at、systemd timer、launchd timer、watchdog 或 detached sleep loop。
