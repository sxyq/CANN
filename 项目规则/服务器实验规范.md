# 服务器实验规范

比赛已结束，当前归档工作不运行 NPU 或 Judge；本文件保留服务器访问、资源安全和用户任务保护要求，不增加执行系统。

## 访问与目录

- 使用项目已配置的 cann-server3 入口；凭据只通过本机安全凭据提供，不写入源码、日志或仓库。
- 实验使用项目专用目录，路线之间保持目录隔离。
- 不使用跳板，不无提示提权，不在 server3 上执行正式 Judge 提交。
- 在实验记录中保存连接、工具链版本、SoC、设备号、目录和命令。

## 资源安全

- 历史设备资源下限为 FREE_HBM=100 MB；小于 100 MB 时停止该设备操作，归档和安全本地工作继续。FREE_HBM 达到下限不证明计时质量合格；实际资源错误、OOM、分配失败或会影响其他用户任务时，停止相应命令并记录原因。
- 多条路线可以并行尝试已有设备入口，不要求独占设备、lease 或等待其他路线。记录设备号、并发任务、HBM、AICore、进程和负载；受并发负载影响的性能样本如实标注，不用它阻止后续源码工作。
- 原 `调度/服务器设备使用.tsv` 已移至 `归档/比赛结束-20261017/历史调度/`，只作历史使用记录，不作为预约或启动入口。
- 磁盘空间不足时停止新增实验数据生成，不删除其他用户文件、公共工具链、模型权重或既有证据。

## 进程与数据保护

- 不停止、杀掉、重启、迁移或修改其他用户的进程、服务、容器、数据和系统配置。
- 不覆盖其他路线的工作目录，不删除失败材料，不改写 Git 历史。
- lease 只作为协调和记录信息，不删除、覆盖、伪造或重写他人的 lease。

## 操作记录

每个版本尽量记录主机、用户、工具链、SoC、NPU 编号、实验目录、命令、返回码、耗时和停止原因。成功、失败、未执行和资源不足都按真实状态保存。

没有用户明确要求时，不创建 automation、scheduled task、cron、crontab、at、systemd timer、launchd timer、watchdog 或 detached sleep loop。
