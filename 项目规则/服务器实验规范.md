# 服务器实验规范

本文件只保留服务器访问、资源安全和用户任务保护要求。它不增加源码、实验结果或文档之外的流程。

## 访问与目录

- 使用项目已配置的 `cann-server3` 入口；凭据只通过本机安全凭据提供，不写入源码、日志或仓库。
- 实验使用项目专用目录，路线之间保持目录隔离。
- 不使用跳板，不无提示提权，不在 server3 上执行正式 Judge 提交。
- 在实验记录中保存连接、工具链版本、SoC、设备号、目录和命令。

## 资源安全

- 设备选择参考 `FREE_HBM` 和真实运行错误；资源紧张或出现 OOM、分配失败、运行时资源错误时停止当前操作并记录原因。
- 多卡并行时每张卡独立分配，一个设备同一时段只运行一条性能路线。
- 使用 `调度/服务器设备使用.tsv` 记录设备分配和释放。
- 采样前后记录 HBM、AICore、进程和负载事实。
- 磁盘空间不足时停止新增实验数据生成，不删除其他用户文件、公共工具链、模型权重或既有证据。

## 进程与数据保护

- 不停止、杀掉、重启、迁移或修改其他用户的进程、服务、容器、数据和系统配置。
- 不覆盖其他路线的工作目录，不删除失败材料，不改写 Git 历史。
- lease 只作为协调和记录信息，不删除、覆盖、伪造或重写他人的 lease。

## 操作记录

每个版本尽量记录主机、用户、工具链/SoC、NPU 编号、实验目录、命令、返回码、耗时和停止原因。成功、失败、未执行和资源不足都按真实状态保存。

未经用户明确要求，不创建 automation、scheduled task、cron、crontab、at、systemd timer、launchd timer、watchdog 或 detached sleep loop。
