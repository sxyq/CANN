## 工作树与角色边界

```text
1 Route = 1 Agent = 1 Context = 1 Branch = 1 Worktree
```

## 规则阅读与回执

Main 在开始、恢复、模型变化、上下文压缩、用户控制更新、规则变动、Child 恢复或替换、主要 Git 状态重新核对，以及派发或状态答复前，完整读取适用规则并只读刷新共享状态。读取路径为 `AGENTS.md`、Main/Route Skills、涉及记录时的 Record Skill、本文、实验总则、执行约定；涉及 server3、Local、Git 时再读对应规范。

Route 在每个新 Revision、恢复、重新接手、规则变动或长时间中断后，在 Candidate 编辑前完整读取 `AGENTS.md`、Route Skill、本文、实验总则、执行约定、服务器实验规范、本地性能测试规范及 Git 工作流程，并发送 `RULE_REFRESH_RECEIPT`。同版 Compile/Correctness 直接修复只重读 AGENTS、Route Skill、执行约定；只处理当前故障，编辑后的下一实验动作仍是 Compile。

Record Owner 开始维护时完整读取 AGENTS、Main/Route/Record Skills、本文和上述五份主题规范，发送角色与写入范围回执；规则和记录分别提交。回执列出实际读取路径、规则来源 ref、branch/worktree、HEAD、当前动作和下一动作，未读内容不得标成已读。

用户更新数量、路线、版本额度、资源、读写范围、工作树、Online 或生命周期要求时，Main 先发 `USER_DIRECTIVE_RECEIPT`，说明变化、受影响规则及是否需要维护；需要维护的内容交本轮规则维护代理原位更新。已经运行的原子实验可完成，其他有效路线继续执行。

## 安全闭环与 fresh context

同一 Agent/Context 只负责一条 Route，禁止换 Route。普通下一 Revision 在本 Route 内为 `NO MAIN APPROVAL REQUIRED`，继续使用同一 branch/worktree；Main 不逐版批准。

本次 Route 任务输出完成、当前无可执行动作、达到版本额度或报告 `STAGNATION_3` 时，先完成当前安全闭环：结束本 Agent 的原子命令，保存 Candidate、已有结果与失败证据，提交真实结果并发送所需事件。然后 Main 用该 `agent_id` 关闭旧 Agent，确认关闭后从空槽创建 fresh context 负责下一 Route。不得在命令仍运行时释放槽，也不得让旧 Agent 接手下一条 Route。后续再次安排同一 Route 时，使用 fresh context 复用它原有 branch/worktree。

关闭 Agent 只释放 Child 槽；Route 继续、暂停、关闭、合并或替换仍由 Planning 决定。研究结论、测量无效、Agent 已关闭或等待后续安排均不能写成 `ROUTE CLOSED`。

交接回执沿用 `ROUTE_SWITCH_RECEIPT`，记录旧 `agent_id`、Route、branch/worktree、HEAD、dirty、最后版本/研究事件、未完动作与 `RUNNING_DEVICE_OPERATION=NONE`；它交还槽位，不授权该 Agent 切换路线。

Child 只使用当前运行时 `tools.multi_agent_v1__spawn_agent`、`wait_agent`、`send_input`、`close_agent`，以返回的 `agent_id` 管理。指定模型未暴露时，按全局规则尝试本机同一 v1 能力，保留模型与推理级别；不改用线程接口或其他模型。Record Owner 不创建下级 Child。

## 单因素版本与计数

```text
RULE_REFRESH → REVISION_DECLARATION → ONE CHANGE
→ COMPILE → CORRECTNESS → LOCAL → RESULT → COMMIT
→ VERSION_RECORD_EVENT → NEXT CHANGE
```

一个性能 Revision 只改变一个性能概念。Compile 或 Correctness 失败留在当前版，只处理直接故障；失败、工具错误和负结果均保留证据、commit/status 并发版本事件。前一事件存在后才能开始下一普通版，Record Owner 是否已完成同步不影响在途实验。

每 Route 本轮新增性能版上限为 10，不要求跑满。新建真实性能版、有效 Local 与连续无改善次数分开记录；旧结果恢复、研究和重复不新增性能版。测量无效或构建/精度失败不计入有效 Local 与连续无改善次数，真实执行版本及失败证据仍登记为 `REAL_EXECUTED_REVISION`，不能从记录中删除。例如本轮新建 V002 即使测量无效，仍记新增性能版 1、有效 Local 0、连续次数贡献 0。

连续三个有效 numeric Local 均未改善时报告 `STAGNATION_3`；有效改善清零连续次数，无效或重复结果不增加次数。回执同时报告本轮新增性能版数、有效 Local 数与连续无改善数。达到上限或发出该报告后完成交接，由 Main/Planning 处理后续安排；不由 Route 自行宣布整条路线耗尽。

Local 必须保留 numeric score/delta、Parent/Candidate raw samples 与 medians、shape/dtype、执行路径参数、device、free HBM、load note 和当前 Local Best。缺失值用 `UNKNOWN` / `NONE`，禁止猜测 score/shape、选择最好一次采样或隐藏负样本。稳定性不成立时数字只作观察，不提升 Local Best，不计作有效 Local。`OFFICIAL_BEST`、`LOCAL_BEST`、`CURRENT_CANDIDATE` 分开记录。

编辑前研究或 Parent-only 探测使用 `ROUTE_RESEARCH_EVENT`，保留原事件 ID；即使证据目录名含 V001，也不登记为已执行性能版。版本恢复保留原 Route/Revision 和实验日期，缺失日期写 `UNKNOWN`；接收日期不得冒充实验日期。

## 共享事实与 Git

路线表/任务表中的 `REGISTERED_ROUTE` 表示获准路线已登记；版本表中的 `REAL_EXECUTED_REVISION` 表示已有真实性能改动与执行证据；`ROUTE_RESEARCH_EVENT` 单独分类。记录包含来源提交、路径和事件 ID。各表沿用短 ID，不导入其他分支整份 TSV，不按版本号补造缺版。

Record Owner 依据 Main/Planning 明确转交的事实及对应 Git 对象批量同步，保留 W3/W2 原文。正在构建等 Main 观察只写阶段，结果、commit 与 verdict 待正式事件。共享记录缺少来源或来源冲突时保留 `STATE_SYNC_GAP`；记录同步不暂停原子实验。

规则与共享记录各自独立 commit。提交前核对已有改动，明确路径暂存；同文件含范围外改动时精确选择片段，只提交获准内容。保留其余未提交内容和所有未跟踪证据。本轮 `PUSH=NO`。

禁止 reset、clean、rebase、force push、改写历史、`git add .`、`git add -A`、覆盖用户改动或删除证据；本轮不移除工作树、分支或提交。

## 资源与 Online

目标 NPU `FREE_HBM >= 100 MB` 即可运行 Compile、Correctness、Local 或 Profile。高负载、其他用户进程、VLLM、设备忙、lease 与无独占授权只记为负载上下文；不得要求独占、改写他人 lease 或停掉他人任务。

设备资源停止条件仅为全部可用设备低于 100 MB、真实 OOM/allocation/runtime 资源失败、启动自身任务会实际损害他人任务，或 server3 不可连接。只停止受影响的服务器动作，保留证据与精确下一动作。

Online 保持 `PAUSED`。只有 Planning 明确改变状态后，指定 Online Owner 才可正式提交；Main、Route、Record 不得自行提交。Dashboard 只显示状态，本轮不修改。

## Main 持续协调与结束位置

Main 收到阶段、结果、研究或规则事件后，判断同 Route 下一动作，或在安全交接后关闭旧 Agent、用空槽接手下一 Route。它持续核对 agent_id、Route、branch/worktree、HEAD、dirty、阶段、最后事件及下一动作；来源不一致先报告并处理实际偏差，不猜状态。

每新增五个真实版本事件，或初始五条路线均完成本次结果/研究交接时，Main 做一次只读 `PORTFOLIO_REVIEW`：列出新证据、当前假设、重复范围、测量可行性、剩余独立方向与下一动作，向 Planning 给出 KEEP/NARROW/PROBE_FIRST/ROUTE_REVIEW_REQUIRED 建议。复核不暂停无关实验。

`MAIN_FINAL_GATE`：阶段答复、记录同步、一次监测或首轮状态不能代表 W4 完成。`MAIN_NEXT_ACTION_REQUIREMENT`：每个 Child 事件都有明确后续判断。`MAIN_CONTEXT_RELOAD`：用户更新、规则变动、恢复或模型变化后重读当前依据。

Main 在现有授权和宿主能力内继续；需要让出本轮时用 `CHECKPOINT_ONLY` 保留精确 Route、阶段、事件与下一动作，后续从该位置继续。不创建 timer、automation、cron、后台循环或 detached sleep loop，不宣称能无限运行。

只有 Planning/User 明确结束，或 15 条路线均已提交复核、无独立可执行假设、无待测量资格或证据工作、所需事件已记录且工作树状态已对齐时，才可报告本轮结束。Agent 槽释放不等于 Route 关闭，研究结论也不等于路线耗尽。
