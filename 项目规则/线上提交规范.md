# 线上提交规范

本文件是 Online 角色链和正式结果处理的唯一说明。本轮 Online 工作由 `cann-online-owner` Skill 执行；本文件不复制成绩。

## 当前 Online 状态

Online 当前为 `PAUSED`。Main 与 Route Agent 不得擅自恢复；只有 Planning / Review Layer 改变 Online 决策后，指定 Online Owner 才能正式提交。Local 闭环继续按当前 Route 规则执行。

## 角色链

```text
Route Agent local result
→ Main recommendation
→ Planning / Review decision
→ Online Owner formal Judge submit
→ Record Owner asynchronous record
```

Route Agent 不正式提交 Online。Main 不直接提交，也不替 Planning 作 Online decision。Online Owner 是唯一正式 Judge submitter。

## 送 Online 的证据包

Main 向 Planning / Review Layer 报告：

- starting local baseline；
- current local best；
- 每个小变化的 Local gain；
- cumulative local gain；
- Correctness status；
- experiment count；
- Local 与历史 Official 方向信息；
- 失败和负结果是否完整保留。

不设固定百分比、固定 Revision 数、每次正向结果必提或固定时间间隔。每个版本仍只改变一件事；是否 Online 由 Planning / Review Layer 决定。

## 正式提交与结果

Planning 批准后，Online Owner 使用现有正式提交工具完成提交，返回 Submission ID、PASS/FAIL/INCONCLUSIVE、Official Score 和 Official delta。正式结果写入 `线上结果/<ROUTE>/<REVISION>/`，共享成绩和校准由 Record Owner 异步更新。

正式 Online 不依赖额外的来源身份、可执行对象身份、测量资格或审阅阶段。已有历史证据中的旧字段保持不动。若提交工具内部仍产生摘要元数据，记为 `TOOLING_REMAINDER`；工作流不计算、不读取、不以该字段作为提交依据。

## Local ↔ Official

每次正式结果都向 Record Owner 发送 Online receipt，由其更新 `调度/本地线上校准.tsv`：

```text
ROUTE
REVISION
LOCAL_CONTEXT
LOCAL_DELTA
OFFICIAL_SCORE
OFFICIAL_DELTA
DIRECTION
SHAPE / DTYPE
MEASUREMENT_NOTE
DECISION
```

Local score 不替代 Official Score；线上失败不清除既有 Local Best 和失败证据。

## 提交安全

禁止 Route Agent 重复提交、并发提交同一 Candidate、在 server3 上提交或使用未经 Planning 批准的 Candidate。未经用户明确要求，不创建 automation、scheduled task、cron、crontab、at、systemd timer、launchd timer、watchdog 或 detached sleep loop。
