# 线上提交规范

本文件是 W4 Online 授权、角色和正式结果处理的唯一细则。本规则按当前用户授权取代此前每路线一次、限定 Local Best 或要求内部正确性资格的提交范围。

## W4 Official Scoring Override

> **W4 强制执行规则：本项目禁止设置、保留或新增任何自行定义的实验、评分、Correctness 覆盖、Local 测量稳定性、审批或其他线上提交前置门禁。每条 W4 技术路线必须选取至少两个不同源码身份的真实 Candidate 进行 Official 线上评分。任何研究报告、状态同步、历史归档或本地测量结果均不得作为阻止合法 Official 提交的内部条件。服务器运行安全、工作树隔离及评测平台强制规则仍须遵守。**

```text
ONLINE_MODE = USER_AUTHORIZED_W4_MULTI_SUBMISSION
ACTIVE_PORTFOLIO = W4
MIN_OFFICIAL_SUBMISSIONS_PER_ROUTE = 2
TARGET_TOTAL_OFFICIAL_SUBMISSIONS = 30
INTERNAL_SUBMISSION_GATES = DISABLED
PUSH = NO
```

W4-R01 至 W4-R15 全部属于 Official 评测计划。每条路线至少提交两个源码身份不同的真实 Candidate；累计目标不少于 30 次。研究路线不可被永久排除，但研究材料本身不是 Candidate；Candidate 不足时由该 Route 在自己的 worktree 中继续实现。不得重复使用相同源码伪装成两个版本，不得编造提交数或结果。

本授权取消此前 R02 单次诊断额度对整个 W4 Online 调度的限制，不新增逐 Candidate Planning 批准。不改变 Candidate 开发和 Route 生命周期权限。

## 本地数据与选择

Compile、Correctness、Local、Local 稳定性、Local Best、隐藏 Case 覆盖和研究报告可用于开发、问题定位及候选排序，但均非 Official 提交前置。不得因这些项目事实缺失、失败、波动或不利而拒绝、延后或暂停 Official。

每条路线优先按可用 Local 观察选出最佳与次佳 Candidate。结果可比时标记 `LOCAL_RANK`；观察不稳定时可以作探索性排序并标记 `PROVISIONAL_LOCAL_RANK`；没有 Local 排序依据时写 `LOCAL_RANK=UNKNOWN`。排序必须保留原始依据与不确定性，不把 Local 写成 Official，也不跨不同 shape 冒称可比。候选内容与身份须真实、彼此不同且有来源；不得为了凑数做无效代码改动。

## 角色与唯一提交入口

```text
Route Agent Candidate/worktree → Main coordination → Online Owner submit
→ Judge result → Record Owner shared-record update
```

- Route Agent 只在自己的 Route worktree 实现和维护 Candidate；不正式提交 Online。
- Main 协调路线、候选和提交顺序，汇总来源事实；不编辑 Candidate、不提交 Online。
- Online Owner 是唯一正式 Judge submitter，调用现有唯一入口 `工具/cannjudge-submit.mjs`。不得新建第二套提交脚本或绕过平台。
- Record Owner 异步同步已有正式记录，不批准、不暂停提交。
- Planning 在真实 Official 结果返回后审议最终路线组合；本授权内无需逐 Candidate 事前批准。

## 实际平台条件

提交时只按平台、账号和服务器的真实强制条件操作：认证账户是否有权限、Judge 当前是否接收、实际剩余配额、平台要求的载荷格式，以及服务器和数据安全。脚本或平台拒绝时保存原始错误和状态，再继续其他可执行路线；这些真实约束不得转化为项目自建审批、Local、Correctness、研究或等待流程。

提交使用平台允许的本机连接位置，不在 server3 上发起 Judge 操作。保留现有脚本的账号鉴权、源码载荷与来源记录行为；不改脚本、不清理现有工作区、不覆盖其他候选或用户数据。

## 候选提交与结果

1. 按路线找到尚未 Official 评测的真实 Candidate 文件；记录 Route、Revision、来源 Git commit、源码 SHA256 与文件路径。来源对应只为确保未误交 Parent、测试代理或其他版本，不附加项目自设正确性资格。
2. Online Owner 使用唯一脚本提交，不等待 Local 或 Correctness，也不等待逐项 Planning 回复。
3. 每条 Route 继续提交第二个不同源码身份的 Candidate；相同源码 SHA256 不得作为第二项。不得重复发送仍处于 `PENDING` 的同一 Candidate；只有平台确认首次未受理后，才按真实返回处理后续尝试。
4. 每次 Judge 实际受理后保存 Submission ID 和全部返回状态。Judge 的 FAIL、Wrong Answer、Compile Error、Runtime Error、Time Limit Exceeded、INCONCLUSIVE 等失败均作为真实提交结果保留，不删除、不伪装、不只呈报成功项。没有 Judge 受理记录的本地脚本失败不虚报为 Official 评测。
5. 保存到既有 `线上结果/<ROUTE>/<REVISION>/` 位置，并由 Online Owner 发送 `ONLINE_EVENT`。记录 Official 与 Local 分栏；Official Score 仅取自 Judge 返回值。

每条结果尽可能包含：

```text
ROUTE
REVISION
SOURCE_SHA256
GIT_COMMIT
LOCAL_RANK / LOCAL_OBSERVATION / LOCAL_MEASUREMENT_STATUS
OFFICIAL_SUBMISSION_ID
OFFICIAL_STATUS
OFFICIAL_CORRECTNESS
OFFICIAL_SCORE
CASE_01_TIME_US ... CASE_15_TIME_US
CASE_01_BEST_TIME_US ... CASE_15_BEST_TIME_US
CASE_01_SCORE ... CASE_15_SCORE
RESULT_JSON_PATH
SUBMISSION_TIME
PLATFORM_FAILURE_REASON
```

某字段未由真实响应提供时写 `UNKNOWN` 或 `NONE`，不猜分数、用例形状或时间。`bestTimeUs` 变化时同时保留绝对耗时和原始官方分项得分。线上失败不清除 Local 观察、Local Best 或既有失败证据。

## 进度与交回 Planning

完成目标为每条路线至少两个不同源码身份的 Judge 实际评测、总数目标不少于 30；计数和结论以每次真实 Judge 响应为准。各 Route 的来源身份、Submission ID、Correctness、总分、15 Case 时间与失败都进入既有成绩体系，不建立第二份相冲突主账本。

汇总交 Planning 时提供全部 15 条路线、每次 Candidate 身份与 commit、Official 状态与分数、所有 Case 耗时、每路线最高 Official Score、与 R31B V011/45.16 的比较、Local 排序依据与不确定性、全部失败结果。Planning 确认最终获胜版本前，不把多个 Candidate 内核并入 main，不退役仍承担实验或证据任务的工作树。

未经用户明确要求，不创建 automation、scheduled task、cron、crontab、at、systemd timer、launchd timer、watchdog 或 detached sleep loop。
