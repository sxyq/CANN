# 线上提交规范

本文件描述用户指定 Candidate 的线上提交、结果保存和数据保全方式。提交使用已有工具和平台实际要求。

## 范围

W2/W3/W4 的历史路线、版本和结果继续保留在原位置。当前对象、文件和顺序以用户指令为准，不自行扩展对象范围。

## 提交

1. 定位用户指定的源码文件，记录 Route、Revision、来源 Git commit、源码身份和文件路径。
2. 使用已有的 工具/cannjudge-submit.mjs 提交，不创建第二套脚本。
3. 按平台实际要求处理账户权限、可用额度、载荷格式和运行环境。平台返回错误时保存真实响应。
4. 本地 Compile、Correctness、Local、稳定性和研究资料作为背景记录，与平台结果分开保存。
5. 是否继续同一对象由用户指令和平台返回共同决定。

保留脚本已有的账号鉴权、源码载荷和来源记录行为。不改动用户指定的 Candidate 源码，不清理或覆盖工作区既有数据。Online 提交不在 server3 上发起。

## 结果与数据保全

每次请求返回后，将真实结果保存到既有 线上结果/<ROUTE>/<REVISION>/ 位置。成功、失败、平台错误和未完成结果均如实留存，不删除失败材料，也不把本地脚本失败写成平台已返回。

结果尽可能包含：

ROUTE
REVISION
SOURCE_IDENTITY
GIT_COMMIT
SOURCE_PATH
SUBMISSION_ID
SUBMISSION_TIME
OFFICIAL_STATUS
OFFICIAL_CORRECTNESS
OFFICIAL_SCORE
RESULT_JSON_PATH
PLATFORM_FAILURE_REASON

官方分数只采用平台返回值，不用 Local 数值替代。响应未提供的字段记为 UNKNOWN 或 NONE，不推测分数、用例形状或耗时。

没有用户明确要求时，不创建 automation、scheduled task、cron、crontab、at、systemd timer、launchd timer、watchdog 或 detached sleep loop。
